# F1: Import in the app

## Goal

Import takes a translationCore 3 project, USFM files, a Scripture Burrito or a translationCore
4.0 project through every step of tC4's Import window (kind, files, review, working, failed,
done), with progress and cancel, and makes one new project or nothing. An import the start
cleanup removed is named once on Home. The app's second model of tC4's format, the fixture seed,
is deleted. A "Move the team to the new translationCore?" screen lets a team leave tC4's team
format.

New on 2026-10-21 (owner ruling OE 5): a menu item "Update a book from USFM" (and "Update a
story from Markdown" for OBS) brings a file edited anywhere into an existing project. The person
chooses a file, chooses the book, and sees a report with counts and a link to the conflict
review. It runs I's Update a book job (delta §13.6, U1-U6). The question "This book has been
changed externally. Would you like to import it into this project?" with Import and Not now is
D1's, not F1's (delta §6, §2.17).

## Why it matters to a translator

Teams bring years of work from translationCore 3 and 4. An import must carry every verse,
alignment and check over unchanged, or refuse with a plain sentence, and never leave half a
project behind. Update a book is the supported way to bring work done in Paratext or another
editor into a project: edit, update, then sync. It never replaces a verse that changed on both
sides; those wait in the review.
