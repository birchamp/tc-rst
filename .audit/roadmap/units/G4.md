# G4: The P8 Graphite probe and right-to-left project journeys

## Goal

A probe inside the real shell measures an Awami Nastaliq line and fails when Graphite did not
shape it: joined width and vertical extent within numeric limits. It runs in CI under Xvfb on
Linux and on Windows and macOS runners, and on the release build when G3's pipeline exists.
Two new journeys run a right-to-left project: an Arabic project drafted, checked and aligned (J2,
J4, J5 on tC4's J10 axis), and the Hebrew original text in Align on Jonah.

## Why it matters to a translator

A translator writing Urdu in Nastaliq sees letters that join and cascade, not a line of separate
letters twice as wide. A translator working right to left drafts, checks and aligns with text
that reads and saves in the right direction.

## Funnel card

- **Invariants**:
  - INV-GRAPHITE-SHAPES-OR-FAILS: in the shipped shell on every platform, the probe line in Awami
    Nastaliq is narrower than 480 px and its ascent and descent are within the limits; otherwise
    the job fails and names the platform and the measure.
  - INV-RTL-PROJECTS-EDIT-CORRECTLY: in a right-to-left project, drafted text, a check decision and
    an alignment save to disk exactly as typed and chosen, and the editor, the bank and the
    original-language cards read right to left.
- **Wrong states**:
  - An Electronite build or a Chromium update without Graphite: Nastaliq shows as separate letters,
    and today no check fails (only `fontLoaded` is asserted).
  - A font that falls back to another face: the line loads but is not Awami's.
  - A right-to-left project whose verse editor or alignment bank reads left to right, or whose
    saved text is reordered.
- **Code**:
  - Types: one pure function `graphiteVerdict({ fontLoaded, boxWidth, ascent, descent })` in
    `shell/graphite.cjs` (to create), returning `{ ok, broken: [...] }` with the limits as named
    constants: `JOINED_MAX_WIDTH = 480`; `ASCENT_MIN = 55`, `ASCENT_MAX = 70`; `DESCENT_MIN = 8`,
    `DESCENT_MAX = 20`. The vertical limits are estimates (basis: G0 measured 61.0 and 13.2 on
    Linux and Windows; no Graphite gives 46); step 1's macOS numbers fix them.
  - One entry point: `measureProbe(page)` in `shell/graphite.cjs`, used by every probe run (the
    shell, plain Chromium, the release smoke).
  - Removed: nothing (`spikes/` stays as reference).
  - Left to checks, and why a type cannot carry it: whether the engine shapes a font is a property
    of the binary on each platform, so only a measurement in that binary can hold it.
- **Checks**:
  - `graphite_verdict_names_each_limit_it_breaks` in `shell/test/graphite.test.cjs` (to create);
    kind: unit; runs in: shell.yml `unit`.
  - `plain_chromium_fails_the_graphite_probe` in `shell/e2e/graphite.test.cjs` (to create); kind:
    contract (the probe run in Playwright's Chromium 141, which has no Graphite, must be judged not
    shaped); runs in: shell.yml `e2e-linux`. This is the standing proof that the check can fail.
  - `graphite_shapes_awami_nastaliq_in_the_shell` in `shell/e2e/graphite.test.cjs` (to create);
    kind: contract; runs in: shell.yml `e2e-linux`, `e2e-windows`, `e2e-macos`, and release.yml's
    smoke jobs once G3 exists.
  - `rtl_project_drafts_checks_and_aligns` in `parity/app/journeys/rtl-project.test.mjs`; kind:
    journey; runs in: G5's app-e2e.
  - `hebrew_original_aligns_right_to_left_on_jonah` in the same file; kind: journey; runs in: G5's
    app-e2e.
  - Proof it can fail: the plain-Chromium test above; for the journeys, change the saved verse's
    expected bytes or the expected `dir` and record the failure.
- **Prose**: a comment beside the limits in `shell/graphite.cjs` naming the measurements they come
  from.
- **Human**: none. If H2 names nobody by the end of M1, this card moves to Track A's app lane
  after G3 (`ROADMAP.md` M4); the steps do not change.
