# G1: The Electronite shell

## Goal

`shell/` holds the shell the app ships (Electronite main script, preload, pure library). It starts
and supervises `tc4`, adds the token to the browser's own requests, mirrors typed text to disk,
keeps one running copy, asks before closing over unsaved text, and gives the page PDF, dialogs,
outside links and the feedback send, to `docs/contracts/SHELL.md` v1 (INT-7). Its tests pass under
Xvfb on Linux and on Windows and macOS runners.

## Why it matters to a translator

A double-click shows one window within a second; a second double-click brings it forward. If the
app or the computer stops mid-sentence, the typed text is offered at the next launch.

## Funnel card

- **Invariants**:
  - INV-UNSAVED-TEXT-SURVIVES-A-CRASH: every buffer line the page sent with `bufferChanged` and the
    server has not saved is offered again at the next launch, after `tc4` dies, the shell dies or
    the computer stops.
  - INV-ONE-INSTANCE: at most one shell and one `tc4` run per user; a second launch starts no
    `tc4`, quits, and the running window is restored and focused.
  - INV-RENDERER-IS-ISOLATED: every `BrowserWindow` has `contextIsolation: true`, `sandbox: true`
    and `nodeIntegration: false` (the spike already does, `spikes/electronite/shell/main.cjs:502-503`);
    navigation and new windows are allowed only on the `tc4` origin; the page never sees Node.
  - INV-THE-TOKEN-NEVER-LEAVES-THE-APP: the token goes only into requests to the `tc4` origin (the
    filter adds it only on paths outside `/api/`); never into a file, a log line, a URL given to
    the system browser, or a request to another origin.
  - INV-LIFECYCLE-HAS-ONE-STATE: the shell is always in exactly one lifecycle state, and only the
    pure `next()` changes it.
- **Wrong states**: two `tc4` from two launches (tC4 #4), or one left running after the shell
  ended; no window while the first launch prepares (#743); typed text gone after a crash (A-3); a
  window closed over unsaved text without asking; the token in a log; a help link of the app's
  origin opened in the system browser, which shows a 401 page (A-33, #632); a mirror append that
  blocks the main thread and so every request (G0: `/api/` p95 7-11 ms became 202-203 ms with a
  busy main thread, `docs/APP-DESIGN.md:59-61`).
- **Code**:
  - Types: in `shell/lib.cjs`, `State` (frozen: `Starting`, `Preparing`, `Running`, `Restarting`,
    `Closing`, `Quitting`), events `{ type, ... }`, and one pure `next(state, event) -> { state,
    actions }` read from `TRANSITIONS[state][event.type]`; a missing pair throws. Actions are data
    (`spawnServer`, `showWindow`, `loadPrepare`, `loadHome`, `reloadHome`, `focusWindow`, `askPage`,
    `askUser`, `sendQuit`, `killServer`, `exitApp`, `showStartError`).
  - One entry point: `dispatch(event)` in `shell/main.cjs` alone calls `next()`, assigns the state
    and runs the actions. The bridge is one table `BRIDGE` in `shell/bridge.cjs` (to create), keyed
    as `docs/contracts/shell-bridge.json`; handlers take the Electron modules as parameters, so
    tests pass fakes. The mirror has one writer, `shell/mirror.cjs` (to create).
  - Removed: nothing in the product. `spikes/electronite/` stays as reference.
  - Left to checks, and why a type cannot carry it: JavaScript has no exhaustive match (a table
    test holds every pair); the reduction must equal `current_lines` across two languages (a
    shared-vectors test); the token on 12 request types and the p95 are runtime facts (end to end).
- **Checks** (unit tests in `shell/test/`, end-to-end tests in `shell/e2e/`, all to create; CI
  workflow `.github/workflows/shell.yml`, to create, jobs `unit`, `e2e-linux` under Xvfb,
  `e2e-windows` on windows-2025, `e2e-macos` on macos-15):
  - `every_state_answers_every_event`; kind: unit (INV-LIFECYCLE-HAS-ONE-STATE).
  - `window_preferences_isolate_the_renderer` and `navigation_outside_the_app_origin_is_refused`;
    kind: unit over the window-options function and the `will-navigate` / `setWindowOpenHandler`

  - `random_lifecycles_end_with_no_tc4_running`; kind: model (seeded random events: `tc4` exits,

  - `only_dispatch_assigns_the_state`; kind: architecture (scans `shell/main.cjs`).

  pairs that must hold: at Electron `ready` the window shows at once (owner ruling); an address

  `{"quit":true}`, waits for `{"closed":true}` or the exit, and kills `tc4` after 5 s; a second
  launch in any state focuses the window. Decide and record what happens when `tc4` exits three

### Step 3: Build the mirror

- Do: create `shell/mirror.cjs`. `bufferChanged(line)` appends one line to `drafts-buffer.log` in
  the app-data folder through an open file handle with asynchronous `fs.promises` calls (never
  the `Sync` calls on the main thread); a timer fsyncs at most once a second. `takeBuffered()`
  returns the reduction of the lines read at launch plus every line appended since, on every call.
  The reduction follows `tc_ui::app::buffer::current_lines` (`crates/tc-ui/src/app/buffer.rs:396`):
  the last line per field and run; a removal names its run and ends only that run's entry; a
  removal that names a text ends the entry only while the entry holds that text (NFC); a line
  that does not parse (a torn last line) is skipped. At launch
  the shell reads the log, reduces it, and replaces it atomically with the reduction: a temporary
  file in the same folder, fsync, rename over the log, fsync the folder.
- Files: `shell/mirror.cjs`, `shell/test/mirror.test.cjs` (to create).
- Done when: `mirror_reduces_like_current_lines` passes on every vector and fails when a removal
  that names a text ends the entry although the entry now holds another text (the drift
  split-seams S9 found: the Playwright stub `Bridge.current` in
  `crates/tc-ui/app/no-loss.mjs:219-234` deletes on any removal);
  `random_mirror_histories_keep_every_unsaved_line` passes and fails when the launch writes in place.
