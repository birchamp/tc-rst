# G5: Browser journeys in CI, with no skips allowed

## Goal

A new GitHub workflow, `.github/workflows/app-e2e.yml`, builds `tc4`, the wasm UI and the fake
Door43, installs Chromium, and runs every browser journey in `parity/app/journeys/` on every push
and pull request. The job fails when any test fails and when any test is skipped, and it prints
each skipped test with its reason.

## Why it matters to a translator

Today no journey runs in CI, so a change can break creating, drafting, checking or aligning and
CI stays green. This job makes every journey a check that can fail before the change reaches a
translator.

## Funnel card

- **Invariants**:
  - INV-JOURNEYS-RUN: every browser test in `parity/app/journeys/*.test.mjs` runs in CI on every
    push and pull request, against a real `tc4`, the real UI build and Chromium (P1).
  - INV-A-SKIP-IS-A-FAILURE: the app-e2e job fails when any test reports a skip, and its log names
    each skipped test and the reason it gave.
- **Wrong states**:
  - A green CI while every browser journey skipped (today, run 39426828571).
  - A missing variable (for example `TC4_DOOR43_FAKE`) that silently skips a subset of tests.
  - Playwright that does not resolve, which skips every browser test.
  - An empty or cut-off test output that a skip counter reads as "0 skipped".
- **Code**:
  - Types: none in Rust. The skip rule is one pure function `countSkips(tapText)` in
    `parity/app/journeys/no-skips.mjs` (to create), returning `{ tests, skipped: [{ name, reason }] }`.
  - One entry point: the job `journeys` in `.github/workflows/app-e2e.yml` (to create) is the only
    CI place that runs the journeys with a browser.
  - Removed: nothing. `ci.yml`'s parity-baseline job keeps loading the journey files; Track B
    may not edit `ci.yml`.
  - Left to checks, and why a type cannot carry it: whether a test runs is decided at run time
    from environment variables (`kit.mjs:21-40`), so only a check of the run's output can hold
    it. The TAP check does that without editing the shared `kit.mjs`.
- **Checks**:
  - `no_skips_passes_a_run_with_no_skip`, `no_skips_names_each_skipped_test_and_its_reason`,
    `no_skips_fails_a_run_with_no_summary` in `parity/app/journeys/no-skips.test.mjs` (to create);
    kind: unit; runs in: ci.yml parity-baseline (its glob `parity/app/journeys/*.test.mjs` picks
    the file up) and app-e2e `journeys`.
  - The app-e2e `journeys` job itself; kind: journey; runs in: app-e2e.yml on push and pull
    request.
  - Proof it can fail: (1) make `countSkips` return an empty `skipped` list: the second unit test
    fails; (2) push a commit that removes `TC4_DOOR43_FAKE` from the job's env: the job fails and
    prints `INV-A-SKIP-IS-A-FAILURE:` with each door43 test and "set TC4_DOOR43_FAKE". Revert
    both and record the failing output in the log.
- **Prose**: a comment at the top of `app-e2e.yml` that says why pixels are not compared here
  (`docs/APP-DESIGN.md` §7.9: pixels gate only on the machine that captured the baseline).
- **Human**: none.

## Steps

### Step 1: Run every journey locally and record the result

- Do: on main, with Node 22, wasm-bindgen 0.2.129 and the wasm32 target installed
  (`TRACK-B.md` §5 steps 2-3), run exactly:
  ```bash
  cargo build -p tc4 --features test-hooks,fixture-backend
  cargo build -p tc-door43-fake
  crates/tc-ui/build-app.sh
  crates/tc-ui/build-app.sh --test-hooks --out target/tc-ui-app-hooks
  TC4_BIN=target/debug/tc4 TC4_UI=target/tc-ui-app TC4_UI_HOOKS=target/tc-ui-app-hooks \
    TC4_DOOR43_FAKE=target/debug/tc-door43-fake \
    node --test --test-reporter=tap parity/app/journeys/*.test.mjs | tee target/app-e2e.tap
  ```
- Files: none committed (the TAP file stays in `target/`).
- Done when: `grep -E '^# (tests|pass|fail|skipped)' target/app-e2e.tap` prints four lines and
  `# skipped 0`.
- Record: a log line `step 1` with the four counts. For each failing test, a `note` line
  starting "REQUEST:" with the file, the test name and its first error line. Do not change a
  failing test. Update `updated` and `next` (`TRACKING.md`).

  One job `journeys`, `runs-on: ubuntu-24.04`, `timeout-minutes: 45`, `env: CARGO_JOBS: 4`
  (`build-app.sh` reads it). Steps in this order:
  1. `actions/checkout@v4`.
  2. The same three steps INT-2 puts at the start of each `ci.yml` job:

### Step 3: Make a skip fail the job

- Do: create `parity/app/journeys/no-skips.mjs`. It reads the TAP file named by its first
  argument; counts the lines matching `/^\s*(not )?ok \d+ - (.*) # SKIP(.*)$/i`; reads the summary
  lines `# tests N` and `# skipped N`. It exits 1 and prints
  `INV-A-SKIP-IS-A-FAILURE: <n> tests skipped in app-e2e; every journey must run here`, then one
  line `<name>: <reason>` per skip, when any test skipped; and also when no `# tests` line exists or
  it says 0. Otherwise it prints `app-e2e: <N> tests, 0 skipped` and exits 0. Export
  `countSkips(text)` for the test. Write the three tests of the funnel card in
  `parity/app/journeys/no-skips.test.mjs`, with TAP samples inline (Node built-ins only). Add a
  workflow step after step 7: `node parity/app/journeys/no-skips.mjs app-e2e.tap` with
  `if: always()`.
- Files: `parity/app/journeys/no-skips.mjs`, `parity/app/journeys/no-skips.test.mjs` (to create);
  `.github/workflows/app-e2e.yml`.
- Done when: `node --test parity/app/journeys/no-skips.test.mjs` passes, and fails with
  `countSkips` returning no skips; the CI proof of the funnel card fails and then passes again.
- Record: a log line `step 3` with both failing outputs. Update `updated` and `next` (`TRACKING.md`).
