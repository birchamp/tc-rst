# FIX-791: A Door43 sync says what a teammate's newer version replaced

## Goal

After a sync with Door43, the Received sheet names each alignment, check, comment, setting, pin or
book where a newer version replaced another, and the "kept the newest version" count counts it,
as receiving an exchange file already does (owner ruling H5).

## Why it matters to a translator

Two teammates align the same verse between syncs: the newest alignment wins and the older one
goes to History. Today a Door43 sync says nothing, so the translator whose alignment was replaced
does not know to look in History. Found by the tC4 issues test of 2026-10-27 (tC4 #791,
`docs/evidence/tc4-issues-2026-10-27/fixed.md` on branch `tc4-fixed-issues-2026-10-27`).

## Before you start

- `grep -n "synced_view(&snapshot, me, &\[\]" crates/tc-app/src/sync.rs` on main 17c9fb18 shows
  the Door43 sync passing no received changes; USB exchange passes `report.received_ids`
  (`crates/tc-app/src/ports/usb.rs`).

## Funnel card

- **Invariants**:
  - INV-H5-RECEIVED-SAYS-WHAT-WAS-REPLACED: every sync path (Door43, exchange file, test hook)
    gives `synced_view` the changes it took in, so a record settled by the newest version is named.
- **Wrong states**:
  - A Door43 sync result with `replaced: []` and `kept_newest: 0` after a teammate's alignment
    replaced this computer's.
- **Code**:
  - Types: `tc_sync::SyncReport` gains `received_ids` (the changes the sync took in that the
    project holds after it), as `tc_sync::exchange::ReceiveReport` has. The sync run already
    collected them for its "some received work is held" check.
  - One entry point: `App::door43_sync` passes them to `synced_view`; the store backend's second
    sync (the username one) adds its own.
  - Removed: the `&[]` at the Door43 call.
  - Left to checks, and why: `synced_view` keeps its slice argument, since the test-hook sync
    builds its ids from written changes, not from a report.
- **Checks**:
  - `a_door43_sync_names_the_alignment_it_replaced` in `crates/tc-app/tests/app/port_contract.rs`;
    kind: two computers on the real Door43 port and `tc-door43-fake`; runs in: the `test-app` gate.
  - Proof it can fail: with `&[]` put back, `A's sync names one alignment … left: 0 right: 1`.
- **Prose**: none.
- **Human**: none. The Received sheet's rows and words already exist (B10, C7b).
