# G3: Release pipeline and installers

## Goal

A workflow `.github/workflows/release.yml` and one script per platform in `scripts/release/`
build the app for each platform the owner chooses (H3): `tc4` in release, the wasm UI, the English
bundle with the OBS pictures, Electronite and the shell. They make the installers, write
`BUILD-MANIFEST.json`, and install each installer on a fresh runner and run a smoke test there.
Nothing is published unless the release has no test hooks, ships every pinned file and has every
interface string translated. Windows builds are signed only on manual runs, and only after H4.

## Why it matters to a translator

This is how the app reaches a translator's computer. A release that installs, starts offline,
keeps their projects on uninstall, and shows its build number is what they need from it.

## Funnel card

- **Invariants**:
  - INV-A-RELEASE-HAS-NO-TEST-HOOKS: every shipped `tc4` binary passes `release_has_no_test_hooks`,
    and its UI is built without `--test-hooks`.
  - INV-EVERY-PINNED-FILE-IS-SHIPPED: every pin of `bundle/en` is in the shipped bundle, each
    downloaded file matching its `fetched.lock` sha256 and size; a build missing one fails.
  - INV-EVERY-INSTALLER-PASSES-THE-SMOKE-TEST: no installer is published unless a fresh runner of
    its platform installed it and the smoke test passed there.
  - INV-NO-UNTRANSLATED-STRING-SHIPS: no release is built or published on a tag run while
    `cargo test --release -p tc-api --test refusals` fails (`rulings/2026-10-22-H10.md`).
- **Wrong states**:
  - A published installer whose `tc4` accepts `--scenario` or serves `test/*` routes.
  - An installer without the OBS pictures, or with a different archive than the pinned one.
  - An installer that never ran on a clean machine (tC4 #45), or that needs a network at first
    run (tC4 #43), or whose uninstall deletes projects (tC4 #44).
  - `tc4.exe` that needs a Visual C++ runtime the computer lacks (tC4 #284).
  - About showing a build that is not the release's (tC4 #278).
  - An unsigned Windows build that starts with no window on a protected machine (tC4 #456, D99).
- **Code**:
  - Types: `BUILD-MANIFEST.json` has one fixed shape written by one script
    (`scripts/release/manifest.mjs`, to create): commit, version, platform, Electronite tag and
    sha256, the bundle's installs, the OBS archive's sha256, and the sha256 of each shipped file.
  - One entry point: one workflow (`release.yml`) calls one build script per platform
    (`scripts/release/build-linux.sh`, `build-macos.zsh`, `build-windows.ps1`, all to create);
    shared steps are Node scripts in `scripts/release/` called by all three.
  - Removed: nothing.
  - Left to checks, and why a type cannot carry it: what a binary contains, what an installer
    installs and whether it starts on a clean machine are facts of built files, so checks on the
    built files hold them.
- **Checks** (all in `release.yml`, jobs to create):
  - `release_has_no_test_hooks` with `TC4_RELEASE_BIN` on each platform's shipped binary; kind:
    contract.
  - `release_bundle_holds_every_pin` (to create, in `scripts/release/fetch-pinned.mjs`): the
    archive matches `fetched.lock`, and `bundle_store`'s summary line reads
    `<n> installs, 0 skipped, ...` (`crates/tc-app/examples/bundle_store/main.rs:53-56`);
    kind: contract.
  - `every_installer_passes_the_smoke_test` (to create, `scripts/release/smoke.mjs`, a port of tC4
    `smoke-api.cjs` and `smoke-installed.zsh`): start, offline resources, create a project with
    one book, save a verse, restart and read it back, `about_commit_matches_the_release_record`,
    a second launch starts no second server, uninstall keeps projects; kind: journey.
  - `tc4_exe_imports_no_vcruntime` (to create, `scripts/release/pe-imports.mjs`); kind: contract.
  - `every_crate_in_cargo_lock_has_a_notice` (to create, `scripts/release/notices.mjs`); kind:
    contract.
  - Job `translations`: `cargo test --release -p tc-api --test refusals`; kind: contract.
  - Proof it can fail: build once with `--features test-hooks` (the hooks check fails); delete the
    OBS zip before `bundle_store` (the pin check fails); the `translations` job fails today (155
    keys pending). Record each output in the log.
- **Prose**: `docs/RELEASE.md` (to create): how to cut a release, who holds the signing access,
  how to rerun the smoke tests.
- **Human**: H3 (platforms), H4 (signing identities), H10 (translations), H16 (the app's name,

## Steps

### Step 1: Build Linux in release and hold the two gates

- Do: write `scripts/release/build-linux.sh`. It sets `TC4_BUILD_COMMIT=$(git rev-parse HEAD)`;
  runs `cargo build --release -p tc4` and `crates/tc-ui/build-app.sh --release --out <stage>/ui`;
  runs `TC4_RELEASE_BIN=target/release/tc4 cargo test -p tc4 --test release -- --ignored`; and
  writes `BUILD-MANIFEST.json` with `scripts/release/manifest.mjs`. Create `release.yml` with
  `on: workflow_dispatch` (input `sign`, boolean, default false) and `push: tags: ['v*']`,
  `permissions: contents: read`, a job `build-linux` (ubuntu-24.04) and a job `translations`
  that runs `cargo test --release -p tc-api --test refusals`. Every build job has
  `needs: translations` with `if: github.event_name == 'workflow_dispatch' || needs.translations.result == 'success'`
  (`always()` on the job so the condition is read), so a tag run builds no installer while a
  rebuild key is untranslated, and a manual run still builds for pipeline testing
  (`rulings/2026-10-22-H10.md` rule 2).
- Files: `.github/workflows/release.yml`, `scripts/release/build-linux.sh`,
  `scripts/release/manifest.mjs` (to create).
- Done when: a manual run's `build-linux` is green and uploads a stage folder with
  `BUILD-MANIFEST.json`; `translations` fails with "a release needs every rebuild key translated"
  (the expected red until H10 is done).
- Record: a log line `step 1` with the run id and the `translations` failure text. Update `updated` and `next` (`TRACKING.md`).

### Step 2: Fetch the OBS pictures and build the bundle

  add the archive, run `cargo run --release -p tc-app --example bundle_store -- --from <work> --out
  <stage>/bundle`, and fail unless its last line contains `, 0 skipped,` (it prints `<n> installs,
  <m> skipped, <k> content files in <dir>`). File a REQUEST: "bundle_store
  must install the OBS picture pack from the downloaded archive; `fetched.lock`'s entry for
  `uW/obs_images_360` names no file" (the main team owns `bundle/` and `crates/`).
- Files: `scripts/release/fetch-pinned.mjs` (to create); `build-linux.sh`.
- Done when: `release_bundle_holds_every_pin` passes in `build-linux` once the REQUEST has landed,
  and fails when the downloaded archive is deleted before `bundle_store`. Until the REQUEST
  lands it fails, naming the OBS pack: that is correct; record it.
- Record: a log line `step 2`; the REQUEST as a `note` line. Update `updated` and `next` (`TRACKING.md`).

## Stop and ask when

- H3 has no ruling: do not start.
- Signing would run before an H4 ruling exists: stop.
- An installer needs the application id and `rulings/2026-10-22-H16.md` still marks part 4
  **open**: use an id that ends in `-test` in test builds only, never publish it, and tell the
  main team. Parts 1 and 3 are answered: version 4.1.0; the app is "translationCore", installed
  as "translationCore 4"; download page https://translationcore.com/tc4.
- A macOS or Linux installer would ship while every project opens read-only for a person with
  Dropbox installed (app-remaining F10, R28, `crates/tc-store/src/platform.rs:136-138`): tell the
  main team; it is a release blocker for those platforms.
- The work needs a change in `crates/**`, `bundle/`, `Cargo.*` or `ci.yml`: write a REQUEST.
- Runner minutes run out, or a gate fails twice in a row and you cannot tell why.
