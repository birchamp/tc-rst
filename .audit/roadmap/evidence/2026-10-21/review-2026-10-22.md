# Review of the roadmap for completeness, 2026-10-22

Asked: "Review the plan for completeness." Six lenses read the roadmap as it stood after the
2026-10-21 commit (`7285d9d`) and the H18-H22 rulings: goal coverage, the enforcement funnel,
tracking and hand-off between sessions, the Track B hand-off, card-level consistency, and
risks. They raised 96 findings (`review-2026-10-22-findings.json`: 6 blockers, 53 major, 37
minor). This file records what was done with each. The changes are in the working tree as one
commit after `7285d9d`; nothing is pushed.

## 1. What changed, in short

- **Two new cards.** `FIX-J` (P1's partial journeys J3, J12, J13, which had no owner) and
  `DOM-3` (capability tokens: `ProjectWriter`, `AppDataWriter`, `Net`, the Code-layer form of
  the write and network rules that CHK-1 only scans for).
- **The board enforces more of the tracking rules.** `board.py --check` now fails on: a card
  past `claimed` whose funnel card has an empty line or no `INV-` name (INV-FUNNEL-FIRST); a
  `done` card with no `verify` log line (INV-REVIEWED-BEFORE-MERGE); a done card with an
  undone dependency; two cards on one branch or worktree; a `later` gate ("S3 from step 4")
  whose step was logged before its gate was met; a `ROADMAP.md` row whose depends differ from
  the card's; `DONE` not depending on every card; a malformed `updated`. It warns on a lane
  with two owners, an active card whose dependency is not done, a claimed card whose branch
  has been quiet for a day, a card whose `needs_owner` or STOP line names a ruling that exists,
  a weekly sweep that is more than eight days old, and a milestone that ended without a rerun
  of the evaluation. `board.py --invariants` prints the registry of invariant names
  across cards and FUNNEL. `board_test.py` covers each new rule (27 tests).
- **Front-matter `later` gates.** A card whose first steps run before a dependency, but whose
  later steps need it, says so in `later: ["S3 from step 4"]` and keeps the dependency out of
  `depends`; the board checks the log against it (X, P, D1, I, F1, AQ1, E2 and others).
- **The H18-H22 rulings are wired in.** No card says STOP for them; S3, I, D1, V, X, E2, F1,
  C7b and the carried-files ruling cite `rulings/2026-10-22-H*.md`; the Update-a-book planner
  has one owner (I step 7a-1, a pure `plan_update` in `tc-import`, before S3 step 9 (d)); the
  kept-copy variant H22 rejected is gone from E2 and X.
- **A new agent can find the plan.** `AGENTS.md` sends every agent to `.audit/roadmap/README.md`;
  `.audit/STATUS.md`, `PROGRESS.md` and `HANDOFF.md` are marked history and no longer
  contradict the roadmap. README holds the one push rule, the one worktree rule (build on
  /home, never in a listed worktree), and the pointer to the pre-roadmap rulings. GLOSSARY
  defines `main`, worktree, orchestrator and the three verification lenses.
- **Session takeover has a rule.** TRACKING: a claimed card whose branch has been quiet 24 h
  may be taken over after a `takeover` log line; uncommitted work in a gone session's worktree
  is committed as `WIP` on its branch before anything else; a heavy gate run is announced with
  a `heavy` log line on the card so the two-run capacity rule can be followed. S2 step 0 and
  INT-4 carry the concrete instructions for the two cards that were held by silent sessions.
- **Track B is a complete brief.** TRACK-B names `main` by its real name
  (`claude/focused-ride-5uzj7p`), pins the tC4 reference clone to `d310bf3`, lists the hooks
  G1 and G5 code against in the frozen interface (including the help-desk key's file and
  location), lists tools for a fresh clone, says how REQUESTs travel (card log + pull request),
  explains that `gates.ps1` runs only on the owner's VM and what the developer runs instead,
  completes Package B′ with a start condition and edit lists, and gives G1, G3 and G4 a fallback
  owner (the app lane, if H2 names nobody by the end of M1).
- **Risks named in the roadmap.** ROADMAP now states what ships if H9 (freeze) is declined
  (preview build to named testers), what happens if H7 waits for v4.0.0, that a SQLite store
  is out of scope before format 1.0, that accessibility beyond tC4's own is out of scope, the
  laptop fallback for G2 (H17), a `nightly-windows` fallback when the VM cannot run (INT-2),
  attribution per bundled resource (G3), the release manager's facts (version scheme 5.0.0,
  minimum OS versions, release notes source, unsigned macOS package: G3 / H16), and the
  renderer and local-server security invariants (G1 INV-RENDERER-IS-ISOLATED, CHK-1
  INV-LOCAL-SERVER-IS-CLOSED, both in DONE's security row).

Validators after the changes: `python3 -I -B .audit/tools/board_test.py` passes (27 tests);
`python3 -I -B .audit/tools/board.py --check` reports 45 cards, 0 errors, 3 warnings (the two
silent sessions, which the takeover rule now covers, and S2 waiting on INT-4, which is the
expected state).
