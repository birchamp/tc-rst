# H16: the app's identity (version, name, download page, application id, projects folder)

- Asked: 2026-10-21, `ROADMAP.md` "What needs the owner"; put to the owner on 2026-10-22.
- Facts from the owner (2026-10-22 12:53): tC4 went out as a soft beta, translationCore
  4.0.0-rc2, build 2418892; the Rust build will be the first public release.
- Answer on the version (2026-10-22 13:03): "Sure let's go 4.1".
- Answer on the name and page (2026-10-22 13:36): "the app name is translationCore, but it
  should be installed as translationCore 4. Download page is translationcore.com/tc4".

This ruling is in parts. A step gated on H16 reads the part it needs; a part marked **open**
does not unblock the step that needs it.

## Part 1: version. Answered

The first public release is **4.1.0**, tag `v4.1.0`, semver from there (patch for fixes, minor
for features, major for a change that breaks an older project or sync peer). The number sorts
above `4.0.0-rc.2`, so beta users, the moved-notice table and any later update check see it
as newer. The product stays "translationCore 4" (the brand under which the beta went out and the
repository `translationCore4` is named); a minor bump tells the beta users what is true: their
4.0 projects are imported, one way, and their team moves with the straggler notice.

Code: `Cargo.toml` `[workspace.package] version` (today `0.1.0`) becomes `4.1.0` in G3's
release step; `BUILD-MANIFEST.json` and About show it; `docs/RELEASE.md` states the scheme.

## Part 2: projects folder and first launch. Answered as recommended

Projects live in `~/translationCore4/projects`. The help pages are corrected to say so (REF1).
At first launch, and from the Import window, the app lists tC4 4.0 projects found in
`~/pankosmia/tc4-projects` and offers *Import* for each; the tC4 folder is never written (F1
step 9). The owner accepted the recommendation by moving to the version question without
objection; if that is wrong, say so and F1 step 9 changes.

## Part 3: the app's name as shown and the download page. Answered

- The app's name, as shown in its window title, About, the help pages and the release notes:
  **translationCore**.
- The installed name, as the installer, the install folder, the Start menu / Applications entry
  and the uninstaller show it: **translationCore 4** (so it sits beside, and is told apart from,
  an installed tC4 beta and older translationCore versions). Executable and bundle names stay
  `tc4` (`tc4.exe`, `translationCore 4.app`).
- The download page: **https://translationcore.com/tc4**. REF1's install paragraph and G3's
  `docs/RELEASE.md` name it; the help-desk and straggler notices that point people to a download
  point there.

## Part 4: the application id for `moved.json`. Open, with a recommendation

The stable id tC4's moved-notice table will know (`docs/TC4-REQUEST-MOVED-NOTICE.md`). The
rebuild chooses it and tells the tC4 team. Recommended: `translationcore-4` (lower case, no
spaces, never changes across versions; the display name can change without touching it). The
owner says yes or gives another id; G3 step 8 uses the recommended id only after that yes.
