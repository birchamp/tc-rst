# H20: "Update a book" with a file whose starting point the app cannot know

- Asked: 2026-10-22, by the roadmap session, in conversation with the owner.
- Options: A, one grouped review row with "Accept all from the file", the project's text shown
  until then (recommended); B, the file's text wins; C, the person picks which checkpoint the file
  came from.
- Answer: "A, but should we not have conflicts for empty verses?" The roadmap session proposed
  the empty-verse rule below in both directions, and recorded it.

## The rule

When the file is not byte-equal to a version the app wrote, so its base is unknown
(`docs/STORAGE-DELTA-2026-10-21.md` §2.16, U3 and Q5):

1. A verse equal in the file and the project: nothing is imported.
2. **The project's verse is empty and the file's verse has text:** the file's text is imported
   directly, with no conflict.
3. **The file's verse is empty and the project's verse has text:** the project's text stays, with
   no conflict. The report lists the verse as "left as it was: empty in the file".
4. **Both have text and they differ:** the verses go into one grouped row in the conflict review,
   with "Accept all from the file" and verse-by-verse choices. The project's text stays shown
   until a choice is made (the import cause carries the `unknown_base` mark).

When the base is known (the file is a copy of a version the app wrote), the ordinary rule applies:
only a verse changed on both sides since the base is a conflict.

## Known edge

If a teammate deliberately cleared a verse and the file still holds its old text, rule 2 brings
the old text back without a question. The cleared version stays in History. Accepted as rare.

"Empty" means a verse with no words (the same test Home's drafted count uses). Formatting or
markers with no words count as empty. (Inference by the roadmap session; correct it if needed.)

## Effect for translators

Drafting new verses elsewhere and updating a book brings them in with no review. Only verses that
have text on both sides and differ wait for a choice.
