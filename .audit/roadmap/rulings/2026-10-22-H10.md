  (2026-10-22 12:53).

## The rule

1. The owner arranges the translations of `crates/tc-ui/assets/i18n-rebuild/*.pending.json`
   (155 keys, nine languages). G3 step 9 sends the files and merges what comes back. The
   translator or service is not named yet; this ruling file is the one G3's `later` gate
   (`H10 from step 9`) looks for, and step 9 starts when the owner hands over the translated
   files.
2. The gate is in CI, not in a person's memory (INV-NO-UNTRANSLATED-STRING-SHIPS, G3): the
   release workflow's `translations` job runs `cargo test --release -p tc-api --test refusals`.
   On a tag run (`refs/tags/v*`) every build job `needs: translations`, so no release installer
   is built, let alone published, while a rebuild key is untranslated. A manual run
   (`workflow_dispatch`) may still build with `translations` red, for testing the pipeline
   before the translations land; `publish` never runs on a manual run.
3. The English-fallback allowlist (`ACCEPTED-ENGLISH.json`) is not taken. It remains possible
   only by a later ruling that names it; the `refusals` test reads it only if that ruling file
   exists.

## Effect for G2

G2's Arabic captures (step 4, `later: H10 from step 4`) wait for the translated files to land
on main, not just for this ruling, since captures with English fallback would need redoing.
G2's gate text says so.

## Unblocks and changes

G3 step 1 (the build jobs' `needs` on tag runs), step 8 (`publish` already needs
`translations`), step 9. G2 step 4's gate reads "the translated files are on main". DONE step 4
ticks H10 when the `translations` job is green on main.
