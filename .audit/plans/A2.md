### 0.4 What the existing code must change (step B)

1. **Quit order** (D5): today `run` sets closing, runs `backend.quit()`, then drains. It must
   drain first, then quit, inside one 5 s budget.
2. **A call outlives its client** (D12): today `api()` awaits `backend.call` inside the request
   future, so a reload or a closed window can drop a save half way, and the drain does not wait
   for it. Run the call on its own task, which holds the in-flight count.
3. **stdin as bytes**: `watch_stdin` uses `read_line`, which fails on a line that is not UTF-8,
   and a failure is taken as "stdin closed": one stray byte would quit the app. Use
   `read_until(b'\n', &mut Vec<u8>)` and `serde_json::from_slice`.
4. **`Stub::call`** compares `path != "test/quiet"` in every build: put the exclusion under
   `#[cfg(feature = "test-hooks")]` (without hooks there is no such route), so a release binary
   holds no `test/` text (`release_has_no_test_hooks`, step H).
5. **`events::step`**: `serde_json::to_string(&frame).ok()?` ends a stream silently when a frame
   does not serialize. Keep ending it (skipping would drop a frame), but log one line first
   (`log::warn("a frame could not be written; the stream ends")`).

A2 and A3 are built at the same time from `98315a4`, so neither may call the other. A3's plan
(D1) makes tc-app transport-free: `App::call(path: &str, body: &[u8]) -> Answer`

`Answer::Ended`; `Then::Continue`, and with `test-hooks` `Then::EndProcess`),
`App::events() -> &EventBus` with `EventBus::subscribe(after: u64) -> Subscription` and
`Subscription::next() -> Next::{Frame(EventFrame), Lagged, Closed}` (built on p0-a3 as planned:

the stream (server-sent events written from the backend's frames, the 15 s heartbeat, `?after=`
handed to the backend, a `Lagged` subscription ending the connection so the UI reconnects and

tc-app's `EventBus` (A3 step 2, built); a second ring in tc-server would be deleted at the join

join; the join adds an end-to-end test over tc-app's bus. Step F writes this split into the A2
row with the reason.

### D4. `app.lock`: an OS lock, and the holder's pid in `app-lock.json` beside it

§5.1 says `tc4` "takes `app.lock` in app data and writes its pid into it", so a new `tc4` that
waits can name the old one. On Windows that cannot work: `File::try_lock` locks the whole file
with `LockFileEx`, and Windows then refuses every other process's read of it
(`ERROR_LOCK_VIOLATION`). tc-store meets the same limit for `.tc/lock` and accepts an unnamed
holder there (`main:crates/tc-store/src/open.rs`, "unnamed when the platform will not read a
locked file"). For `app.lock` the restart case is exactly the Windows case (AD39: a `tc4` still
closing after its shell died), so the name must survive:

- `app.lock` is the lock only: `OpenOptions::new().read(true).write(true).create(true)
  .truncate(false)` (clippy's `suspicious_open_options` wants `truncate` explicit), then
  `File::try_lock()` (stable since 1.89; toolchain 1.97). Never read, renamed or deleted: the OS
  releases it when the process ends, a crash or a kill included.
- Right after taking it, the holder writes `app-lock.json` = `{"pid": <u32>, "at": <WallMs>}`
  by write-temp-then-rename in app data (temp `app-lock.json.<pid>.tmp`, `sync_all`, rename,
  then on Unix open the folder and `sync_all` it). If the write fails, log one line and
  remove any old `app-lock.json` (best effort), so a stale record never names a process that no
  longer holds the lock: naming the wrong process could lead a person to end an unrelated
  program. The only window left is a crash between taking the lock and the rename, which is
  microseconds wide.
- `TryLockError::WouldBlock` → poll every 100 ms for up to 10 s (AD39). `TryLockError::Error(e)`
  → a start failure (exit 4), never a wait. Taken → go on. Still held after 10 s → read
  `app-lock.json` (missing or unreadable means "unnamed"), print exactly one stdout line,
  `{"error":{"type":"appLockHeld","value":{"pid":1234}}}` (`"pid":null` when unnamed), one
  stderr sentence (`tc4: process 1234 still holds <app_data>/app.lock after 10 s; it may still
  be closing. End it, then start translationCore again.`, or "another process" when unnamed),
  and exit with code 3. A waiting `tc4` prints nothing and binds nothing.
- Order at start: parse arguments → create app data → take `app.lock` (the wait) → bind → print
  the address line → serve.
- `AppLock` lives in tc-server (`src/applock.rs`), not in tc4, so
  `cargo check -p tc-server --target x86_64-pc-windows-msvc` checks it (tc4 pulls in
  tc-door43's TLS stack, which does not cross-check here).

Design text (step E): §5.1's `app.lock` bullet, AD39's "(the lock records its pid)", §4.9's
`app.lock` row, and a new `app-lock.json` row right after it (exact text in step E).

### D5. Quit, closed stdin, and closing (changed at re-plan)

`Server::run` waits for the first of: a stdin line that parses as `{"quit":true}` (`Control {
quit: bool }`; other keys ignored; any other line logged and ignored), stdin end-of-file or a
read error, `backend.quitting()`, and with `handle_signals` Ctrl+C or, on Unix, SIGTERM. Then:

1. Set `closing`: every new request answers **503** with `Connection: close` (a save that
   arrives now stays dirty in the UI; it never runs against a closing backend).
2. **Drain first**: wait up to `min(drain_within, close_within)` (1 s) for the requests being
   answered and the backend calls still running (D12) to finish. A save accepted before the quit
   reaches a backend that is still open, and its reply reaches the UI, so the field is clean
   instead of offered again at the next launch. The first plan quit first and drained after,
   which let a save in flight meet a closing backend.
3. If the drain saw any, sleep 25 ms, so the replies just finished reach their sockets (each
   connection writes on a task of its own).
4. `tokio::time::timeout_at(started + close_within, backend.quit())`: the backend's quit work
   (aligner links, checkpoints, actors; later units) gets what is left of the **one 5 s budget**
   for the whole close, so `closed_stdin_quits_within_5_s` holds whatever the backend does. The
   cap exists so a hung disk never keeps a dead shell's `tc4` alive holding `app.lock` and
   `.tc/lock`; what the store wrote is durable, and a cut checkpoint runs again later. Log a
   line when the cap cut it.
5. End every event stream (`streams_end`).
6. Unless the cause was a closed stdin, write `{"closed":true}\n` and flush; ignore write
   errors (the shell may be gone; Rust ignores SIGPIPE, so the write fails instead of killing
   the process).
7. Abort the serve task and return the `Exit`.

`tc4` then calls `std::process::exit(0)`, with a comment: tokio reads stdin on a blocking-pool
thread that stays in `read()` while the shell keeps stdin open, and dropping the runtime waits
for blocking tasks, so it would never return. The stand-in does the same
(`spikes/electronite/src/main.rs`).

### D6. Test hooks: the feature, the flag, `test/crash` and ending the process

- Cargo feature `test-hooks` in tc-server (`= ["tc-api/test-hooks"]`, in the tree) and in tc4
  (`= ["tc-server/test-hooks", "tc-api/test-hooks"]`); runtime flag `tc4 serve --test-hooks`,
  which exists only with the feature (without it: "unknown flag --test-hooks", exit 2). The test
  rows are routed only after `Server::with_test_hooks()`.
- **Feature unification**: tc-api's tests turn on `tc-api/test-hooks` through a self
  dev-dependency, so in `cargo test --workspace` and `cargo clippy --workspace --all-targets`
  tc-api always has the `test` rows. tc-server (in the tree) and tc4 have the same self
  dev-dependency, so all three agree in those builds. Every item used only by hooks is
  `#[cfg(feature = "test-hooks")]`, or `cargo clippy -p tc-server -p tc4 --lib --bins` (no
  dev-dependencies, so no hooks: the release shape) fails on dead code. Step G adds that line
  to CI.
- **Ending the process** (`src/hooks.rs`, all cfg'd):

  ```rust
  /// The exit code of a test crash. tc-app's `hooks::CRASH_EXIT_CODE` is the same (A3); the
  /// join asserts it.
  pub const CRASH_EXIT_CODE: i32 = 86;
  pub trait Ender: Send + Sync + 'static {
      /// A crash before the reply: ends the process now. Returns only in tests.
      fn end_now(&self, at: tc_api::test::CrashPoint);
      /// A crash after the reply: ends the process once the reply's body was handed to the socket.
      fn end_after_reply(&self);
  }
  /// `end_now`: `std::process::exit(CRASH_EXIT_CODE)`. `end_after_reply`: a std thread sleeps
  /// 100 ms (the body is on the wire by then on loopback), then exits.
  pub struct ExitProcess;
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub enum Ended { Now(CrashPoint), AfterReply }
  /// Tests: records each call with its `Instant`, never exits.
  #[derive(Default)] pub struct RecordingEnder { calls: Mutex<Vec<(Ended, Instant)>> }
  impl RecordingEnder { pub fn calls(&self) -> Vec<(Ended, Instant)>; }
  ```

  `ServerConfig` gains `#[cfg(feature = "test-hooks")] pub ender: Arc<dyn Ender>`
  (`ServerConfig::new` sets `Arc::new(ExitProcess)`). `Answer` gains
  `#[cfg(feature = "test-hooks")] Ended` and `Then` gains `#[cfg(feature = "test-hooks")]
  EndProcess`. For `Reply { then: EndProcess }` the route wraps the body in
  `EndAfterBody { inner: axum::body::Body, ender: Option<Arc<dyn Ender>> }`, which implements
  `http_body::Body` by delegating `poll_frame`, `is_end_stream` and `size_hint` (so the
  `Content-Length` stays), and calls `end_after_reply()` **in `Drop`**. Trap: hyper takes the
  last frame of a sized body, sees `is_end_stream()` and drops the body; it never polls it to
  `None`, so a hook on `poll_frame` returning `None` never fires. `http_body::Frame` is not
  re-exported by axum: add `http-body = "1.1.0"` (in the lock) to `[workspace.dependencies]`
  and to tc-server. `Answer::Ended` → 503 with `Connection: close` and no body (only a

- **The Stub's crash points** (until the join; tc-app's replace them, A3 D5). `Stub` gains

### D7. Uploads and downloads

- **Uploads** (§5.5, AD26, A-28). `POST /api/v1/uploads`, raw body, headers `X-Tc-Upload-Name`
  (the file's name, UTF-8, percent-encoded) and `X-Tc-Upload-Flow` (`UploadFlow::from_header`).
  It is under `/api/`, so the guard requires the token, `Origin` and `X-Tc-Api: 1`, as for any
  API call. Order of checks:
  1. Flow header missing or unknown → `Reply::Err(BadRequest { field: "X-Tc-Upload-Flow",
     reason })` with status 200 (AD9: a domain answer) and `Connection: close` (the body was not
     read).
  2. `Content-Length` over `limits.upload_cap(flow)` → **413** at once (`too_large()`), nothing
     read, nothing written. A size equal to the cap is allowed.
  3. Name header missing, not visible ASCII, not valid percent-encoding, not UTF-8, empty, over
     255 bytes, or holding a control character (`char::is_control`) → `BadRequest { field:
     "X-Tc-Upload-Name" }`, `Connection: close`. **The name is never a path**: the file is
     `uploads/<32 hex>` only.
  4. Stream `request.into_body().into_data_stream()` into `uploads/<id>.part` through a
     `tokio::io::BufWriter::with_capacity(1 MiB, tokio::fs::File)`, counting bytes. Past the cap
     (a chunked body, or a body longer than it declared) → stop, 413. A body error (the client
     went away) → no entry. A write error (disk full) → `Reply::Err(Refused(Refusal::Upload(
     UploadRefusal::NotWritten { reason: error.to_string() })))`.
  5. Complete → flush, drop the file, rename `.part` to `uploads/<id>`, register
     `Upload { id, name, size, flow, path }`, answer `Reply::Ok(UploadView { id, name, size })`.
  - A `PartFile { path, armed: bool }` guard deletes the `.part` in `Drop` unless the rename
    disarmed it: hyper drops the handler future when a connection dies, so cleanup on the error
    path alone would leave files behind. Its `std::fs::remove_file` is one unlink; say so in a
    comment (it runs on the async side).
  - No fsync: `uploads/` is emptied at every start, so a crash never reads a partial upload
    back, and an fsync of 4 GiB would cost seconds. Say so in a comment.
  - The id: 16 bytes from `getrandom::fill`, lowercase hex, `UploadId::parse`.
  - The rename and the downloads' rename go through one helper that retries up to 10 times,
    50 ms apart, on `ErrorKind::PermissionDenied` (on Windows a virus scanner can hold a file
    that was just written; G0 ran with Defender on). It runs on the blocking pool.
  - The route has `DefaultBodyLimit::disable()` and is not counted in flight (the gate already
    skips `UPLOADS_PATH`).
  - `Uploads { dir, entries: Mutex<HashMap<UploadId, Upload>> }` with
    `get(&UploadId) -> Option<Upload>` and `take(&UploadId) -> Option<Upload>` (the caller then
    owns and deletes the file). Later flows (F1, E2, B4b's USFM) reach it through the join
    adapter; in A2 only tests call it.
- **Downloads registry** (§5.5). `Downloads { dir, keep: Duration, entries: Mutex<HashMap<
  DownloadId, Entry { name, content_type: &'static str, path, size, added: std::time::Instant
  }>> }` with `dir() -> &Path` (a producer writes its file there first, so `add` is a rename on
  one volume), `add(written: &Path, file_name: &str, content_type: &'static str) ->
  Result<DownloadId, DownloadError>` (blocking: called from a job's blocking thread; validates
  the name like an upload's and also refuses `/` and `\`; renames to `downloads/<id>`),
  `pub(crate) fn sweep(&self, now: Instant) -> Vec<PathBuf>` (removes entries older than `keep`
  and returns their files; the sweeper task deletes them with `tokio::fs::remove_file`, every
  `limits.downloads_sweep`). `DownloadError { BadName(String), Random, Io(io::Error) }`
  (`thiserror`). `GET /download/{id}/{name}`: the id must parse and be registered and `name`
  (axum's `Path` decodes it) must equal the registered name, else 404; answer the file streamed
  in 256 KiB chunks (`futures_util::stream::unfold` over a `tokio::fs::File`; there is no
  tokio-util in the lock) with `Content-Type`, `Content-Length`,
  `Content-Disposition: attachment; filename="<ASCII fallback>"; filename*=UTF-8''<percent-encoded>`
  (fallback: each char that is ASCII graphic or space and not `"`, `\`, `%` or `;` kept, every
  other `_`; encoding: `utf8_percent_encode(name, NON_ALPHANUMERIC)`), `Cache-Control:
  no-store`. A file stays 10 minutes and may be fetched more than once in that time.
- `ServerHandle` (`#[derive(Clone)]`, holds `Arc<Uploads>` and `Arc<Downloads>`) with
  `uploads()` and `downloads()`; `Server::handle(&self) -> ServerHandle`. `Shared` holds the same
  two `Arc`s.
- `Server::bind` empties exactly `<app_data>/uploads` and `<app_data>/downloads`
  (`remove_dir_all`, which does not follow symlinks, then `create_dir_all`). A failure to empty
  is logged, never fatal: the registries only serve ids of this run. A failure to create is
  `ServerError::AppData`.
- `Limits` gains `upload_cap: fn(UploadFlow) -> u64` (default `UploadFlow::cap`; a test passes
  a non-capturing closure), `downloads_keep: Duration` (10 min) and `downloads_sweep: Duration`
  (60 s).
- `/media/obs/...` (B7) and `/print/{job}` (D2) are not routed in A2; their units add them. Until
  then they answer 401 or 404 behind the guard.

### D9. The loopback spike

What it measures (§8.3, AD18, A-14): the round trip of one aligner-sized request from a wasm
`fetch` in Chromium to `tc4 serve` over loopback and back to a parsed reply in wasm, p95, twice:
**plain** (the page's own `fetch` sets `X-Tc-Token`, as the UI does under AD11) and **through a
header-adding proxy** (the page sets no token; a request interceptor adds `X-Tc-Token` to every
request, `/api/` included: the cost if the shell's filter could not leave `/api/` out).

- **The endpoint**: `test/echo` (built in tc-api, answered by the Stub). The join must give
  tc-app the same one-line handler (A3's router needs a handler per row).
- **Proxy mechanism**: Playwright's request interception, `context.route('**/*', handler)` with
  `route.continue({ headers: { ...(await route.request().allHeaders()), 'x-tc-token': token } })`.

  driver), which adds the header: the shape of Electron's `onBeforeSendHeaders` listener (a hop
  to the main process's JS and back). An HTTP forward proxy would add a TCP hop instead, and
  Chromium bypasses proxies for loopback by default. Use `allHeaders()`, not `headers()`: the
  latter leaves out headers the network stack adds, and a request without `Origin` is a 403.

### D12. A backend call runs on a task of its own, which the drain waits for (new at re-plan)

hyper drops a handler's future when its connection dies (a reload, a closed window, a killed
browser). If the backend call runs inside that future, a save can stop half way, and the drain
of D5 no longer counts it. tc-app spawns its writes (A3 D4), but the server must not rely on
each backend getting that right. So `routes::api`:

```rust
let backend = Arc::clone(&state.backend);
let guard = InFlight::enter(Arc::clone(&state.shared));   // owned: holds Arc<Shared>
let call = tokio::spawn(async move {
    let _guard = guard;          // the drain waits for the call, not for its client
    backend.call(path, body).await
});
match call.await {
    Ok(answer) => answer_response(answer /* , ender for EndProcess */),
    Err(error) if error.is_panic() => { log::warn(format_args!("a request to {path} panicked")); 500 }
    Err(_) => 500,
}
```

`InFlight` holds `Arc<Shared>` instead of `&Shared` (the gate keeps its own guard for the
request; the task's guard covers the call). The `catch_unwind` and `AssertUnwindSafe` go: a
panic in a spawned task is a `JoinError`. `Backend::call`'s doc gains: "The server runs it on a
task of its own: it runs to its end even when the client goes away." `Backend::quit`'s doc
gains: "A call that outlasted the drain may still be running."

Design text (step B): §5.3, after "`every_endpoint_is_routed_once` checks the router serves
exactly `tc_api::ALL`.", add: "Each API call runs on a task of its own, so a client that goes
away (a reload, a closed window) never cuts a call short, and the quit waits for calls still
running (§5.1). *(A2)*"

## 5. Invariants (the verifiers will attack these)

1. **A quit never skips the backend's quit work** (aligner links and checkpoints, later), except
   a test crash and the 5 s cap; a closed stdin, a signal and `app/quit` are quits, not crashes.
2. **No request runs against a closing backend**: new requests get 503 before they reach it, so
   the UI keeps their text dirty; requests already accepted finish first (D5's drain).
3. **A call is never cut short by its client going away** (D12), and the quit waits for it up to
   the drain's limit.
4. **A second `tc4` never serves beside the first**: it binds and prints nothing until it holds
   `app.lock`, and a held lock names the holder after 10 s; a stale record never names a process
   (D4).
5. **No frame is dropped silently by the server**: it writes every frame the backend yields, in
   order; a lagging subscription ends the stream so the UI reconnects (replay or `Resync`),
   never a skipped frame on a stream that stays open.
6. **A partial upload is never complete**: it is registered only after its last byte is written
   and renamed; a cap, a cut connection, a dropped handler or a disk error leaves no `.part`; the
   person's name for the file is never a path.
7. **A body over a cap is refused whole** (413), never cut and passed on.
8. **The token is never logged**, nor a query that may hold it; the address line is the only
   place it is printed.
9. **No test hook exists in a release build**: no `--test-hooks` flag, no `test/` route or text,
   no `EndProcess` path (`release_has_no_test_hooks`).
10. **Every endpoint of `tc_api::ALL` reaches the backend, each once; nothing else does.**
11. **Help pages never redirect; no directory is served; no path leaves the UI folder.**
12. **One stray line on stdin never quits the app**; only `{"quit":true}` and the end of stdin do.

## 7. Traps found while planning

1. **`crates/tc4` without sources breaks the workspace** (0.3): delete it before the first
   commit; recreate it in step E.
2. **Windows cannot read a locked file** (std's `try_lock` locks the whole range): the holder's
   pid goes in `app-lock.json` (D4).
3. **Feature unification**: tc-api's self dev-dependency turns its `test-hooks` on in every test
   and `--all-targets` build. tc-server and tc4 have the same self dev-dependency; hook-only items
   are cfg'd; `cargo clippy -p tc-server -p tc4 --lib --bins` is the release-shaped lint (D6).
4. **`Router::layer` skips a fallback added later**: the fallback is set before the layers (in
   the tree); keep new routes before `.fallback` too.
5. **hyper does not poll a full body to `None`**: end the process from the body wrapper's `Drop`
   (D6). **`http_body::Frame` is not re-exported by axum**: add `http-body`.
6. **hyper drops a handler's future when its connection dies**: spawn the backend call (D12),
   and delete a `.part` from a `Drop` guard (D7).
7. **tokio's stdin reader thread blocks in `read()`**: exit with `std::process::exit`, never by
   dropping the runtime (D5). Any harness that starts `tc4` keeps its stdin open (a closed stdin
   is a quit): the spike driver and A6b's `env-rust.mjs` spawn it with a piped stdin.
8. **`read_line` fails on a line that is not UTF-8**, and a failure reads as "stdin closed": use
   `read_until` (0.4 item 3).
9. **Nagle on loopback**: `TCP_NODELAY` on every accepted socket (in the tree).
10. **The CSP blocks inline scripts on index.html**: the spike page and A4a's `index.html` load
    their scripts from `/ui/` (D9).
11. **Playwright's `route.request().headers()` leaves out `Origin`**: use `allHeaders()` (D9).
    **`page.evaluate` and typed arrays**: return `Array.from(...)` from the page.
12. **Playwright 1.61.1 (tC4's) needs a Chromium that is not installed**: use
    `parity/ds-gallery/node_modules/playwright` (1.56.1, Chromium build 1194) from the main
    checkout, read only (D9).
13. **`HTTPS_PROXY` is set in this container**: no `reqwest` client against loopback in tests;
    `node:http` in the spike ignores it.
14. **axum's extractors cap bodies at 2 MB** (`DefaultBodyLimit`): read bodies yourself and
    disable it on the API (in the tree) and upload routes.
15. **tower-http's `ServeDir` redirects directories**: not used (in the tree).
16. **`endpoint_table!` resolves the callback at the call site**: define the callback macro above
    the invocation in the same module (as `routes.rs` and `stub.rs` do).
17. **Two edits of one design line conflict at merge**: leave §4.1, §5.4's first bullet, §5.8,
    §5.1's command-line bullet and the §10 order paragraph to A3 (D1). Your A2 row edit sits on
    the line above A3's row, and your §5.1 `app.lock` bullet follows the command-line bullet A3
    edits: whoever merges second keeps both texts. Put the `app-lock.json` row of §4.9 right
    after the `app.lock` row, not at the end of the table, where A3 adds a paragraph.
18. **A3 changed tc-api too** (`Feature::{Account, Feedback}`, `StoredText.base`, golden
    `test/fieldLog.json`, lines in `tests/golden.rs` and `tests/roundtrip.rs`): if a merge of
    `phase0` brings them, keep both sides of each list and regenerate goldens only for your own
    types.
19. **Disk**: `CARGO_INCREMENTAL=0`, `-j 2`, crate-scoped tests until the end, prune when under
    6 GB, 1.1 GB free before the 1 GiB upload test.
20. **The 1 GiB test and `tokio_never_blocked` read process-wide numbers** (`VmHWM`, lateness):
    each is its own test binary, or parallel tests in the same process would spoil them.
21. **A saturated single worker looks blocked**: tokio polls its timer and I/O driver only every
    61 task polls when busy, and debug-built hyper handles a request in a fraction of a
    millisecond, so an unpaced load could push the ping past 50 ms with no blocking call. Pace the
    load (step F) and keep `the_watchdog_sees_a_blocked_worker` as the proof that the test can
    fail.
22. **`File::try_lock` returns `TryLockError::WouldBlock` for a held lock and

23. **The two release builds share `target/release/tc4`**: run the spike before the plain release

24. **An early answer to an upload leaves its body unread**: send `Connection: close` with every
    answer given before the body was read (413, a bad header).
25. **A browser that is still sending may never see a 413** (the server closes and the client
    gets a reset): the UI checks a file's size first (step C's design text); the server's 413 is
    the backstop.
26. **Do not use `git stash`**: one stash serves every worktree of the repository.

## 8. Notes for the join (A3 step 11, or step I here)

The adapter lives in tc4 (tc-server and tc-app never depend on each other; the orphan rule
allows a tc4 newtype):

```rust
struct AppBackend(tc_app::App);
struct AppEvents(tc_app::events::Subscription);
impl tc_server::EventSource for AppEvents {
    async fn next(&mut self) -> tc_server::Next {
        match self.0.next().await {
            tc_app::events::Next::Frame(f) => tc_server::Next::Frame(f),
            tc_app::events::Next::Lagged => tc_server::Next::Lagged,
            tc_app::events::Next::Closed => tc_server::Next::Closed,
        }
    }
}
impl tc_server::Backend for AppBackend {
    type Events = AppEvents;
    async fn call(&self, path: &'static str, body: Bytes) -> tc_server::Answer { /* map tc_app::Answer and Then one to one */ }
    fn subscribe(&self, after: u64) -> AppEvents { AppEvents(self.0.events().subscribe(after)) }
    async fn quit(&self) { self.0.quit().await }
    async fn quitting(&self) { self.0.quitting().await }
}
```

`tc4 serve` then builds `AppConfig` from its flags (`--projects` absent → tc-app's default
folder; `build: BuildInfo { version: BUILD_VERSION, commit: BUILD_COMMIT }`), starts the `App`
inside the runtime after `bind` and after the address line, and runs `AppBackend` instead of the
`Stub`. `CRASH_EXIT_CODE` is asserted equal on both sides. tc-app must answer `test/echo`
(`Ok(EchoView::of_size(req.size))`, `BadRequest` above `MAX_ECHO`). Later units reach uploads
and downloads through traits tc-app declares and this adapter implements with
`ServerHandle::uploads()` and `downloads()`. The Stub stays as the backend of tc-server's tests.
