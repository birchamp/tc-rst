## 1. Decisions this plan makes (read before coding)

### D1. The seam with tc-app: tc-server is generic over a transport-shaped `Backend`

A2 and A3 are built at the same time from `98315a4`, so neither may call the other. A3's plan
(D1) makes tc-app transport-free: `App::call(path: &str, body: &[u8]) -> Answer` (bytes in,
bytes out; `Answer::Reply { body, then: Then }`, `Answer::NotFound`, and with `test-hooks`
`Answer::Ended`; `Then::Continue` and with `test-hooks` `Then::EndProcess`), `App::events() ->
&EventBus` with `EventBus::subscribe(after: u64) -> Subscription` and `Subscription::next() ->
Next::{Frame(EventFrame), Lagged, Closed}`, `App::quit()` and `App::quitting()`. tc-app owns the
typed per-row dispatch (`Handle<E>`, §3.3), the reply cache and body digests (AD4), `hello`'s real
state, the event ring with `Resync` and coalesced progress (§4.1: `EventBus`, "broadcast plus the
ring"), and the crash points before the store and before the reply (A3 D5).

So tc-server never depends on tc-app, and tc-app never depends on tc-server. tc-server defines a
trait with the same shape, and the program crate `tc4` joins the two with a 40-line adapter
(section 7) once both have merged:

```rust
// crates/tc-server/src/backend.rs
pub trait Backend: Send + Sync + 'static {
    type Events: EventSource;
    /// One API request. `path` is `service/name`, always a row of tc-api's tables (the server
    /// answers 404 for any other path before it calls this). `body` is at most `Limits::api_body`.
    fn call(&self, path: &'static str, body: Bytes) -> impl Future<Output = Answer> + Send;
    /// The event stream after `after` (0: the reader holds no frame). Replay, `Resync` and
    /// coalescing are the backend's (tc-app's `EventBus`, §4.1).
    fn subscribe(&self, after: u64) -> Self::Events;
    /// §5.1's quit work before the process exits: aligner links, checkpoints, actors. It may be
    /// called after `app/quit` already ran it, so it must be idempotent.
    fn quit(&self) -> impl Future<Output = ()> + Send;
    /// Resolves once the app asked to quit (`app/quit`).
    fn quitting(&self) -> impl Future<Output = ()> + Send;
}
pub trait EventSource: Send + 'static {
    fn next(&mut self) -> impl Future<Output = Next> + Send;
}
pub enum Next { Frame(tc_api::event::EventFrame), Lagged, Closed }
pub enum Answer {
    /// HTTP 200, `application/json`: the bytes of a `tc_api::Reply`.
    Reply { body: Vec<u8>, then: Then },
    /// 404.
    NotFound,
    /// A test ender ended the backend: no reply (only with `test-hooks`).
    #[cfg(feature = "test-hooks")]
    Ended,
}
pub enum Then {
    Continue,
    /// `test/crash { at: afterReply }` fired: end the process once this body is sent.
    #[cfg(feature = "test-hooks")]
    EndProcess,
}
```

What A2 therefore builds for the row's "event stream with ring, heartbeat, `Resync`, coalesced
progress": the stream itself (server-sent events written from the backend's frames, the 15 s
heartbeat, `?after=` handed to the backend, a `Lagged` subscription ending the connection so the
UI reconnects and gets the replay or `Resync`, every stream ended at quit). The ring, `Resync` and
coalescing are tc-app's `EventBus` (A3 step 2); building a second ring in tc-server would be
deleted at the join (A3 D1 says so). The HTTP tests of replay and `Resync` use a scripted event
source until the join; the join adds an end-to-end test over tc-app's bus. Write this split into
the A2 row (step 9) with the reason: §4.1 gives the ring to tc-app, A2 and A3 run in parallel, and
a second ring would be thrown away.

Do not edit §4.1, §5.4's first bullet, §5.8 or the §10 order paragraph: A3's plan (step 10)
edits those, and two edits of one line would conflict.

### D4. `app.lock`: an OS lock, and the holder's pid in `app-lock.json` beside it

§5.1 says `tc4` "takes `app.lock` in app data and writes its pid into it", so a new `tc4` that
waits can name the old one. On Windows that cannot work: Rust's `File::lock`/`try_lock` locks the
whole file with `LockFileEx`, and Windows then refuses every other process's read of it
(`ERROR_LOCK_VIOLATION`); STORAGE's O1 says the same for `.tc/lock` ("unnamed when ... the platform
will not read a locked file"). The owner's laptops are Windows, so:

- `app.lock` is the lock only: opened read+write, `create(true)`, `truncate(false)` (clippy's
  `suspicious_open_options` wants it explicit), `File::try_lock()` (stable since 1.89; toolchain
  1.97). Never read, never renamed, never deleted: the OS releases it when the process ends, crash
  included.
- Right after taking it, the holder writes `app-lock.json` = `{"pid": <u32>, "at": <WallMs>}`
  with a write-temp-then-rename in app data (temp `app-lock.json.<pid>.tmp`, `sync_all`, rename,
  fsync the folder on Unix; tc-store's `atomic_write` is not on `phase0`, C1a replaces this
  helper). A failure to write it is logged and ignored: the record only names a process in a
  message.
- `TryLockError::WouldBlock` → poll every 100 ms for up to 10 s (AD39). Taken → go on. Still held
  → read `app-lock.json` (a missing or unreadable record means "unnamed"), print one JSON line on
  stdout, `{"error":{"type":"appLockHeld","value":{"pid":1234}}}` (`"pid":null` when unnamed), a
  sentence on stderr ("tc4: process 1234 still holds <app_data>/app.lock after 10 s; it may still
  be closing. End it, then start translationCore again."), and exit with code 3. Nothing else is
  on stdout before that line, so the shell (G1) reads the first line either way.
- Order at start: parse arguments → create app data → take `app.lock` (the wait) → bind → print
  the address line. A waiting `tc4` prints nothing and binds nothing.
- The Linux tests prove the logic; the Windows track's test run (`.audit/tasks/windows-track.md`)
  is where a locked file's unreadability shows. If it turns out readable there, the record still
  costs nothing.

`AppLock` lives in tc-server (`src/applock.rs`), not in tc4, so `cargo check -p tc-server
--target x86_64-pc-windows-msvc` checks it (tc4 pulls in tc-door43's TLS stack, which does not
cross-build here). Design text (step 8): §5.1's `app.lock` bullet, AD39's "(the lock records its
pid)", and §4.9's `app.lock` row say the pid is in `app-lock.json` beside the lock, because
Windows lets no other process read a locked file; add an `app-lock.json` row to §4.9's table.

### D5. Quit, closed stdin, and closing

`Server::run` waits for the first of: a stdin line that parses as `{"quit":true}` (a typed
`#[derive(Deserialize)] struct Control { quit: bool }`; any other line is logged and ignored),
stdin end-of-file or a read error, `backend.quitting()`, Ctrl+C (`tokio::signal::ctrl_c`) or, on
Unix, SIGTERM. Then, in order:

1. Set `closing`: every new request answers **503** with `Connection: close` (a save that
   arrives now keeps its text dirty in the UI; it is never half-run after the backend closed).
2. `tokio::time::timeout(limits.close_within /* 5 s */, backend.quit())`. The cap exists so a
   hung disk never keeps a dead shell's `tc4` alive holding `app.lock` and `.tc/lock`; what the
   store already wrote is durable, and the shell's close guard (G1) is what keeps unsaved aligner
   links from a quit. Log when the cap cut it.
3. End every event stream (a `tokio::sync::watch` the stream task selects on).
4. Wait up to `limits.drain_within` (1 s) for in-flight requests to finish (the event stream
   and uploads in progress are not waited for).
5. Unless the cause was a closed stdin, write `{"closed":true}\n` to stdout and flush (design:
   "answers `{"closed":true}` if stdin is still open"); ignore write errors (the shell may be
   gone; Rust ignores SIGPIPE, so a write fails instead of killing the process).
6. Return `Exit::{QuitMessage, StdinClosed, AppQuit, Signal}`.

`tc4` then calls `std::process::exit(0)`, with a comment: tokio reads stdin on a blocking-pool
thread that stays in `read()` while the shell keeps stdin open, and dropping the runtime would
wait for it forever. The stand-in did the same (`spikes/electronite/src/main.rs`).

Design text (step 7): §5.1's quit bullet gains "New requests get 503 while it closes; the
backend's quit work is cut after 5 s; Ctrl+C and SIGTERM quit the same way."

### D6. Test hooks: the feature, the flag, `test/crash` and ending the process

- Cargo feature `test-hooks` in tc-server (`= ["tc-api/test-hooks"]`) and in tc4
  (`= ["tc-server/test-hooks", "tc-api/test-hooks"]`); runtime flag `tc4 serve --test-hooks`,
  which exists only with the feature (without it: "unknown flag --test-hooks", exit 2). The test
  rows are routed only when the flag is given (`Server::with_test_hooks(self) -> Self`, cfg'd).
- **Feature unification trap**: tc-api's tests enable `tc-api/test-hooks` through a self
  dev-dependency, so in `cargo test --workspace` and `cargo clippy --workspace --all-targets`
  tc-api always has the `test` rows. Give tc-server and tc4 the same self dev-dependency
  (`tc-server = { path = ".", features = ["test-hooks"] }`; tc4 therefore needs a `lib` target,
  section 2), so all three agree in those builds. Every item used only by hooks must be
  `#[cfg(feature = "test-hooks")]`, or `cargo clippy -p tc-server -p tc4 --lib --bins` (no
  dev-dependencies, so no hooks: the release shape) fails on dead code. Add that line to
  `.github/workflows/ci.yml` (step 10), next to A3's `cargo clippy -p tc-app --lib` if it is there.
- **Ending the process.** tc-server: `pub const CRASH_EXIT_CODE: i32 = 86;` (the code A3's
  `ExitProcess` uses; keep them equal, and at the join make one use the other's) and

  ```rust
  #[cfg(feature = "test-hooks")]
  pub trait Ender: Send + Sync + 'static {
      /// A crash before the reply: ends the process now. Returns only in tests.
      fn end_now(&self, at: tc_api::test::CrashPoint);
      /// A crash after the reply: ends the process once the reply's body was handed to the socket.
      fn end_after_reply(&self);
  }
  pub struct ExitProcess;    // end_now: std::process::exit(CRASH_EXIT_CODE); end_after_reply: a std
                             // thread sleeps 100 ms, then exits (the body is flushed by then on loopback)
  pub struct RecordingEnder; // tests: records the calls, never exits
  ```

  `ServerConfig` carries `#[cfg(feature = "test-hooks")] pub ender: Arc<dyn Ender>` (default
  `ExitProcess`). For `Answer::Reply { then: Then::EndProcess }` the server wraps the body in
  `EndAfterBody { inner: Body, ender: Option<Arc<dyn Ender>> }`, which implements
  `http_body::Body` (via `axum::body::HttpBody`) by delegating `poll_frame`, `is_end_stream` and
  `size_hint`, and calls `end_after_reply()` **in `Drop`**. Trap: for a full body hyper never polls
  past the last data frame (it checks `is_end_stream()`), so a hook on `poll_frame` returning
  `None` never fires; hyper drops the body once it took the last frame or the connection died.
  `Answer::Ended` → 503 with `Connection: close` and no body (only a test ender gets there).
- **The Stub's crash points** (only until the join; tc-app's replace them, A3 D5): `test/crash
  { at, path }` arms one crash (replacing an armed one; a `path` that is not a command or job row
  of `tc_api::ALL` → `BadRequest { field: "path" }`). On the Stub's one write that succeeds,
  `app/clientError`, when the armed `path` is `None` or `"app/clientError"`: `BeforeStore` →
  `ender.end_now()` before logging; `BeforeReply` → `end_now()` after logging; `AfterReply` →
  `Then::EndProcess`; `DuringDraftWrite` is accepted and never reached. After `end_now` returns
  (only a `RecordingEnder` returns), the Stub answers `Answer::Ended`. An armed crash fires once.
  The arming hooks themselves never trigger a crash. These are A3's rules, so the process tests of
  step 8 keep passing after the join.
- **`release_has_no_test_hooks`** (AD35; A2 creates the feature, so A2 adds it):
  `crates/tc4/tests/release.rs`, `#[ignore]` with a doc comment saying it builds the release binary
  and how to run it (`cargo test -p tc4 --test release -j 2 -- --ignored`). It runs
  `env!("CARGO") build --release -p tc4 -j 2 --manifest-path <workspace>/Cargo.toml` (a plain
  build: no dev-dependencies, so no hooks), then asserts: `tc4 serve ... --test-hooks` exits 2
  with "unknown flag"; a `tc4 serve` without it answers `POST /api/v1/test/quiet` with 404; the
  binary's bytes contain neither `test/crash` nor `test/fieldStore`. Run it once in step 11 and

### D7. Uploads and downloads

- **Uploads** (§5.5, A-28). `POST /api/v1/uploads`, raw body, headers `X-Tc-Upload-Name` (the
  file name, UTF-8, percent-encoded) and `X-Tc-Upload-Flow` (`exchange`, `import`, `usfm`,
  `guidedFix`: `tc_api::upload::UploadFlow`, camelCase). Caps from `UploadFlow::cap()`: exchange
  4 GiB (4 × 1024³), every other flow 512 MiB (512 × 1024²); a size equal to the cap is allowed.
  - A `Content-Length` over the cap → **413** at once, `Connection: close`, nothing read, nothing
    written.
  - Otherwise stream `Body::into_data_stream()` into `<app_data>/uploads/<id>.part` through a
    `tokio::io::BufWriter` of 1 MiB around `tokio::fs::File`, counting bytes; past the cap (a
    chunked body) → stop, delete the `.part`, 413. A body error (the client went away) → delete
    the `.part`, no entry. Complete → flush, close, rename to `uploads/<id>`, register
    `Upload { id, name, size, flow, path }`, answer `Reply::Ok(UploadView { id, name, size })`.
  - A write error (disk full) → delete the `.part`, answer
    `Reply::Err(ApiError::Refused(Refusal::Upload(UploadRefusal::NotWritten { reason })))`.
  - Missing or bad headers → `Reply::Err(ApiError::BadRequest { field: "X-Tc-Upload-Name" | "X-Tc-Upload-Flow", reason })`.
    A name must decode as UTF-8, be 1 to 255 bytes and hold no control character. **The name is
    never a path**: the file is `uploads/<32 hex>` only.
  - No fsync: `uploads/` is emptied at every start (§4.9), so a crash never reads a partial
    upload back, and an fsync of 4 GiB would cost seconds. Say so in a comment.
  - The id: 16 bytes from `getrandom::fill`, lowercase hex, `UploadId::parse`.
  - The route keeps `DefaultBodyLimit::disable()`; every other route reads through the API cap
    (D8).
  - `ServerHandle::uploads() -> &Uploads` with `get(&UploadId) -> Option<Upload>` and
    `take(&UploadId) -> Option<Upload>` (the caller then owns and deletes the file). Later flows
    (F1, E2, B4b's USFM) reach it through the join adapter; nothing in A2 calls it but the tests.
- **Downloads registry** (§5.5). `Downloads { dir, keep: 10 min, entries }` with
  `dir() -> &Path` (a producer writes its file there first, so `add` is a rename on one volume),
  `add(written: &Path, file_name: &str, content_type: &'static str) -> Result<DownloadId,
  DownloadError>` (validates the name like an upload's and refuses `/`, `\`; renames the file to
  `downloads/<id>`), `sweep(now: tokio::time::Instant)` (deletes entries and files older than
  `keep`; a task calls it every 60 s). `GET /download/{id}/{name}`: the id must parse and be
  registered and `name` must equal the registered name, else 404; answer the file streamed in
  256 KiB chunks (`futures_util::stream::unfold` over a `tokio::fs::File`; no tokio-util in the
  lock), `Content-Type`, `Content-Length`, `Content-Disposition: attachment; filename="<ASCII
  fallback>"; filename*=UTF-8''<percent-encoded>`, `Cache-Control: no-store`. A file stays 10
  minutes and may be fetched more than once in that time.
- At `Server::bind`, `remove_dir_all` then `create_dir_all` exactly `<app_data>/uploads` and
  `<app_data>/downloads` (std's `remove_dir_all` does not follow symlinks). A failure to empty
  is logged, never fatal: the registries only serve ids of this run.
- `/media/obs/...` (B7) and `/print/{job}` (D2) are not routed in A2; their units add them. They
  answer 404 behind the security layer until then.
- Design text (step 6): §5.5's uploads bullet names the two headers, the flows, `.part` then
  rename, no fsync and why, and `UploadRefusal::NotWritten`.

### D8. An API request body is capped at 8 MiB

§3.2 says "a request is bounded where the server reads its body (A2)". The largest phase-0 bodies
are a few KB; the largest designed ones (`session/open { buffered }`, `editor/saveSection` for
Psalm 119) are well under 1 MiB. Read with `axum::body::to_bytes(body, limits.api_body)`; a
`Content-Length` over the cap or a body that grows past it → **413**. axum's own
`DefaultBodyLimit` (2 MB for its extractors) does not apply because the handler reads the body
itself; still, set `DefaultBodyLimit::disable()` on the API route so the two never disagree.
Design text (step 4): §3.2's sentence gains "(8 MiB; 413 above it)" and AD9's status list gains
503 (closing) beside 401, 403, 409 and 413.

### D9. The loopback spike

What it measures (§8.3, AD18, A-14): the round trip of one aligner-sized request from a wasm
`fetch` in Chromium to `tc4 serve` over loopback and back to a parsed reply in wasm, p95, twice:
**plain** (the page's own `fetch` sets `X-Tc-Token`, as the UI does under AD11) and **through a
header-adding proxy** (the page sets no token; a request interceptor adds `X-Tc-Token` to every
request, `/api/` included: the cost if the shell's filter could not leave `/api/` out).

- **The endpoint**: a new test row `query "test/echo": $crate::test::Echo => $crate::test::EchoView;`

`run` converts the listener (`set_nonblocking(true)`, `tokio::net::TcpListener::from_std`) and
serves with `axum::serve(listener.tap_io(|tcp| { let _ = tcp.set_nodelay(true); }),
router.into_make_service())` (`axum::serve::ListenerExt`, present in 0.8.9). **`TCP_NODELAY`
matters**: Nagle plus delayed ACK can add 40 ms to a small request-reply on loopback, which would
swallow the aligner's 30 ms budget.

`security.rs` (`axum::middleware::from_fn_with_state`), in this order (§5.2):

1. `Host` equals `127.0.0.1:PORT` byte for byte, else 403 (no `Host` → 403).
2. Debug builds only (`#[cfg(debug_assertions)]`, so release has no code for it): `GET /` with a
   `dev-token` query equal to the token (constant time) → 303 to `/#t=<token>` with
   `Set-Cookie: tc4_token=<token>; HttpOnly; SameSite=Strict; Path=/`. A wrong `dev-token` falls
   through to step 3.
3. The token (D11), or in debug builds the `tc4_token` cookie, else 401. Every route, static files
   and unknown paths included.
4. Any method other than GET: `Origin` equals `http://127.0.0.1:PORT`, else 403 (`Origin: null`
   too). HEAD is not GET: it needs `Origin` (the design's literal rule; no client sends HEAD).
5. Path starts with `/api/`: `X-Tc-Api` equals `1`, else 409 with the JSON body
   `Reply::<()>::Err(ApiError::Version { server: API_VERSION })`.
6. Never an `Access-Control-*` header.

Every response also gets `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`.
401 and 403 bodies are short plain text with `Cache-Control: no-store`. **Trap:** axum's
`Router::layer` wraps only routes (and a fallback) added before it, so set `.fallback(not_found)`
before the layers, or an unknown path without a token answers 404 instead of 401. Layer order:
the closing gate and in-flight count innermost, the security guard outermost (added last).
**Never log a URI with its query** (it can hold `dev-token`), a header value, or the token.

### Step 5. tc-server: the event stream

`events.rs`, `GET /api/v1/events` (`Query<EventsQuery { after: Option<u64> }>`; a bad `after`
is axum's 400). Response headers `Content-Type: text/event-stream`, `Cache-Control: no-store`,
body `Body::from_stream(futures_util::stream::unfold(state, step))` where the state holds the
backend's `B::Events`, a `tokio::time::interval_at(now + heartbeat, heartbeat)` with
`MissedTickBehavior::Delay`, the server's closing `watch::Receiver`, and a `started` flag. Each
step:

- first: yield `": tc4\n\n"` (so the client's `fetch` resolves at once and the stream is seen as
  open);
- then `tokio::select!` (all three are cancel-safe): `events.next()` → `Frame(f)` → yield
  `format!("id: {}\ndata: {}\n\n", f.seq, serde_json::to_string(&f)?)` (serde_json never writes a
  raw newline, so one `data:` line holds the frame); `Lagged` or `Closed` → end the stream (the
  UI reconnects with its last seq: the backend replays or sends `Resync`); heartbeat tick → yield
  `":\n\n"`; closing → end.
- The request is not counted in flight (D5 step 4 waits for none).

Tests, `tests/events.rs`, with a `Scripted` backend whose `subscribe(after)` records `after` and
returns a source that yields a scripted list, then frames the test pushes through an
`mpsc::UnboundedSender<Next>`:

- `frames_are_written_as_server_sent_events`: three frames → three `id:`/`data:` blocks, in
  order; each `data` parses as the `EventFrame` that was yielded (seq, instance, event).
- `after_is_handed_to_the_backend`: `?after=7` → `subscribe(7)`; no query → `subscribe(0)`.
- **`replay_then_live_reaches_the_reader_in_order`**: the source replays seqs 5–7, then live 8,
  9 are pushed → the reader gets 5, 6, 7, 8, 9.
- **`a_resync_frame_reaches_the_reader`**: the source's first frame is `Event::Resync` at the
  newest seq (what tc-app's bus sends for a gap) → the reader gets it first, then live frames.
- **`a_lagging_subscription_ends_the_stream_and_a_reconnect_resumes`**: push `Lagged` → the
  stream ends (the chunked body terminates); reconnecting with `after=<last seq read>` calls
  `subscribe(<that seq>)`.
- `the_stream_starts_with_a_comment_and_heartbeats_while_idle`: `heartbeat = 100 ms`; nothing

## 4. Invariants (the verifiers will attack these)

1. **A quit never skips the backend's quit work** (aligner links and checkpoints, later), except
   a test crash and the 5 s cap; a closed stdin is a quit, not a crash.
2. **No request is half-run after closing began**: new requests get 503 before they reach the
   backend, so the UI keeps their text dirty.
3. **A second `tc4` never serves beside the first**: it binds and prints nothing until it holds
   `app.lock`, and a held lock names the holder after 10 s instead of guessing.
4. **No frame is dropped silently by the server**: it writes every frame the backend yields, in
   order; a lagging subscription ends the stream so the UI reconnects (replay or `Resync`), never
   a skipped frame on a stream that stays open.
5. **A partial upload is never complete**: it is registered only after its last byte is written
   and renamed; a cap, a cut connection or a disk error deletes the `.part`; the person's name
   for the file is never a path.
6. **A body over a cap is refused whole** (413), never truncated and passed on.
7. **The token is never logged**, nor a query that may hold it; the address line is the only
   place it is printed.
8. **No test hook exists in a release build**: no `--test-hooks` flag, no `test/` route, no
   `EndProcess` path (`release_has_no_test_hooks`).
9. **Every endpoint of `tc_api::ALL` reaches the backend, each once; nothing else does.**
10. **Help pages never redirect; no directory is served.**

## 6. Traps found while planning

1. **Windows cannot read a locked file** (std's `try_lock` locks the whole range): the holder's
   pid goes in `app-lock.json` (D4).
2. **Feature unification**: tc-api's self dev-dependency turns its `test-hooks` on in every test
   and `--all-targets` build. tc-server and tc4 get the same self dev-dependency; hook-only items
   are cfg'd; `cargo clippy -p tc-server -p tc4 --lib --bins` is the release-shaped lint (D6).
3. **`Router::layer` skips a fallback added later**: set the fallback first, or unknown paths
   skip the token check (step 3).
4. **hyper does not poll a full body to `None`**: end the process from the body wrapper's `Drop`
   (D6).
5. **tokio's stdin reader thread blocks in `read()`**: exit with `std::process::exit`, never by
   dropping the runtime (D5). Any harness that starts `tc4` must keep its stdin open (a closed
   stdin is a quit): the spike driver and A6b's `env-rust.mjs` spawn it with a piped stdin.
6. **Nagle on loopback**: set `TCP_NODELAY` on every accepted socket (step 3).
7. **The CSP blocks inline scripts on index.html**: the spike page and A4a's `index.html` load
   their scripts from `/ui/` (D9).
8. **Playwright's `route.request().headers()` can miss `Origin`**: use `allHeaders()` (D9).
9. **Playwright 1.61.1 (tC4's) needs a Chromium that is not installed**: use
   `parity/ds-gallery/node_modules/playwright` (1.56.1, Chromium 141) from the main checkout,
   read only (D9).
10. **`HTTPS_PROXY` is set in this container**: no `reqwest` client against loopback in tests.
11. **axum's extractors cap bodies at 2 MB** (`DefaultBodyLimit`): read bodies yourself and disable
    it on the API and upload routes (D7, D8).
12. **tower-http's `ServeDir` redirects directories**: do not use it for `/help/` (step 3).
13. **`endpoint_table!` resolves the callback at the call site**: define the callback macro above
    the invocation in the same module (step 4).
14. **Two edits of one design line conflict at merge**: leave §4.1, §5.4's first bullet, §5.8

## 7. Notes for the join (A3 step 11, or step 12 here)

The adapter lives in tc4 (tc-server and tc-app never depend on each other; the orphan rule allows
a tc4 newtype):

```rust
struct AppBackend(tc_app::App);
struct AppEvents(tc_app::Subscription);
impl tc_server::EventSource for AppEvents {
    async fn next(&mut self) -> tc_server::Next {
        match self.0.next().await {
            tc_app::Next::Frame(f) => tc_server::Next::Frame(f),
            tc_app::Next::Lagged => tc_server::Next::Lagged,
            tc_app::Next::Closed => tc_server::Next::Closed,
        }
    }
}
impl tc_server::Backend for AppBackend {
    type Events = AppEvents;
    async fn call(&self, path: &'static str, body: Bytes) -> tc_server::Answer { /* map tc_app::Answer and Then one to one */ }
    fn subscribe(&self, after: u64) -> AppEvents { AppEvents(self.0.events().subscribe(after)) }
    async fn quit(&self) { self.0.quit().await }
    async fn quitting(&self) { self.0.quitting().await }
}
```

`tc4 serve` then builds `AppConfig` from its flags (`build: BuildInfo { version: BUILD_VERSION,
commit: BUILD_COMMIT }`), starts the `App` inside the runtime after `bind`, and runs
`AppBackend` instead of the `Stub`. Make `CRASH_EXIT_CODE` one constant. tc-app must answer
`test/echo` (`Ok(EchoView::of_size(req.size))`, `BadRequest` above `MAX_ECHO`). Later units reach
uploads and downloads through traits tc-app declares and this adapter implements with
`ServerHandle::uploads()` and `downloads()`.
