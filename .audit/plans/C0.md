```rust
pub use tc_store::{Refusal as RuleRefusal, StoreCounters, StoreNotice};

/// Who asked for a command (AD37): the `Committed` event of its batch names this, so the
/// `Changed` frame of a person's own save names their request.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Origin { Request(tc_api::ids::RequestId), Server }

pub struct StoreCommand {
    command: Command,
    shown: Vec<(RecordKey, Vec<ChangeId>)>,
    origin: Origin,                       // Origin::Server unless `requested_by` says otherwise
}
impl StoreCommand {
    pub fn save_verse(shown: EditToken, words: String) -> Self;                       // exists
    pub fn resolve(conflict: ConflictId, shown: Vec<ReviewToken>, choice: Choice) -> Self; // exists
    /// `SaveSection` (STORAGE §5.2): one edit token per verse and chapter front the editor
    /// displayed, `None` for one displayed and unchanged; the book's layout token if it has one.
    pub fn save_section(book: BookId, shown: Vec<(EditToken, Option<SectionValue>)>,
                        layout: Option<EditToken>) -> Self;
    /// `Draft` (STORAGE §5.14): kept beside the actor (R22), writes no change.
    pub fn draft(field: DraftField, shown: Vec<EditToken>, text: String) -> Self;
    /// The UI request this command answers.
    pub fn requested_by(self, request: tc_api::ids::RequestId) -> Self;
    pub fn origin(&self) -> &Origin;
    pub(in crate::backend) fn shown(&self) -> &[(RecordKey, Vec<ChangeId>)]; // drop the cfg
    pub(in crate::backend) fn journal(&self) -> &Command;                       // drop the cfg
    pub(in crate::backend) fn into_parts(self) -> (Command, Origin);
}
```

The handle:

```rust
struct StoreHandle {
    /// `None` once `close` took it.
    inner: RwLock<Option<tc_store::ProjectHandle>>,
    /// The snapshot `snapshot()` answers after close (a session never reads then; a stray read
    /// gets the last state, never a panic).
    last: OnceLock<Snapshot>,
    /// Sends each submitted command's reply to the relay, in the order the actor takes them.
    relay: Mutex<Option<std::sync::mpsc::Sender<Job>>>,
    origins: Arc<Origins>,
    subscribers: Arc<Mutex<Subscribers>>,
}
struct Job { pending: tc_store::Pending<Result<tc_store::StoreReply, tc_store::CommandError>>,
             origin: Origin, reply: tokio::sync::oneshot::Sender<Result<StoreReply, CommandError>> }
struct Origins { state: Mutex<OriginState>, changed: Condvar }
struct OriginState { by_change: HashMap<ChangeId, Origin>, relay_gone: bool }
struct Subscribers { senders: Vec<UnboundedSender<StoreEvent>>, ended: bool }
struct StoreSnapshot(tc_store::Snapshot);   // impl Published: fold, seq, token, review_token
```

Methods:
- `facts()`: tc-store's facts with `session_mode`; after close, the facts taken at close.
- `snapshot()`: `Snapshot::new(StoreSnapshot(h.snapshot()))` under the read lock; after close,
  `last`. One small allocation per call; the bench measures it (M1).
- `parse_edit(token)`: `h.parse_edit(token.body())` then `EditToken::from_journal`; after close,
  `Err(TokenError::Malformed("the project is closed".into()))`. `parse_review` the same.
- `submit(command)`:
  1. `let (command, origin) = command.into_parts();`
  2. Under `relay`'s lock (so the relay's order is the actor's order): `let pending =
     h.submit(command);` (no handle → `Err(Closed)` at once).
  3. If `pending.is_ready()` (a draft, which tc-store answers at once beside the actor, R22; or
     a closed actor): settle it inline (below) and return a ready future. A draft must never wait
     in the relay behind a long command.
  4. Else hand `Job { pending, origin, reply: tx }` to the relay and return
     `Box::pin(async move { rx.await.unwrap_or(Err(CommandError::Closed)) })`.
- `settle(result, origin, origins)` (shared by the relay and the inline path): map the reply
  (tokens through `EditToken::from_journal`, keeping `stored`, `seq`, `changes`, `new_conflicts`,
  `skipped`) or the error (`command_error`); when the reply is `Ok` with changes, record
  `changes[0] → origin` in `origins` and notify. A reply token that is not of the edit kind is a
  store bug: leave that token out and keep the reply `Ok` (`debug_assert!`); a stored write must
  never come back as a refusal (trap 6).
- The **relay** thread (`"tc-app store relay"`): `for job in jobs { let r = job.pending.wait();
  let mapped = settle(r, job.origin, &origins); let _ = job.reply.send(mapped); }`, then
  `relay_gone = true` and notify. It needs no tokio runtime, and it records the origin whether
  or not anyone still awaits the reply (an HTTP caller that went away).
- The **forwarder** thread (`"tc-app store events"`): `while let Ok(event) = rx.recv()`:
  - `Committed { seq, delta, changes }` with `changes` empty → `StoreCause::System` (S1's only
    such step is a second writer's fold, which also sends a `Notice` and a `Mode`; the pump names
    each record's writer from the snapshot anyway);
  - with `changes` → wait on `origins.changed` until `by_change` holds `changes[0]` (take it) or
    `relay_gone` (then `Origin::Server`) → `StoreCause::Command { origin }`. This wait is
    bounded by the actor: it emits the event, then resolves that same reply, and every earlier
    reply is already resolved (one actor, in order). No timeout.
  - `Notice(n)` → `Notice(n)`; `Mode(m)` → `Mode(session_mode(&m))`; `Materialized { paths }` →
    the same.
  - Send to every live subscriber (`retain(|tx| tx.send(e.clone()).is_ok())`).
  On exit (tc-store's sender is gone: its actor stopped and its handle dropped): `ended = true`,
  clear the senders, so every pump's channel ends ("The channel ends when the handle closes").
- `subscribe()`: a new unbounded channel; if `ended`, return a receiver whose sender is already
  dropped.
- `checkpoint(reason)`: map `CheckpointReason::{LeavingProject, Other}` to tc-store's; return
  `Box::pin(async move { match pending.await { Ok(()) => CheckpointOutcome::Unchanged,
  Err(e) => Failed { reason: e.to_string() } } })`. tc-store's `Pending` is a `Future`, so no
  thread blocks. `Unchanged` because S1 makes no commit (S2's; the outcome then says whether it
  did); the UI shows only `Failed` ("Checkpoint not saved"), so nothing visible depends on it.
  After close: `Failed { reason: "the project is closed" }`.
- `close(self: Arc<Self>)`: take `inner` (write lock), store `last` and the facts, drop the relay
  sender (the relay drains the jobs already queued: the actor answers each command queued before
  `Close`), then run `h.close()` on a std thread (`"tc-app store close"`: it waits for the open's
  background work, a checkpoint and the actor's join; up to 3 s on a whole Bible, PERF) and
  return a future over a oneshot (`StoreError::Other(e.to_string())` on error). A second close is
  `Ok(())`. If the thread cannot start, close inline and say why in a comment.
- `Drop for StoreHandle`: if `inner` is still `Some`, move it to a std thread to drop:
  tc-store's own `Drop` sends `Close` and joins the actor (handle.rs:752-763), which must never
  block a tokio worker (trap 4).
- `counters()`: `h.counters()`; after close, the counters taken at close.
- `offered_drafts()`: tc-store's list mapped to the seam's `OfferedDraft`.
- `wait_idle()` (test-hooks): `h.wait_idle()`.

`StoreBackend::reset` (test-hooks): `Ok(())`, with a comment: projects on disk have no seed to
go back to; C1a's scenario store writes its projects again there.

Do not call, anywhere in tc-app: `tc_store::ProjectHandle::{mint, mint_review}` (they mint from

```rust
        self.hooks()?;

            .map_err(|_| ApiError::NotSaved(NotSaved::StaleScope))?;

                Err(unworded) => self.internal("the store refused a save no screen words yet",

            }),
        }
    }
}
```

## 7. Traps

1. **`AddBook` seeds stubs.** tc-store's `AddBook` builds tC4's blank book (`___` in every verse,
   seed.rs); the fixture's text must come from `NewProject.records`
   (`BookPresence` + `records_from_usfm`), or `chapter_view_equals_seed_usfm` compares stubs.
2. **`Store::list` lists staging folders.** A create writes `project.json` into
   `.staging-create-<hex>/` before the rename (store.rs:320-340), and `list` only checks that the
   file exists. Leave out the `.staging-` prefix in `list` and refuse it in `open`, or Home could
   show a half-made project and an open could take its lock while the create still writes it.
3. **Fold counters are shared.** `FoldState` clones share one `Arc<CounterCells>`
   (fold/state.rs:488), so the actor's work after an open (O14's storage check, a materialize
   3 s after a batch) counts into every snapshot's counters. `wait_idle` before any counted
   section; C1a's count rows on the store meet the same.
4. **tc-store's `close(self)` and `Drop` block.** Both wait for background work, a checkpoint and
   the actor's join. Never on a tokio worker: `close` runs on its own thread; `Drop` hands the
   handle to a thread.
5. **The event comes before the reply.** `Project::commit` emits `Committed` and only then does
   the actor resolve the reply; the forwarder must wait for the relay to record the origin, and
   the relay must record it whether or not anyone awaits the reply. A draft is answered at once
   by tc-store (beside the actor, R22) and must never queue behind a long command in the relay.
6. **A stored write never comes back as an error.** Map a reply token that fails
   `EditToken::from_journal` by leaving it out, not by failing the reply: a "not saved" for a
   write that is on disk makes the person retry with the old token and conflict with their own
   save.
7. **`Stored::Unchanged` carries no token from tc-store** (project.rs:214-223). `wire::write::ack`
   must echo the request's token and the displayed words, or the field never becomes clean and
   its next save is made from a stale base.
8. **A verse save can write two changes** (the verse and its reflowed alignment, R25, Q-6).
   `Ack.tokens` returns both; `saved` holds only the verse's words, read by the change whose key
   is the verse's.

## 8. Invariants that protect a translator's work (check each before your last commit)

- A write's reply says exactly what the disk holds: `Durable` only after tc-store's B3, never a
  refusal for a stored write, never "saved" for a refused one (traps 6, 7; the crash test).
- Every command submitted gets exactly one reply, and every batch it stores reaches the seam as
  one `Committed` with its origin (property test, `every_fold_step_reaches_the_seam`).
- A token is minted only from the snapshot a screen read; nothing in tc-app calls tc-store's
  `ProjectHandle::mint` (B1b's I4 fix; optional lint in step 2).
- No folder that holds a project is hidden from `list`; an unusable one is listed with its reason.
- A read-only project writes nothing, and every command on it is refused with its reason.
- A draft is never delayed behind a long command, and an unverifiable draft's text is offered,
  never dropped.
- Closing keeps every save and lets go of the lock; nothing blocks a tokio worker on the actor.
- Every project a test writes validates as a Scripture Burrito.
