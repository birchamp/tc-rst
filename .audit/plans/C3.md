## Tokenless comment recovery (AD4)

A first Add may commit before its Ack reaches the browser or shell mirror. The buffered
comment then still has no base token. Recovery compares its text with every current head
on its exact typed verse/frame target, using that book/story's comment index. Equal text
is already stored and settles, so Keep cannot duplicate that saved text.

Different newer text remains an explicit Keep/new-comment offer, preserving all existing
notes. It is never rebased onto the newest comment or a comment selected by timestamp,
author or matching sent text. The durable journal has no RequestId/server-run provenance,
and the backend's request-origin map does not survive restart, so those heuristics cannot
prove which CommentId the interrupted Add minted. A signed minted token in the buffer is
proof and follows the existing revision recovery path. No persistent request-ID design or
storage-format change is introduced by this unit.

The focused real-store regressions cover committed Add/crash-before-Ack equality, newer
unsaved text, and an independent same-target note. Final outcomes belong in the root's
verification handoff after the tests run.

## Bounded verification findings

Three lenses covered storage/protocol recovery, the mounted UI and production glue, and
the generated real-store save histories. Keep the existing generators and strict scale
counters. Fix concrete translator-data or user-facing failures without another broad review.

- Closing a clean newly added comment used to discard the minted identity. A stale read
  on remount could then add a second comment. An O(1) map of closed comment pairs keeps the
  proven identity outside active fields; newer view pairs supersede it, and closing the
  project or restarting drops that open's map. Inactive comments do not enter timer/gate scans.
- Browser proof found that OBS Save/blur removed the card and editing lock before Ack.
  A requested close now waits for a clean Ack; a refused save retains its card and text for
  correction/Retry. Only an explicit close being saved disables the field; idle autosaves
  preserve typing.
- The generated empty-reference case reached the existing OBS text validation rule, but
  its refusal was sent as `Internal`. `SaveRefusal::InvalidText` now carries the rule's
  reason as a typed refusal, and the UI renders it as escaped text. The generated input
  remains covered: it must preserve the unsaved text and old journal until corrected.

The initial browser run passed 25/27 journeys: all four new comment journeys, J21's frame/
title/reference byte proof, and the existing OBS/Understand read journeys. Its two failing
OBS lock/refusal cases exposed the mounted-card issue above; unchanged assertions await
the focused rerun, plus a production empty-reference/correction journey. Final gate and
capture results are under "Final proof".

## Finishing (2026-10-20)

- **The held-frame journey (user harm, fixed).** The 7/8 run predated the rail half of the
  OBS editing lock: during a held save the story rows and frame buttons stayed on, so the
  person could leave a card whose save had not answered. `story_rail` now turns them off
  while a card is open, with tC4's pointer-down capture and `cursor: default` (#698). The
  test was right. The uncommitted tree also referred to the private `tc_obs::error`
  module; it now uses the re-exported `tc_obs::TextProblem`.
- **Story text in tC4's stored form (major, user harm, fixed).** tC4 runs
  `normalizeStoryUnit` before each write and on blur (`src/data/storyScheduler.ts:16-22`,
  `src/state.jsx:6930-6941`). Without it a frame typed with a blank line or a final
  newline, or a title with a space after it, was refused, by the 2 s pause too, and the
  standing failure kept the person on the screen until Retry. `tc_api::story::stored_text`
  is that function: the server applies it before every `story/saveFrame`, `story/saveRef`
  and Keep of a story draft, and the card applies it on Save and blur, so the field settles
  on the stored text and closes. Native proof:
  `drafts::story_texts_are_saved_and_kept_in_the_form_tc4_stores` (fails without the
  server step); browser proof:
  `a_blank_line_in_a_frame_and_spaces_around_a_title_save_in_their_stored_form`.
- **Blur after the card closed (blocker, user harm, fixed before commit).** The first
  version read the editor's node on the blur that a closing card fires after it is gone,
  which panicked the page. The blur now takes its text from the event.
- **Declared difference.** An emptied reference line, or a frame line in the picture,
  title or reference form, is refused with its reason while the card keeps the text; tC4
  silently restores an emptied reference and shows only "Save failed — retry" for the
  others (`docs/PLAN.md`, unit C3). The owner is told.
- **app-language e.** tC4's comment half is in `app_language_e_a_verse_typed_before_the_switch_survives_it`:
  a verse comment blurred before the switch shows in Understand in Spanish and is stored.
- **Captures.** `understand-tit1`, `en-understand-tit1`, `en-understand-tw-article`,
  `en-understand-questions`, `obs-understand` and `en-obs-understand` are tC4's pixel for
  pixel and DOM line for line with writable boxes, so their read-only residuals are retired.
  `obs-translate` and `en-obs-translate` differ only by their existing picture-pack residual.
- **Minors** (`.audit/minors.tsv`): a story refusal's reason is English in a translated
  interface (user, rare); the generated save histories type no white space into story
  fields (internal).
