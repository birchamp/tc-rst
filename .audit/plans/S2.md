### 0.3 Decisions this plan takes (follow them; each is justified in its step)

- **D1. One writer thread per open project** (`crate::writer`), owner of everything about
  derived and carried files: the manifest, holds, busy paths, `.tc/external/` copies, heads
  files, the materialize intent, `metadata.json`, git objects (blobs, trees, commit objects),
  `refs/tc/carried`. The actor keeps the fold, the journal files (pending, packs), the seal,
  device and seq, commits, and the branch reference update (R21: "only the seal and the
  final reference update are actor steps").
- **D2. Message passing only.** The writer never blocks waiting for the actor, and the actor
  never blocks on the writer except inside `close`, where it keeps draining its own channel
  until the writer says it has stopped. This is what prevents a deadlock between the
  outside-edit recording (writer asks actor) and a closing actor (actor waits for writer).
- **D3. Git through a real directory beside every `Vfs`.** Add
  `Vfs::outside_dir(&self, folder) -> io::Result<PathBuf>`: `StdFs` returns the folder itself;
  `FaultFs` keeps a real temporary mirror directory per model and returns
  `<mirror>/<folder path>`. libgit2 always runs on a real `.git`, so every existing `FaultFs`
  test also exercises real git, and one implementation serves production and tests. Git is
  outside the `Vfs` (as §16.2 says): kill points never stop a git call; git crash rows use
  hook fail points instead.
- **D4. Commit objects are written raw** with `Odb::write(ObjectType::Commit, …)`, because
  libgit2's `git_signature_new` refuses an empty email (`signature.c:93`, "Signature cannot
  have an empty name or email") and §5.13 requires an empty email (D85).
- **D5. Commit trees are built from HEAD's tree with `git2::build::TreeUpdateBuilder`**
  (`create_updated` writes only changed subtrees), from the manifest's blob ids for files the
  last materialization made equal to the snapshot's projection; only held, blocked or stale
  paths are rendered from the snapshot.
- **D6. The outside-edit diff is a pure function in `tc-journal`** (`outside.rs`,
  `FoldState::plan_outside_edit`). `tc-store` only reads bytes, copies them, and commits the
  plan.
- **D7. Recording an outside edit "accepts" the bytes.** After the batch is durable (or
  after the planner found nothing to record, or found the file undecodable), the manifest entry
  takes `md5 = d` (unsettled, scope cleared), the copy stays in `.tc/external/`, and the path is
  rewritten from the fold (X6). This is what lets the compare-and-swap overwrite bytes that are
  now safely recorded, and it makes re-examination after a crash idempotent.
- **D8. A file a scanner holds (WIN hazard 2), step 1d.** (a) Every rename and every removal
  of a project file goes through `atomic::rename_held` / `remove_held` /
  `remove_dir_all_held` / `rename_dir_noreplace_held`, which retry while
  `Vfs::is_held(&err)` with a bounded back-off. `StdFs::is_held` is true on Windows for raw
  OS errors 5, 32 and 33; `FaultFs` returns errors carrying a `HeldByAnotherProgram` payload
  that its `is_held` recognizes, so the retry is tested on Linux. The wait goes through
  `Vfs::wait_held(Duration)` (`StdFs` sleeps; `FaultFs` records the wait and does not sleep).
  (b) A save whose temp file stays behind after `NotWritten` is never rolled forward into a
  seq another save already used: O2 no longer renames a complete pending temp at once; it is
  decided after O8 by the fold's `(device, seq)` index (`FoldState::change_at`). A temp whose
  seq a durable change already holds is the person's failed attempt: it is moved, never
  deleted, to `.tc/external/` with `Notice::UnsavedAttemptKept`. Of several colliding temps
  only the newest is rolled forward. A temp nothing collides with is rolled forward as
  today (the Windows lazy-rename case, "Saved" was shown). A complete temp that cannot be
  placed, or a temp that cannot be read, is never removed: it counts as an unreadable pending
  file (§6.3, `PendingUnreadable` rotation). The seq counter rule of §5.0 stays ("does not
  advance on `NotWritten`"): it is what makes the collision visible to the next open.
- **D9. §7.4 is a warning, never a gate (WIN "Open"), step 1c.** `incomplete_history` keeps
  its meaning and every choice of the conflict's kind stays offered; *Apply what was
  recovered* is listed first when the missing parent is in a held batch. Code: the presence
  conflict of a restore race is also marked when a *Start empty* verse head (a `StartOver`
  change of a race batch that is still a verse head) continues a missing change; its
  `batches` include the batches of the race verse heads it lists; the property counts only
  heads (candidates, `also`, unreadable heads), never unreadable bases.
- **D10. Outside edits cost what they changed (§11.1, the task's count clause).** Each heads
  file (`.tc/heads/<escaped>.bin`) gains, per record, a 16-byte digest of how the written file
  shows that record (`ShownDigest`: md5 of the record's entry in the file, normalized: CRLF
  and CR to LF, spaces and tabs before a line end removed). The renderer computes it from the
  pieces it writes; the decoder computes it from the pieces it reads, with the same function.
  The planner sends a key down the full rules only when its digest differs, it is new, or it
  is gone. A heads file without digests (S1's format) or an unknown base falls back to the
  slower comparison with the book's projection.

`decode_file` fills `Decoded::digests` with `shown_digest` over the pieces it reads (USFM:
`codec::decompose`'s header, chapter fronts and verse parts; sidecars: each parsed entry
re-serialized with `to_canonical_json`), one decode of the file and nothing from the fold.
The property of 1a.2 ties these digests to the renderer's.

Rules, in this order. Each rule has a unit test in `tests/outside.rs` named after it.

1. **Key universe.** Keys of `decoded.records` ∪ keys of `base`. For a USFM file the base keys
   are the book's `BookHeader`, `ChapterFront`, `Verse`, `BookLayout`; a verse in the base but
   not in the file is found as `Absent { moved_to: None }`, a chapter front as
   `ChapterFront::Absent`. For JSON files a record in the base and not in the file is a
   *removal*.
2. **Prefilter (cost follows the change, D10).** A key whose decoded digest equals its base
   record's `shown` digest shows what the app wrote: it is not changed, whatever its current
   heads, and no value of it is read. Only keys with a different digest, keys new in the file
   and base keys gone from the file go through rules 3 to 11. A base without digests
   (`shown: None` for every record, or `Base::Unknown`) falls back to comparing each decoded
   record with `projected(key)` (USFM: with `book_parts(book)`, one pass over the projected
   book): it costs the book, only in those rare cases. `keys_examined` counts the keys that
   went through rules 3 to 11. (`reconciling_an_outside_edit_costs_what_it_changed`.)
3. **written(k)** = `shown_value(k, base heads)`. `Unreadable` or `Conflicting` → this key is
   planned unknown-base. A key with no base heads has written = nothing.
4. **Whitespace.** For text values (`Verse` words and layout, `BookHeader`, `ChapterFront`,
   story parts, comment text) compare with CRLF and CR turned into LF and spaces and tabs at
   line ends removed (`normalize_ws`, the same function the digests use). Equal → not
   changed; count it in `whitespace_only`. Keys the digest prefilter already skipped are not
   counted, so the store says `WhitespaceOnlyEdit` whenever the file's bytes differ from the
   manifest's and the plan records nothing.
5. **CRLF back.** For a changed text value: if written has `\r\n` and found has no `\r`,
   found gets `\r\n` for every `\n` (X3).
6. **Values the file cannot carry.** A `Verse::Text` found where written is `Text` keeps
   written's `from` (USFM has no place for it, §2.3); `Versification.name` keeps written's
   name; decoded computed flags were already ignored by the decoder (`flags_ignored`).
7. **Nothing to record when the project already shows it.** If found(k) equals
   `projected(k)` (canonical value bytes, `canon::encode_record_json`) → not changed. This
   makes a second examination of the same bytes record nothing (crash rows X1, X2 after a
   seal moved the batch into a pack) and is new spec text (step 4).
8. **Removals.** A removal of an `Alignment`, a `Check` or a `Comment` cannot be written (no
   removal value exists): it goes to `kept_removals`, nothing is planned for it, and it
   counts as a removal for rule 9. A removed `Verse`, `ChapterFront`, `Setting`,
   `ProjectMeta`, `ResourcesExtra` is planned with its removal value (`Absent`,
   `ChapterFront::Absent`, `None`).
9. **Unknown base** (X3): every changed key is planned with `parents = []` and
   `unknown_base = true` when `force_unknown`, when `base` is `Unknown`, when the file removes
   a record that had a value (rule 8 or a removal value), or when more than 50 keys changed.
   Otherwise a key whose found value equals an **older** value of its own history
   (`history(k)` minus the base heads, compared by canonical value) is unknown-base alone (a
   revert). Every other changed key: `parents` = its base heads (empty for a new key),
   `unknown_base = false`.
10. **Comments.** A decoded comment with a new or absent id is a new `Comment` record with no
    parents (rule V6). The store derives a missing id deterministically:
    `CommentId(sha256("outside-comment\0" ‖ path ‖ canonical JSON of {target,text})[..16])`
    (so §11.2's walk can reuse it). A comment whose id exists and whose text or target
    changed is planned **with no parents and `unknown_base = true`**: V6 forbids parents on
    an `External` comment change, so the two versions become a visible `Comment` conflict.
    This is new spec text (X2 says only "new entries become Comment changes").
11. **A book file of an absent book** (no `Present` head): add
    `BookPresence::Present { scope: Whole, how: Added }`, no parents, in the same plan
    (§7.6). `book_added` says so.
12. Plan order: sort changes by key; at most one change per key.

`OutsidePlan` never contains a change whose value equals written(k) or projected(k).

### 5.1 Pack blobs and the expected pack set (§4.4, §5.11 K3, §6.1 O7/O8)

- The expected pack set = HEAD tree's packs (non-redundant, §4.7) ∪ the manifest's pack list ∪

  are immutable, and reading 674 MiB at every checkpoint would break its budget. This is new

- Seal K4 and consolidation Q4: a pending file or replaced pack that cannot be removed now

  it at the next open. Do not fail the seal for it.

### 5.2 The split (R21)

Actor `checkpoint(reason, reply)`:
1. `read_only` → reply `Ok(CheckpointReport::default())`.
2. `second_writer()`, expected-pack check (5.1), seal (K1–K6, no blob writes), and
   `self.project.publish()`; take `dirty` and the snapshot; build `PackListing` (path → id,
   size, fingerprint, md5 if known; `complete: bool`, missing and unreadable sets); read
   `head` (actor's `Git::head`).
3. Send `Job::Checkpoint { snapshot, dirty, packs, reason, head, sealed: Result<SealReport,
   String>, reply }`. Return to the queue.

Writer:
1. `Point::BeforeCheckpoint` hold.
2. C2: run the materialize groups for `dirty`.
3. Store missing pack blobs (5.1). If `!packs.complete` → reply with
   `CheckpointSkip::PackMissing`, notice, no tree.
4. C3: `build_tree` (5.3), then validate (5.4). Failure → `Notice::MaterializeBlocked
   { reason: Blocked::TreeInvalid { problem } }`, reply `TreeInvalid`, no commit.
5. C4: tree == HEAD's tree → reply `NoChanges`.
6. C5 object: `write_commit(tree, [head], author, message)` (5.5); `Point::BeforeHeadUpdate`
   hold and `Hooks::check(Point::BeforeHeadUpdate)` fail point; send
   `Msg::MoveHead { commit, expected: head, tree, reply }`.

Actor on `MoveHead`: `git.move_branch(expected, commit)`; on a mismatch (HEAD moved since,
only a future sync can do that) reply `Err(LookAgain)`-style error and leave the dirty set
for the next checkpoint; else `write_index(tree)` (C6), emit `StoreEvent::Checkpointed {
commit }`, reply `Ok(CheckpointReport { commit: Some(commit), .. })`.

`ProjectHandle::checkpoint` returns `Pending<Result<CheckpointReport, StoreError>>`;
`pub struct CheckpointReport { pub commit: Option<GitOid>, pub sealed: Vec<String>, pub skipped: Option<CheckpointSkip> }`.
The create path (`Store::build`) and `close` use it unchanged.

The 30-minute timer and `close` call the same path. A checkpoint after a failed seal still
materializes (I7) and commits only if the seal left no pending file unsealed that the
snapshot folded (otherwise the tree's derived files would show changes its packs lack:
skip the commit with `CheckpointSkip::SealFailed` and let the next checkpoint commit).

### 6.2 Recording, in `crates/tc-store/src/outside.rs`

Writer side (`Writer::examine(&mut self, fold: &FoldState, rel, bytes, d, mode)`):

1. X1: `copy_external(rel, bytes)` (exists). Carried files skip X1: the blob is their copy.
2. Base: the heads file `.tc/heads/<escaped>.bin` parsed with `HeadsFile::parse` and
   `canon::decode_key` (counter `heads_read`); for `metadata.json` its own heads file (M6 now
   writes one from `metadata_heads`). No manifest entry: if HEAD is an app commit and its tree
   has `rel`, the base is the file's keys' heads restricted to HEAD's pack set (for each key:
   the changes whose packs are all in HEAD's tree, minus those with a child among them; two
   such heads with different values → that key unknown); if HEAD's tree lacks `rel`, the base
   is empty (every key is new). Manifest entry but no readable heads file, or no usable HEAD →
   `Base::Unknown`. (Spec: §6.2 row "no manifest entry" made concrete; new sentence for a lost
   heads file.)
3. Decode (`outside::decode_file`); OBS stories through `tc_obs::story::decode_story`
   (`reformatted` counts as whitespace-only parts). Failure → `OutsideOutcome::Undecodable`.
4. Plan: `fold.plan_outside_edit(...)` with
   `ExternalSource::LocalFile { path: rel, seen_md5: d }`.
5. Plan empty → `Nothing`; else send
   `Msg::RecordOutside { rel, md5: d, plan, reply_to_writer: true }` and put `rel` in
   `pending_record` (no write of `rel` until the reply).

Actor side (`Project::commit_external(plan, Reconciles { path, seen_md5 })`): skip if a pending
file's header already reconciles `(path, md5)` (keep `reconciles` in `PendingInfo`, from the
loader's facts) — X4; B1 runs the per-change rules only (no command rules); B2 assigns seq, at,
batch; B3 writes the pending file with `purpose: save` and the `reconciles` header member; B4 to
B6 as `commit`. Then send `Job::Recorded { rel, md5, outcome: Recorded { batch, changes,
unknown_base } | Refused(reason) }` to the writer and emit `Notice::OutsideEditRecorded`.
A plan the rules refuse (a non-NFC check id in a sidecar, V2) is `Refused`: the copy stays,
`Notice::OutsideEditUnreadable { reason }`.

Writer on `Recorded` (D7): entry `md5 = d`, size/mtime from a stat, `settled = false`,
`scope = None`, `held = None`, `blob = None`; write the manifest; remove from `pending_record`;
add `rel` to `retry` so the next job rewrites it from the fold (the batch's own `Delta` also
marks it through the actor). The same acceptance follows `Nothing` (whitespace-only: notice
`WhitespaceOnlyEdit`; the rewrite restores the file's line endings, §18 item 14) and
`Undecodable` (notice `OutsideEditUnreadable` naming the copy and the reason, e.g. "verse 7
appears twice (line 212)"; the file is rewritten so the burrito is valid again).

At open (O9) the same steps run inline: plan from the open's fold, `project.commit_external`,
accept, mark dirty. A crash between X4 and the acceptance (row X2) is handled by rule 7 of the
planner (the project already shows found) and by the `reconciles` check.

`metadata.json` (M6): bytes there that neither the manifest, the intent nor the new bytes name
are copied (as S1 does, `MetadataEditedOutside`), examined and sent for recording, and then
written over: the copy is what keeps the person's bytes if the recording fails.
`DerivedFieldsEdited` when derived fields were changed.

`project.json` and `format.json` changed outside: never recorded; written back from HEAD's tree
(else this app's `format.json` merged with the local document; for `project.json`, the id and

## Traps found while planning

1. **Disk**: full at planning time (253 MB free; a write of this plan failed once with
   ENOSPC, and the planner removed this worktree's `target/release` to finish it). Vendored
   libgit2 and OpenSSL add about 600 MB to `target/`. Prune first (step 0); never keep two
   corpora; the `FaultFs` mirrors live in `/tmp` (same disk) and static corpora's mirrors are
   only removed by the next run's sweep. Create a mirror lazily (at the first `outside_dir`),
   so FaultFs tests that never open a project make none, and make `Mirror::drop` remove its
   folder at once: `kill_everywhere` makes one copy per kill point.
2. **libgit2 at -O0** makes corpus commits in `cargo test` very slow: add the profile overrides
   of 4.1.
3. **Empty email**: `git2::Signature::new(name, "", …)` fails (libgit2 `signature.c:93`). Write
   commit objects raw (D4).
4. **Reflog identity**: libgit2 takes `user.name`/`user.email` from the machine's global config
   for reflogs (`refs.c:453`). Set `core.logAllRefUpdates=false`.
5. **Spec errors to fix**: §5.13 and §18 item 10 say ref updates are not fsynced; with
   `core.fsyncObjectFiles=true` libgit2 1.9.7 fsyncs ref writes (`refdb_fs.c:2543`) and the
   repack's pack and index (`indexer.c:1411-1433`, `pack-objects.c:1453`).
6. **Owner check**: `ErrorCode::Owner` is not damage. Never rebuild for it (there is no safe
   way to turn the check off).
7. **Streaming reads** of packed objects fail in libgit2 (`git_odb_open_rstream` only for loose
   objects): fall back to `odb.read`.
8. **`Repository` is not `Sync`**: one handle per thread.
9. **Deadlock**: the writer must never wait for the actor; the actor's close must keep
   draining its channel (D2).
10. **Two threads and kill points**: `kill_everywhere` stays valid because each action waits
    for its `Pending`; `wait_idle` must include the writer, or a background write consumes the
    kill point meant for the action.
11. **Windows file removal** while the writer reads a value through an open handle: seal K4 and
    Q4 must tolerate a failed removal (5.1).
12. **USFM has no `from`**: carry written's `from` (planner rule 6), or every renumbered verse
    becomes a false change.
13. **V6 forbids parents on an External comment change**: a comment edited in the file becomes
    a no-parent change, a visible `Comment` conflict (planner rule 10).
14. **Alignments, decisions and comments have no removal value**: a deleted record in a file is
    kept, noticed, and makes the file's other changes unknown-base (planner rule 8).
15. **Re-examination after a crash** must record nothing new (planner rule 7 + D7 + the
    `reconciles` check).
16. **`Entry.oid` already means "carried"** in S1 code (`unsettled()`, removal rules,
    `classify`): add `blob` for derived files instead of reusing `oid`.
17. **`an_open_reads_each_pack_once`**: storing pack blobs must not open a pack a second time;
    use the loader's attached handle, and nothing at all when HEAD holds every pack.
18. **B5**: `Dirty::mark` today makes `paths`, `pins` and every OBS project rewrite everything,
    and `conflicts.json` is marked on every batch; and it scans a book's keys on the actor for
    every save. Move the expansion to the writer (3.1).
19. **Held vs recorded**: several S1 tests assert holds for edits that S2 records; update them
    (6.6) rather than keeping S1 behaviour.
20. **`reads_never_wait_behind_a_held_checkpoint`** asserts the old behaviour (a save waits):
    invert it.
21. **Floats**: `Json` holds integers only; a sidecar or settings edit with a float cannot be
    decoded (undecodable path), never an error that stops the open.
22. **Rules refuse a plan** (a non-NFC identity in a decoded sidecar, V2): the whole batch is
    refused; treat it as undecodable (copy kept, notice), never as an error.
23. **`metadata.json` as a path**: `RepoPath::parse("metadata.json")` succeeds; use it in
    `ExternalSource::LocalFile` and the new notices. Check `Change::new` accepts it.
24. **Test hooks must not move counters**: validate through the raw `Vfs`.
25. **FaultFs watcher events** come only from `put`/`delete`/`set_mtime` (another program),
    never from the store's own writes; the StdFs watcher test covers own-write filtering.
26. **The open's O14 and the writer's first job both run in the background**: `wait_idle`
    waits for both before tests count operations.
27. **Commit time and every `at`** come from the store's `Clock` (`ManualClock` in tests), so
    trees, commits and ids are deterministic in tests.
28. **The old `Point::BeforeMaterialize` hold during the open** now fires on the writer after
    the open returned; tests that hold it while opening on another thread still work.
29. **O2 deletes a temp it could not read** (`finish_temps`, open.rs:707: `read(..).ok()` →
    "incomplete" → `atomic_remove`). On Windows a scanner can make a complete pending temp
    unreadable for a moment; deleting it loses a save "Saved" was shown for. Step 1d keeps
    it.
30. **O2 fails the whole open on one held rename or removal** (`?` at open.rs:713 and 718).
    Step 1d tolerates both.
31. **A failed save's temp and the seq.** The counter does not advance on `NotWritten` (§5.0),
    so the retry reuses the seq. That is right only if the next open never rolls the failed
    temp forward; step 1d's `(device, seq)` rule is what makes it right. Do not "fix" it by
    advancing the counter: the abandoned temp would then roll forward with its own seq and
    still conflict with the person's retried text.
32. **The ledger rule after a temp that cannot be placed.** `check_identity` (open.rs:850)
    compares the ledger with the fold's largest seq; a temp left in place is not folded, so
    count its seqs into `held`, or the open shows a false "This copy is missing N changes".
33. **`set_busy` now refuses removals too.** S1 tests that hold a derived file while the
    store removes it (none found at planning time) would change behaviour; grep `set_busy`.
34. **`HeldRetry::SAVE` waits up to 2 s on the actor.** That is the rare held case only; the
    25 ms p95 save row is measured without holds. The writer's derived files use
    `BACKGROUND` (35 ms) so one held file never stalls a book.
35. **Digest equality must mean "the file shows what the app wrote".** Compute digests from
    the exact pieces the decoder produces (`decompose`'s `VersePart`, the canonical JSON of a
    parsed entry); a projected chapter front of `None` is written as `\c N\n` and must be
    hashed as such. A mismatch only costs time (the key takes the full rules), never a lost
    edit, but it breaks the cost test: fix the renderer.
36. **A digest collision would hide an edit** (the key is skipped, the file accepted and
    rewritten; only the `.tc/external/` copy keeps it). md5's 128 bits make this negligible;
    do not shorten the digest.
37. **Spec §7.4's old sentence** ("the only choice offered is *Apply what was recovered*")
    has no code behind it; do not add any. The UI design (APP C7b) reads §7.4, so the spec
    text is the fix.
