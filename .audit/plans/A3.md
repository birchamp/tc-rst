## 1. Decisions this plan makes (read before coding)

Each is backed by the design or fixes a gap in it; step 10 writes the design fixes into
`docs/APP-DESIGN.md`.

### D1. tc-app is transport-free; the join with tc-server is a named step

A2 (tc-server, `tc4 serve`) and A3 are built at the same time from the same base, so neither can
call the other. The row's "done when", "`tc4 serve` answers `hello` with real state", needs both,
so it is unbuildable inside A3 alone unless A2 merged first. Therefore:

- tc-app never depends on axum, tc-server or `tc4`, and never creates those crates.
- `App` answers every endpoint through one transport-free entry point,
  `App::call(path, body) -> Answer`, whose `Answer::Reply { body, .. }` holds exactly the bytes
  the HTTP route returns with status 200. It also gives `App::events()` (the event bus) and
  `App::quit()` / `App::quitting()`.
- A3's "done when" is proved in process: `hello_answers_real_state` calls
  `App::call("app/hello", b"{}")` on an `App` started from a real `AppConfig` and checks every
  field against live state.
- The join (`tc4 serve` builds the `App` from its flags, routes `POST /api/v1/*` to `App::call`,
  the event stream to `App::events`, quit to `App::quit`, and proves it with
  `tc4_serve_answers_hello_with_real_state`) is done by A3 if A2 is on `phase0` when you build
  (step 11), else by the first unit built on both (A9 or A4b). Step 10 writes this into §10.
- If A2 built its own `hello` state, its own ring of events, or its own `test/crash` handling in
  tc-server, the join keeps tc-app's (§4.1 gives tc-app `EventBus`, "broadcast plus the ring";
  §3.3 gives tc-app a handler for every row) and deletes the server's copy.

### D2. Every endpoint row gets a handler in tc-app, so the router is complete at compile time

§3.3: "tc-app must implement `Handle<E>` for each row, so a request without a handler does not
compile". The phase-0 table also holds rows that later units build: `account/signIn`,
`cancelSignIn`, `resume`, `signOut`, `profileLink` (A8) and `feedback/compose` (A5, whose
workflow task says "Feedback is composed here"). A3 gives them honest placeholders:

- `account/state` and `account/helpLink` are real: `state` is the same `AccountView` `hello`
  carries, from the keychain and memory; `helpLink` echoes the URL after the internet check.
- `account/signIn`, `cancelSignIn`, `resume`, `signOut`, `profileLink` answer
  `ApiError::Unavailable(Feature::Account)`; `feedback/compose` answers
  `ApiError::Unavailable(Feature::Feedback)`. Add those two variants to `tc_api::error::Feature`
  with doc comments naming A8 and A5. A8 and A5 replace the placeholders and delete the variants
  they no longer use.

### D3. The internet check runs before the reply cache and is never cached

AD25's backstop: an endpoint whose `NET` is `Some(kind)` answers `NeedsInternet(kind)` while the
switch is off. The UI then asks, calls `net/set {on:true}`, and sends **the same request again**
(§5.6 item 2). If the refusal were cached under its `RequestId`, the resend would get
`NeedsInternet` forever. So the dispatcher checks `NET` after parsing and before the reply cache,
and a `BadRequest` (no id known) is never cached either. Every other answer of a write is cached.

### D4. A write runs on its own task, so a dropped connection never cancels it

A reload or a lost connection drops the HTTP handler's future. If the save ran inside it, a
save could stop half way. `ReplyCache::run` spawns the write's work with `tokio::spawn`; callers
only await its outcome. A retry while it runs waits for the same outcome (A-2); the work never
runs twice.

### D5. Crash points are tc-app's, in the generic write path

`test/crash { at, path }` (§5.8) ends `tc4` "the next time a write reaches `at`". Only the write
path knows where "before store" and "before reply" are, so tc-app checks the armed crash for
every write (product writes and `test/fieldStore`; never the `test/*` arming hooks themselves):
`BeforeStore` before the handler runs, `BeforeReply` after it returns, inside the spawned work.
`AfterReply` cannot be done in tc-app, because only the server knows when the reply was sent:
`Answer::Reply` carries `then: Then::EndProcess`, and the server ends the process after writing
the body. Ending the process goes through an injected `Ender`: in production it calls
`std::process::exit(CRASH_EXIT_CODE)`; in tests `RecordingEnder` records the point, marks the
`App` dead (every later `call` answers `Answer::Ended`), and the test starts a new `App` on the
same app-data folder, as the harness restarts `tc4`. `DuringDraftWrite` is accepted and armed but
no phase-0 write reaches it.

### D6. `test/fieldStore` is durable on disk, unlike the prefs

A4b's `reload_anywhere_stores_the_last_text_once` ends `tc4` through `test/crash` and then checks
what was stored, so the test fields must survive a process end: their state is
`<app_data>/test-hooks/fields.json`, written atomically (temp file in the same folder, `sync_all`,
rename, fsync the folder) **before** the reply, as STORAGE's B3 is before an `Ack`. Prefs stay in
memory as the row says (§4.9: "Before S1 these files live in memory"); C1a moves app data onto
`tc_store::atomic_write`. The atomic helper lives in `hooks` under `test-hooks` only and is
deleted when C1a brings tc-store's.

### D7. `test/fieldStore` mimics the store's token and conflict rules, and its log says when a save was not on the current version

- Each test field has a version (0 at first) and a value ("" at first). Its token is
  `ShownToken::from_body(base64url(payload ‖ mac16))`, `payload` the canonical JSON
  `{"field":<name>,"version":<n>}`, `mac16` the first 16 bytes of HMAC-SHA256 under a random
  32-byte key kept in `fields.json` (so tokens survive a restart, as the store's installation
  secret does).
- A store whose token fails its MAC or names another field: `NotSaved::BadToken`.
- Text is stored in NFC. A store whose NFC text equals the value of the version its token names
  stores nothing: `Stored::Unchanged`, no log line (STORAGE:1447).
- Otherwise version + 1, value = text, one log line. If the token named an older version than the
  current one, the real store would keep both versions as a conflict (STORAGE:1449-1453), so the
  `Ack` lists one `ConflictBrief` (by `Who::Mine`), and the log line is marked
  `TokenBase::Stale`. In A4b's tests of the save machine a stale store is a self-conflict, which
  AD4 exists to prevent, so A4b can assert there are none. This needs one tc-api change:
  `StoredText` gains `pub base: TokenBase` (`enum TokenBase { Current, Stale }`, camelCase on the
  wire). Update A1's golden (`UPDATE_GOLDEN=1`, step 9).

### D8. The projects folder (Q-4): an existing folder wins; at first launch the default is checked

There is no `projects.json` to remember a choice in phase 0 (prefs are in memory), so the rule
must give the same folder at every launch from what is on disk, and never hide a folder that
holds projects:

1. `--projects <dir>` given (tc-app: `ProjectsFolder::Given`): use it as given. No check: each
   project's open gates a synced folder anyway (STORAGE §5.0, O5).
2. Otherwise let D = home/`translationCore4`/`projects` (home = `%USERPROFILE%` on Windows, `$HOME`
   elsewhere) and L = the local data folder/`translationCore4`/`projects` (`%LOCALAPPDATA%` on
   Windows; `$HOME/Library/Application Support` on macOS; `$XDG_DATA_HOME` when absolute, else
   `$HOME/.local/share`, on Linux). L is never copied by OneDrive's Known Folder Move, iCloud
   Drive's Desktop and Documents, or a roaming profile.
3. If D is a folder: use D. Else if L is a folder: use L (an earlier first launch chose it).
4. First launch (neither exists): if the cloud detection finds no client for D, create D. If it
   names a client for D and none for L, create L. If both are synced, create D: every project
   then opens read-only with STORAGE's copy offer, which tells the person why.
5. A first-launch choice adds a report (`ReportOp::ProjectsFolder`, with the path, the choice and
   the client), so "Ask for help" carries it.

Known edge, written into §4.9: if a person later makes D by hand while L holds projects, D wins
and L's projects are not listed. No app path creates D once L exists.

The cloud detection is a port of `storage:crates/tc-store/src/platform.rs` `cloud_client` (env
roots `OneDrive`, `OneDriveConsumer`, `OneDriveCommercial`; Dropbox `info.json` roots; iCloud,
`Library/CloudStorage`, Google Drive under home; `.dropbox` and `.stfolder` in an ancestor;
Windows placeholder attributes). tc-store is not on `phase0`, so the port lives behind the
`FolderCheck` trait in `tc_app::folders`, reads its variables from `HostEnv` (so tests drive it
on Linux), and C1a replaces it with `tc_store::platform::StdPlatform::folder`. This is a rebuild
behavior with no tC4 counterpart (tC4 keeps its profile under the home folder,
`tC4:scripts/desktop-bootstrap.cjs:30-33`), so say so to the owner in the final answer.

### D9. Scoped prefs need a session; phase 0 has none

`prefs/setDraftUnit`, `setAlignSuggestions` and `recordPlace` carry `at: Scope`. The project id
behind a scope comes from the session registry (B1b). A3 adds the seam
`trait SessionDirectory` with `NoSessions` (every scope is stale), and the handlers answer
`ApiError::NotSaved(NotSaved::StaleScope)` for a scope it does not know (§3.5: a write never gets
`ApiError::StaleScope`). Tests use a fake directory, so the handlers are tested for real. `hello`'s
`sessions` comes from the same seam.

### D10. One app-level `ReplyCache` now; B1b adds one per session

§4.4 keys the cache per session. Phase-0 writes have no session (`net/set`, `prefs/setLocale`,
`app/quit`, `app/clientError`, `jobs/cancel`, `test/fieldStore`), so A3 runs every write through
one app-level cache. B1b wires per-session caches for scoped writes ("the reply cache wired to
sessions"). Same type.

### Step 2. `EventBus` (events.rs)

§3.6, §4.1, §5.4. One bus per `App`, shared by jobs, the internet switch, startup and later

```rust
pub const RING_FRAMES: usize = 4096;
#[derive(Clone)]
pub struct EventBus { inner: Arc<BusInner> }
struct BusInner { instance: ServerInstance, state: Mutex<Ring>, live: broadcast::Sender<EventFrame> }
struct Ring {
    next_seq: u64,                    // first frame is 1
    first_seq: u64,                   // seq of slots[0]
    slots: VecDeque<Option<EventFrame>>,  // None: a progress frame a newer one of its job replaced
    floor: u64,                       // highest seq dropped for capacity; 0 at first
    latest_progress: HashMap<JobId, u64>,
}
impl EventBus {
    pub fn new(instance: ServerInstance) -> Self;
    pub fn instance(&self) -> ServerInstance;
    /// Stamps, keeps and sends one frame; returns its seq.
    pub fn publish(&self, event: Event) -> u64;
    /// Frames after `after`, then live ones. `after` is the last seq the reader holds, 0 for
    /// none. If the ring no longer holds every frame after `after`, or `after` is beyond the
    /// newest frame (another server run's number), the first frame is `Resync`.
    pub fn subscribe(&self, after: u64) -> Subscription;
    pub fn head(&self) -> u64;
}
pub struct Subscription { replay: VecDeque<EventFrame>, live: broadcast::Receiver<EventFrame>, last: u64 }
pub enum Next { Frame(EventFrame), Lagged, Closed }
impl Subscription { pub async fn next(&mut self) -> Next; pub fn try_next(&mut self) -> Option<Next>; }
```

Rules:

- `publish` holds the ring lock while it assigns the seq, stores the slot and sends on
  `broadcast`, so a subscriber made under the same lock never misses or repeats a frame.
- Coalescing (§5.4: "the newest per job replaces older ones"): when a frame for job J is
  published, the slot of J's previous `Running` frame becomes `None`; then if the new frame is
  `Running`, record its seq in `latest_progress`, else remove J's entry. State frames
  (`Queued`, `Cancelling`, `Done`, `Failed`, `Cancelled`) are never dropped. Live subscribers get
  every frame; coalescing only shortens a replay. Use the slot index `seq - first_seq`, so
  replacing is O(1).
- Capacity counts slots, tombstones included: past `RING_FRAMES`, pop the front and set
  `floor` to its seq.
- `subscribe(after)`: under the lock, make the receiver; if `after < floor` or
  `after > next_seq - 1`, replay one frame `EventFrame { seq: head, instance, event: Resync }`;
  else replay every `Some` slot with seq > `after`. `last` = the last replayed seq (or `after`).
- `next`: replay first; then `live.recv()`: skip frames with seq ≤ `last`;
  `RecvError::Lagged` → `Next::Lagged` (the server ends the stream; the UI reconnects with its
  last seq and gets the replay or `Resync`); `Closed` → `Next::Closed`.
- `broadcast` capacity: `RING_FRAMES`. Ignore the error of a send with no receivers.
- The SSE text (`id:`, `data:`), the 15 s heartbeat and the per-connection queue are tc-server's
  (A2, §5.4). Write that split into the module comment.

```rust

pub struct BodyDigest([u8; 32]);
impl BodyDigest {
    /// SHA-256 of the endpoint path, a zero byte, and the request as serde writes it again
    /// after parsing: the same request sent twice digests the same, whatever its spacing, and
    /// an id reused for another endpoint differs.
    pub fn of(path: &str, canonical_body: &[u8]) -> Self;
}
#[derive(Clone, Debug)]
pub enum Outcome { Reply(Arc<[u8]>), #[cfg(feature = "test-hooks")] Ended }
pub enum CacheAnswer {
    Fresh(Outcome),    // this call ran the work
    Repeat(Outcome),   // a retry: the first attempt's outcome, finished or awaited
    Reused,            // the id came with another body: ApiError::RequestReused
}
pub struct ReplyCache { state: Mutex<CacheState>, finished_cap: usize }
struct CacheState { entries: HashMap<RequestId, Entry>, finished: VecDeque<RequestId> }
struct Entry { digest: BodyDigest, slot: Slot }
enum Slot { Running(watch::Receiver<Option<Outcome>>), Finished(Outcome) }
impl ReplyCache {
    pub const FINISHED: usize = 1024;
    pub fn new(finished_cap: usize) -> Arc<Self>;
    /// Runs `work` once per request id on its own task, so a caller that goes away (a reload,
    /// a dropped connection) never stops a write half way.
    pub async fn run<W>(self: &Arc<Self>, id: RequestId, digest: BodyDigest, work: W) -> CacheAnswer
        where W: Future<Output = Outcome> + Send + 'static;

}
```

Rules:

- Lookup under the lock: other digest → `Reused` (the work is dropped unpolled, so nothing ran);
  `Finished(o)` → `Repeat(o)`; `Running(rx)` → wait on `rx.wait_for(Option::is_some)` →
  `Repeat`; absent → insert `Running`, spawn the work, wait → `Fresh`.
- The spawned task: `let out = work.await;` then under the lock set `Finished(out)`, push the id
  on `finished`, evict from the front while `finished.len() > finished_cap` (remove the entry
  only if it is still `Finished` with that id), then `tx.send(Some(out))`.
- In-flight entries are never evicted (A-2).
- The dispatcher's work already turns a handler panic into an `Internal` reply (step 8), so the
  cache's task never ends without an outcome.

Tests (`tests/app/replies.rs`, multi-thread runtime where waits matter):

- `retry_of_a_finished_request_gets_the_first_reply`: work counts runs and returns bytes A; a

- `retry_while_the_first_attempt_runs_waits_and_runs_once`: first work waits on a

- `retry_with_another_body_is_request_reused`: finished and running cases both → `Reused`, and
  the second work never runs.
- `an_id_reused_for_another_endpoint_is_request_reused`: same body bytes, other path.
- `a_write_finishes_when_its_caller_goes_away`: drop the first caller's future after the work
  started (`tokio::time::timeout` of 1 ms around it); the work still completes (its side effect is

- `finished_replies_are_bounded_and_running_ones_never_evicted`: cap 4; one held running entry

- proptest `each_request_runs_once`: random interleavings of ids, bodies and retries on a

Rules:

- `set_locale`: the task builds the app document with the new locale, writes it, and only on
  success makes it current; on failure the stored and the current locale stay as they were and
  the handler answers `Refused(Prefs(LocaleNotSaved))` (tC4 keeps the dialog and saves nothing,
  `app-language.spec.ts:262-283`). Because the task applies the change right after the write and
  before its next message, a debounced write that comes next serializes the new locale too.
- Every other write that fails keeps the value for the session and adds a `PrefsWrite` report
  (§4.9). The next change of that file writes again.
- `record_place`: the task applies tC4's `recordPlace` to the stored record of the unit, then
  restarts that project file's 500 ms timer (`state.jsx:3843-3849`). Port the rule exactly: mode
  = update's or prior's or `Draft`; chapter = update's or prior's or 1; verse = `Keep` → prior's
  or none, `Clear` → none, `Set(v)` → v; tool kept only when the mode is `Check` (update's or
  prior's); `at` = now. Keys: a book's code (`"TIT"`), or `story:N`.
- `record_last_edit`: keep it as `lastEdit`, record it as a place observation of its unit (tC4's
  `recordLastEdit` calls `rememberPlace`, #329), and restart a 5 s timer for the app document.
  tC4 waits 1 s; §4.9 says why the rebuild waits 5 s (A-20).
- A write serializes the document as it is when the timer fires, never a copy taken earlier
  (tC4: "The write reads the NEWEST pending record when it runs").
- `leave_project` and `flush` write every pending document at once and return after the writes.
- Timers: `tokio::time::sleep_until` on the earliest deadline inside a `select!` with the
  message channel.

```rust
macro_rules! router {
    (fn $name:ident $( $kind:ident $([$net:ident])? $path:literal : $req:path => $ok:ty; )*) => {
        impl App {
            pub(crate) async fn $name(&self, path: &str, body: &[u8]) -> Option<Answer> {
                match path {
                    $( $path => Some(router!(@run $kind self $path $req body)), )*
                    _ => None,
                }
            }
        }
    };
    (@run query $app:ident $path:literal $req:path $body:ident) => { $app.run_query::<$req>($body).await };
    (@run command $app:ident $path:literal $req:path $body:ident) => { $app.run_write::<$req>($path, $body).await };
    (@run job $app:ident $path:literal $req:path $body:ident) => { $app.run_write::<$req>($path, $body).await };
}
tc_api::endpoint_table!(router fn route_product);
#[cfg(feature = "test-hooks")]
tc_api::test_hook_table!(router fn route_test_hooks);
```

`canonical = serde_json::to_vec(&req)`; `digest = BodyDigest::of(path, &canonical)`; `id =
req.request()`; build the work:

```text
let app = self.clone();
work = async move {
    let _busy = app.busy_guard();                         // a write whose caller left still counts (test/quiet)
    #[test-hooks] if let Some(e) = app.crash_at(CrashPoint::BeforeStore, path) { return e }     // Outcome::Ended
    let handled = tokio::spawn({ let app = app.clone(); async move { app.handle(req).await } }).await;
    let reply = match handled { Ok(r) => Reply::from(r), Err(join) => Reply::Err(app.internal("a handler stopped", join)) };
    let bytes = serde_json::to_vec(&reply) …;                // a failure here is Internal too
    #[test-hooks] if let Some(e) = app.crash_at(CrashPoint::BeforeReply, path) { return e }

}
```

## 4. Invariants (the verifiers will attack these)

1. **No write runs twice for one request id**, while it runs, after it finished, or when its
   caller went away; a retry with another body is refused, never answered with the first reply.
2. **No write stops half way because a connection dropped** (D4).
3. **A refusal that changed nothing and needs a resend is never cached** (D3).
4. **`test/fieldStore` is durable before its `Ack`**; a crash before the reply keeps the text,
   a crash before the store keeps nothing; the log never loses or duplicates a line except a
   stale store, which is marked.
5. **Every text is compared and stored in NFC.**
6. **Prefs never lose a member**: unknown and malformed members are kept; a failed write keeps
   the value for the session and is reported; a failed app-language save changes nothing.
7. **Progress counts never fall within a phase; no `Running` frame follows `Cancelling` or a
   terminal frame; a job's end is published at once; nothing before 300 ms.**
8. **No frame is lost or repeated between a replay and the live stream**; a reader that cannot
   be served from the ring gets `Resync`, never a silent gap.
9. **Flows**: no two passes that exclude each other are ever held together.
10. **The projects folder** is never moved from a folder that exists; nothing is created except
    at a first launch; the user's own `--projects` is used as given.
11. **No lock is held across an `.await` or while a job's work runs.**
12. **The Door43 token never reaches the UI or a report**; `tc_door43::Token` prints redacted.

## 6. Traps found while planning

1. **Paused tokio time auto-advances** when every task waits on something other than a timer.
   In paused tests, never `.await` a channel or a `Notify`; step with
   `tokio::time::advance(d).await` plus `tokio::task::yield_now().await`, and read with
   `try_next` / `try_recv`. Tests that need real threads (`cancel_stops_at_next_chunk`, the
   flow-gate thread race, the reply-cache waits) use a multi-thread runtime without pause and no
   sleeps longer than needed.
2. **`start_paused` needs tokio's `test-util` feature** (dev-dependency only). For a proptest
   case, build the runtime with `Builder::new_current_thread().enable_time().start_paused(true)`.
3. **Feature unification**: the self dev-dependency turns `test-hooks` on for every test build
   and for `cargo clippy --workspace --all-targets`. Only `cargo clippy -p tc-app --lib` sees the
   library without it, so items used only by hooks must be `#[cfg(feature = "test-hooks")]` or
   that gate fails on dead code.
4. **tc-api's `server` feature** is on in every host build (tc-app and tc-api's own tests enable
   it). That is fine: AD3's proof is tc-ui's wasm32 build, which never links tc-app.
5. **`Reply::<()>::Err(e)`** serializes an error for any endpoint; do not try to name `E::Ok`
   when the body did not parse.
6. **Requests refuse unknown keys at any depth** (`deny_unknown_fields`), so a parse error is a
   normal `BadRequest`, not an internal error.
7. **The digest must be of the re-serialized request plus the path** (D3/A-2): digesting raw
   bytes would call a whitespace-different resend "another body".
8. **`AfterReply` is the server's job**: tc-app can only say `Then::EndProcess`.
9. **A crash hook must not fire on the request that armed it**: exclude the arming hooks.
10. **`std::process::exit` in `ExitProcess`** ends without destructors; that is the point (a
    crash, not a quit). Never call it outside `test-hooks`.
11. **`HostEnv` on Linux cannot make a Windows path with backslashes**: assert path components,
    not strings, in the Windows tests.
12. **The first-launch folder does not exist when it is checked**: canonicalize its deepest
    existing ancestor, or a symlinked temp dir (macOS `/var` → `/private/var`) defeats the
    prefix match against canonical roots.
13. **Holding the prefs `Mutex` while calling `AppDataFiles::write`** is fine for `MemoryFiles`
    (no await). Note in a comment that C1a's disk writer must snapshot and write on
    `spawn_blocking` instead.
14. **Disk is short** (4.5 GB free at planning time; the storage worktree's target is 9 GB and is
    not yours). `CARGO_INCREMENTAL=0`, `-j 2`, crate-scoped tests until the end, prune when
    under 6 GB. Never touch other worktrees or the scratchpad.
15. **`account/state` must not read the keychain per call**: an OS keychain can prompt the
    person. Read once at start.
16. **`LocaleId` is `Copy` and parses only the ten ids**: a stored `"EN"` is not English by
    case-folding; it reads as the default and stays in the file.
17. **`endpoint_table!` passes prefix tokens before the rows** (`tc_api::endpoint_table!(router fn
    route_product)`); the callback name resolves at the call site, so `router!` must be defined
    above the invocation in the same module.
18. **A2 may land a different seam.** If `phase0` gains A2 while you build, merge it and follow
    D1 and step 11; if A2's server already answers `hello` from its own state, the join replaces
    that state with `App`'s.
