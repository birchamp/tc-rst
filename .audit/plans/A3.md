### Findings on the built code (fix them in step 8)

- **F1. A lost reply-cache entry stays "running" forever.** When the task that runs a write
  ends without an outcome (`CacheAnswer::Lost`), its entry stays `Slot::Running` with a dead

## 1. Decisions (read before coding)

Each is backed by the design or fixes a gap in it; step 10 writes the design fixes into
`docs/APP-DESIGN.md`.

### D1. tc-app is transport-free; whoever of A2 and A3 merges second joins them

A2 (tc-server, `tc4 serve`) and A3 are built at the same time from the same base, so neither can
call the other, and the row's "done when", "`tc4 serve` answers `hello` with real state", needs
both. Therefore:

- tc-app never depends on axum, tc-server or `tc4`, and never creates those crates.
- `App` answers every endpoint through one transport-free entry point,
  `App::call(&self, path: &str, body: &[u8]) -> Answer`, whose `Answer::Reply { body, then }`
  holds exactly the bytes the HTTP route returns with status 200; plus `App::events()` (the
  bus), `App::quit()` and `App::quitting()`. A2's `Backend` trait
  (`p0-a2:crates/tc-server/src/backend.rs`) has exactly this shape: `call(path: &'static str,
  body: Bytes) -> Answer`, `subscribe(after) -> Events`, `quit()`, `quitting()`, with its own
  `Answer`/`Then`/`Next` enums whose variants match tc-app's one to one.
- A3 proves its part in process: `hello_answers_real_state` calls
  `App::call("app/hello", b"{}")` on an `App` started from a real `AppConfig` and checks every
  field against live state.
- The join is a ~40-line adapter in `tc4` (A2's plan, section 7): a newtype `AppBackend(App)`
  implements `tc_server::Backend`, `AppEvents(Subscription)` implements `EventSource`, and
  `tc4 serve` starts `App` instead of A2's `Stub`. **A2 does it if `p0-a3` reached `phase0`
  before A2's last gates (A2 step 12); A3 does it if A2 reached `phase0` before yours (step 11);
  if neither, A9 or A4b, whichever starts first.** Step 10 writes this into §10.
- At the join, tc-app's ring, `hello` state and crash points before the store and the reply
  replace any server copy (§4.1 gives tc-app `EventBus`, "broadcast plus the ring"; §3.3 gives
  tc-app a handler for every row). A2's plan already builds no ring and keeps its `Stub` only as
  the backend of tc-server's own tests.

### D2. Every endpoint row gets a handler in tc-app, so the router is complete at compile time

§3.3: "tc-app must implement `Handle<E>` for each row, so a request without a handler does not
compile". The phase-0 table also holds rows later units build: `account/signIn`,
`cancelSignIn`, `resume`, `signOut`, `profileLink` (A8) and `feedback/compose` (A5, whose
dialog composes the attachment; tC4's `attachmentText` needs the version line the dialog shows).
A3 gives them honest placeholders:

- `account/state` and `account/helpLink` are real: `state` is the same `AccountView` `hello`
  carries, from memory; `helpLink` echoes the URL after the internet check (tC4's help panel

- `account/signIn`, `cancelSignIn`, `resume`, `signOut`, `profileLink` answer
  `ApiError::Unavailable(Feature::Account)`; `feedback/compose` answers
  `ApiError::Unavailable(Feature::Feedback)`. **Done** in `91d8c3e` (tc-api `Feature`). A8 and A5
  replace the placeholders and delete the variants they no longer use.

### D3. The internet check runs before the reply cache and is never cached

AD25's backstop: an endpoint whose `NET` is `Some(kind)` answers `NeedsInternet(kind)` while the
switch is off. The UI then asks, calls `net/set {on:true}`, and sends **the same request again**
(§5.6 item 2). If the refusal were cached under its `RequestId`, the resend would get
`NeedsInternet` forever. So the dispatcher checks `NET` after parsing and before the reply cache,
and a `BadRequest` (no id known) is never cached either. Every other answer of a write is cached,
refusals included (a retry after a lost reply must get the same refusal, not run again).

### D4. A write runs on its own task, so a dropped connection never cancels it

Built (`ReplyCache::run` spawns the work). The dispatcher must not await anything a dropped
caller would cancel before it hands the work to the cache.

### D5. Crash points are tc-app's, in the generic write path

`test/crash { at, path }` (§5.8) ends `tc4` "the next time a write reaches `at`". Only the write
path knows where "before store" and "before reply" are, so tc-app checks the armed crash for every
write (product writes and `test/fieldStore`; never the arming hooks `test/crash`, `test/hold`,
`test/release`, `test/reset`): `BeforeStore` before the handler runs, `BeforeReply` after it
returns, both inside the work the cache runs. `AfterReply` cannot be done in tc-app, because only
the server knows when the reply was sent: `Answer::Reply` carries `then: Then::EndProcess`, and
the server ends the process after writing the body (A2's `EndAfterBody` does it in its `Drop`).
Ending goes through an injected `Ender`: in production `ExitProcess` calls
`std::process::exit(CRASH_EXIT_CODE)` (86, the value A2's tc-server uses too); in tests
`RecordingEnder` records the point and the `App` marks itself dead (D12): every later `call`
answers `Answer::Ended`, and the test starts a new `App` on the same app-data folder, as the
harness restarts `tc4`. `DuringDraftWrite` is accepted and armed, and no phase-0 write reaches it.

### D6. `test/fieldStore` is durable on disk, unlike the prefs

A4b's `reload_anywhere_stores_the_last_text_once` ends `tc4` through `test/crash` and then checks
what was stored, so the test fields survive a process end: their state is
`<app_data>/test-hooks/fields.json`, written atomically (temporary file in the same folder,
`sync_all`, rename, fsync the folder on Unix) **before** the reply, as STORAGE's B3 comes before
an `Ack`. The write runs on `tokio::task::spawn_blocking` (an fsync on a runtime worker would stall
every other request; §4.7 does the same for installs). Prefs stay in memory as the row says. The
atomic helper lives in `hooks.rs` under `test-hooks` only; C1a deletes it for
`tc_store::atomic_write`.

### D7. `test/fieldStore` mimics the store's token and conflict rules

- Each test field's version is the number of texts stored into it (0 at first) and its value is
  the last stored text ("" at first). Its token is
  `ShownToken::from_body(base64url_nopad(payload ‖ tag))`, `payload` the JSON
  `{"field":<name>,"version":<n>}` as `serde_json::to_vec(&json!(…))` writes it (the workspace
  enables `preserve_order`, so the key order is fixed), `tag` the full 32-byte HMAC-SHA256 of the
  payload under a random 32-byte key kept in `fields.json`, so tokens verify after a restart, as
  the store's installation secret does. Verify with `ring::hmac::verify` (constant time).
- A token whose tag fails, that names another field, or that names a version above the current
  one: `NotSaved::BadToken`.
- The text is compared and stored in NFC.
- **A store whose NFC text equals the value of the version its token names stores nothing**
  (STORAGE:1446-1447): `Stored::Unchanged`, no log line, `tokens: [the token of the named
  version]`, `saved: [the named version's value]`, `view: ViewSeq(current version)`. The field
  is then clean on the token it already had, so a newer version made meanwhile meets its next
  save as a conflict, never as a silent replacement. *(Revision 1 answered with the current token
  and value, which would have turned the next save into a revert.)*
- Otherwise: version + 1, value = text, one log line `StoredText { request, text, base }`. If
  the token named an older version than the current one, the real store would keep both as a
  conflict (STORAGE:1449-1453), so the line is `TokenBase::Stale` and the `Ack` lists one
  `ConflictBrief` by `Who::Mine`. In A4b's tests of the save machine a stale store is a
  self-conflict, which AD4 exists to prevent, so A4b asserts there are none. tc-api's
  `StoredText.base` is **done** (`91d8c3e`).

### D9. Scoped prefs need a session; phase 0 has none

### D10. One app-level `ReplyCache` now; B1b adds one per session

§4.4 keys the cache per session. Phase-0 writes have no session, so every write goes through one
app-level cache. B1b wires per-session caches for scoped writes. Same type.

### D11. `test/reset` turns the internet switch off

`test/reset` is the parity harness's `home()` between scenarios (§5.8). tC4's internet switch is
page state that every reload turns off (`tC4:e2e/helpers/door43Share.ts:21-25`: "reload starts
off"), so every tC4 scenario starts offline. The rebuild's switch lives in the server for the
launch (§5.6), so `test/reset` turns it off and publishes `Internet { on: false }` if it was on,
as a fresh launch would find it. Step 10 adds this to §5.8's row and step 9 to tc-api's `Reset`
doc comment (no wire change).

### D12. A dead App writes nothing and holds nothing

After `RecordingEnder` fires, the `App` is dead: `call` answers `Answer::Ended` at once, and
every durable write (`fields.json`) checks the dead flag inside the writer lane, after the hold
point and before the write, and returns `Outcome::Ended` without writing. Ending releases every
hold, so a store that was held finishes (as `Ended`) instead of waiting forever. A real
`ExitProcess` never returns, so none of this runs in a release-shaped test build.

### D13. A `--projects` folder that does not exist stops the start

`App::start` with `ProjectsFolder::Given(p)` and `!folders.is_folder(p)` returns
`StartError::ProjectsFolder { path, reason: "is not a folder" }`. The default rule only creates
a folder at a first launch, when neither candidate exists. Nothing is created in place of a
folder someone named, so a typo never shows an empty project list as if the projects were gone.

### D14. A2's `test/echo` row

`p0-a2:900cf7a` adds `query "test/echo": Echo => EchoView` to `test_hook_table!`
(`EchoView::of_size(size)`, `MAX_ECHO` = 4 MiB). Once it is on your branch, the test-hook

**8.5 `dispatch.rs`**

```rust
pub trait Handle<E: Endpoint> {
```

Impls write `async fn handle(&self, req: X) -> Result<…, ApiError>`; that compiles against the
trait's `+ Send` signature as long as the body holds no `!Send` value across an await.

The router (checked to compile while planning revision 1; the rows' shape is
`kind [Net]? "path": Req => Ok;`, the same as tc-api's own `define_endpoints!`):

```rust
macro_rules! router {
    (fn $name:ident $( $kind:ident $([$net:ident])? $path:literal : $req:path => $ok:ty; )*) => {
        impl App {
            pub(crate) async fn $name(&self, path: &str, body: &[u8]) -> Option<Answer> {
                match path {
                    $( $path => Some(router!(@run $kind self $path $req body)), )*
                    _ => None,
                }
            }
        }
    };
    (@run query $app:ident $path:literal $req:path $body:ident) => { $app.run_query::<$req>($body).await };
    (@run command $app:ident $path:literal $req:path $body:ident) => { $app.run_write::<$req>($path, $body).await };
    (@run job $app:ident $path:literal $req:path $body:ident) => { $app.run_write::<$req>($path, $body).await };
}
tc_api::endpoint_table!(router fn route_product);
// Step 9 adds, below it:
// #[cfg(feature = "test-hooks")]
// tc_api::test_hook_table!(router fn route_test_hooks);
```

A row without `impl Handle<Row> for App` fails to compile: that is §3.3's guarantee. `router!`
must be defined above the invocations in the same module (the callback resolves at the call site).

`App::call(path, body)`:

1. (step 9) If the App is dead → `Answer::Ended`.
2. Unless `path == "test/quiet"`, count the call in `calls` with a guard that decrements on drop
   (a dropped connection drops the future, and the guard with it).
3. `route_product(path, body)`; then (step 9, `hooks.is_some()`) `route_test_hooks`; else
   `Answer::NotFound`.

`run_query::<E>(body) where App: Handle<E>`: parse
(`serde_json::from_slice::<E>(body)`; error → reply `Err(BadRequest { field: "body", reason:
e.to_string() })`); NET guard (`if let Some(kind) = E::NET && !internet.is_on()` → reply
`Err(NeedsInternet(kind))`); `self.handle(req).await`; serialize `Reply::<E::Ok>::from(result)`
with `Then::Continue`. A query's handler runs in the caller's task; queries change nothing, so a
dropped caller loses nothing.

`run_write::<E: Write + Send>(path: &'static str, body) where App: Handle<E>` (the request moves
into a spawned task, hence `Send`; every request type is plain data): parse (BadRequest,
uncached); NET guard (uncached, D3); `canonical = serde_json::to_vec(&req)` (failure → an
`internal` reply, uncached); `digest = BodyDigest::of(path, &canonical)`; `id = req.request()`;
then:

```text
let app = self.clone();
work = async move {
    (step 9) if let Some(o) = app.crash_at(CrashPoint::BeforeStore, path) { return o }   // Outcome::Ended
    let handled = tokio::spawn({ let app = app.clone(); async move { app.handle(req).await } }).await;
    let reply = match handled {
        Ok(result) => Reply::from(result),
        Err(stopped) => Reply::Err(app.internal("a request handler stopped",
                          facts(json!({"path": path, "stopped": stop_reason(stopped)})))),
    };
    (step 9) if app.is_dead() { return Outcome::Ended }   // D12: a write that ran on past the end
    let bytes = serde_json::to_vec(&reply)   // failure: serialize Reply::<()>::Err(app.internal(…)) instead
    (step 9) if let Some(o) = app.crash_at(CrashPoint::BeforeReply, path) { return o }
    Outcome::Reply(bytes.into())
};
match self.inner.replies.run(id, digest, work).await {
    CacheAnswer::Fresh(Outcome::Reply(b)) => Answer::Reply { body: b.to_vec(), then: self.then_after(path) },
    CacheAnswer::Repeat(Outcome::Reply(b)) => Answer::Reply { body: b.to_vec(), then: Then::Continue },
    CacheAnswer::Reused => reply Err(ApiError::RequestReused),
    CacheAnswer::Lost => reply Err(self.internal("a write ended without a reply", facts(json!({"path": path})))),
    #[cfg(feature = "test-hooks")] CacheAnswer::Fresh(Outcome::Ended) | CacheAnswer::Repeat(Outcome::Ended) => Answer::Ended,
}
```

`then_after(path)` is `Then::Continue` until step 9 (then: `EndProcess` iff an `AfterReply` crash
is armed with `path` `None` or equal to this path; it disarms it). The inner `tokio::spawn` turns a
handler panic into an `Internal` reply, so the cache's task always gets an outcome and `Lost`
stays unreachable in practice. `Reply::<()>::Err(e)` serializes an error for any endpoint
(trap 5).

```rust

struct FieldsFile { schema_version: u32 /* 1 */, key: String /* 64 hex */, fields: BTreeMap<String, Vec<StoredText>> }

    key: ring::hmac::Key,
    lane: tokio::sync::Mutex<()>,                  // one store at a time, held across the hold and the write
    state: std::sync::Mutex<FieldsFile>,           // what fieldLog reads; changed only by the lane holder
}
impl TestFields {
    pub fn load(app_data: &Path) -> Result<Self, String>;   // creates the folder; makes the key the first time and writes the file
    pub async fn store(&self, req: FieldStore, hooks: &TestHooks) -> Result<Ack, ApiError>;
    pub fn log(&self, field: &str) -> Result<FieldLogView, ApiError>;
}

```

Version of a field = `stores.len()`; value of version v = `stores[v-1].text`, v0 = "". One
source of truth, so version and log cannot disagree.

`write_file_atomically`: temp `dir/<name>.<pid>.<n>.tmp` (n from a static `AtomicU64`);
`File::create`, `write_all`, `sync_all`, close; `fs::rename` over `dir/<name>`; on Unix
`File::open(dir)?.sync_all()`. On any error remove the temp file (ignore that error) and return
the first error. Run it inside `tokio::task::spawn_blocking`.

`store`, in order:
1. Field name: non-empty, at most 200 bytes, no control character; else
   `BadRequest { field: "field", reason }`.
2. Token: `base64url` decode of `shown.body()`; split payload and the last 32 bytes;
   `hmac::verify`; parse the payload; field must equal `req.field`; else `NotSaved(BadToken)`.
3. Take `lane` (async).
4. `hooks.holds.reach(HoldPoint::Save).await` (inside the lane, as a held save holds the actor's
   queue; reads do not wait, because `log` reads `state`).
5. If `hooks.dead` is set: write nothing and return `Err(NotSaved(Disk("tc4 ended")))` (D12).
   That error is never sent: `run_write`'s work checks `app.is_dead()` (test-hooks only) right
   after the handler returns and, when dead, returns `Outcome::Ended` instead of a reply, so the
   caller gets `Answer::Ended` as from a process that is gone.
6. Read the field under `state`: `version`, `named` = token's version; `named > version` →
   `NotSaved(BadToken)`.
7. `text = req.text.nfc().collect::<String>()`; if `text == value(named)` →
   `Ack { view: ViewSeq::new(version), stored: Unchanged, tokens: [TokenUpdate { record,
   token: mint(named) }], new_conflicts: [], saved: [SavedValue { record, text: value(named) }],
   rows: [], disk_warning: None }`; no write, no log line (D7).
8. Else build the new file (clone of `state` with `StoredText { request, text, base: if named ==
   version { Current } else { Stale } }` pushed), serialize, write atomically on the blocking
   pool; failure → `NotSaved(Disk(reason))`, memory unchanged. Success → replace `state`,
   answer `Ack { view: ViewSeq::new(version + 1), stored: Written, tokens: [TokenUpdate {
   record, token: mint(version + 1) }], new_conflicts: stale ? [ConflictBrief { conflict:
   ConflictRef(hex(SHA-256(field ‖ 0 ‖ (version + 1) as decimal))), record, by: PersonLabel {
   who: Who::Mine, computer: None } }] : [], saved: [SavedValue { record, text }], rows: [],
   disk_warning: None }`.

`record` = `RecordRef::parse(&serde_json::to_string(&json!({"field": name, "kind":
"testField"})))` (the field name has no control character, so it parses).

`log(field)`: `FieldLogView { current: Shown { value, token: mint(version), marker: None },
stores }`; an unknown field answers version 0, value "", its token, no stores (that is how a test
field starts). `load` with a `fields.json` that does not parse → `Err` (start fails; never
overwrite a file the hooks cannot read).

## 4. Invariants (the verifiers will attack these)

1. **No write runs twice for one request id**, while it runs, after it finished, or when its
   caller went away; a retry with another body is refused, never answered with the first reply;
   a write whose task was lost is never run again under its id.
2. **No write stops half way because a connection dropped** (D4); `test/quiet` sees it until it
   ends.
3. **A refusal that changed nothing and needs a resend is never cached** (D3), and neither is a
   body that does not parse.
4. **`test/fieldStore` is durable before its `Ack`**: a crash before the reply keeps the text, a
   crash before the store keeps nothing, a store held or queued when the App ends is never
   written (D12), and a disk failure changes neither the file nor memory.
5. **The test log never loses or duplicates a text**: a retry adds nothing, an unchanged text
   adds nothing, every other store adds one line, and a store over an older version is marked
   `stale`, never silently `current`.
6. **An unchanged store never moves the field's token forward** (D7), so a newer version is
   never replaced without a conflict.
7. **Every text is compared and stored in NFC.**
8. **Prefs never lose a member** (built): unknown and malformed members are kept; a failed write
   keeps the value and is reported; a failed app-language save changes nothing and is refused.
9. **Progress counts never fall within a phase; no `Running` frame follows `Cancelling` or a
   terminal frame; a job's end is published at once; nothing before 300 ms** (built).
10. **No frame is lost or repeated between a replay and the live stream**; a reader the ring
    cannot serve gets `Resync` (built). An event a command causes is published before its reply.
11. **Flows**: no two passes that exclude each other are ever held together (built).
12. **The projects folder** is never moved from a folder that exists; nothing is created except
    at a first launch; a named folder is used as named and never created (D13).
13. **No lock is held across an `.await`** except the test fields' writer lane, which is an async
    mutex by design; no lock is held while a job's work runs; reads never wait behind a held
    store.
14. **The Door43 token never reaches the UI, a report or a log**; the keychain is read once per
    launch.
15. **No test hook in a release build**: everything in `hooks.rs` is behind `test-hooks`;
    `cargo clippy -p tc-app --lib` builds without it.

## 6. Traps

1. **Paused tokio time auto-advances** when every task waits on something other than a timer.
   In paused tests, never `.await` a channel or a `Notify`; step with `tokio::time::advance` plus
   `yield_now`, read with `try_next` / `try_recv` (`common.rs` has `settle` and `step`). Tests
   with real waits (holds, concurrent `net/set`, retries in flight) use a multi-thread runtime
   without pause.
2. **`spawn_blocking` under a paused clock**: the blocking pool is real time; a paused test that
   stores into a test field must yield until the store returns, or use an unpaused runtime. Use
   unpaused runtimes for every `field_store.rs` test.
3. **Feature unification**: the self dev-dependency turns `test-hooks` on for every test build
   and for `cargo clippy --workspace --all-targets`. Only `cargo clippy -p tc-app --lib` sees the
   library without it.
4. **Step order for the router**: with the feature on, `test_hook_table!(router …)` needs every
   `test/*` handler, so add that line in step 9, not step 8, or step 8's tests do not compile.
5. **`Reply::<()>::Err(e)`** serializes an error for any endpoint; do not try to name `E::Ok`
   when the body did not parse.
6. **Requests refuse unknown keys at any depth** (`deny_unknown_fields`), so a parse error is a
   normal `BadRequest`, not an internal error.
7. **The digest is of the re-serialized request plus the path** (built): digesting raw bytes
   would call a whitespace-different resend "another body".
8. **`AfterReply` is the server's job**: tc-app only says `Then::EndProcess`, and only to a
   `Fresh` answer.
9. **A crash hook must not fire on the request that armed it**: exclude the arming hooks, and
   refuse them as `path`.
10. **`std::process::exit` in `ExitProcess`** ends without destructors; that is the point. Never
    call it outside `test-hooks`.
11. **`HostEnv` on Linux cannot make a Windows path with backslashes**: assert components, not
    strings (built tests do).
12. **`TestApp` must not see the machine's real variables**: build `HostEnv::new(HostOs::Linux,
    [("HOME", …), ("USERPROFILE", …), ("XDG_DATA_HOME", …)])` with only the temp paths, never
    `HostEnv::current()`, or a developer's OneDrive variable changes the result.
13. **`hmac::verify` needs the full tag**; do not truncate it (no hand-written constant-time
    compare needed).
14. **`watch::Receiver::has_changed`** is `Err` only after the sender dropped; use it for F1, not
    `borrow().is_none()` (a running write's value is `None` too).
15. **`account/state` must not read the keychain per call**: an OS keychain can prompt the person.
16. **`LocaleId` parses only the ten ids** (built): a stored `"EN"` reads as English and stays.
17. **`endpoint_table!` passes prefix tokens before the rows**; `router!` must be defined above
    the invocation in the same module.
18. **Merging phase0** (if A2 has merged): conflicts are expected in
    `crates/tc-api/tests/golden.rs` (the `use tc_api::test::{…}` line: keep both lists, ours adds

## Changes made while building steps 8 to 10 (after revision 2)

A review of the built steps found five points where the plan lost, hid or misreported work.
They were fixed with tests written first; the design text follows them.

1. **D3 amended: the internet check moved into the reply cache.** The dispatcher answered
   `NeedsInternet` before the cache for every request. `NeedsInternet` says nothing was sent
   (§3.5), so a retry of a write that had run, after the switch went off, got a refusal that said
   it never happened. `ReplyCache::run` now takes `refuse: Option<ApiError>`; it applies only to
   an id the cache has not seen, in one step under the cache's lock, and keeps nothing.
   `CacheAnswer::Refused`. Tests: `a_retry_of_a_net_write_that_ran_gets_its_reply_not_needs_internet`,
   `a_refusal_of_a_new_id_runs_nothing_and_keeps_nothing`, `a_refusal_never_applies_to_an_id_that_was_sent`.
2. **D8 amended: the local folder beside a default one.** The plan's "known edge" (a default
   folder made by hand after a first launch chose the local one hides the local folder's
   projects) broke "never hide a translator's work". When both folders exist the local one is
   used (`RootChoice::LocalBesideDefault`), and the report names the default folder as not
   listed. When `XDG_DATA_HOME` makes the two paths one folder, it is `Existing`.
3. **D11 amended: `test/reset` also forgets the kept replies** (`ReplyCache::forget_settled`),
   keeping writes still running, so a request id can be used again in the next scenario and a
   retry of a running write still waits for it.
4. **`test/crash` with `at: duringDraftWrite` is a bad request** (`field: "at"`) in phase 0:
   no write reaches it, so an arm would let a crash test pass by doing nothing. The unit that
   adds draft writes accepts it.
5. **A retry never takes an `AfterReply` crash** (commit `ceb2514`): only a first attempt's
   reply can end the process after it.
