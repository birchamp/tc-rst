## 1. What A7 is, and what it is not

A7 builds, in `parity/view-gallery/`:

1. a Vite app that mounts tC4's real `src/App.jsx` from a tC4 clone with `src/state.jsx` replaced
   by a stub, built by the clone's own toolchain as tC4's release build is;
2. a recorder that drives real tC4 against the baseline's mock (`env-tc4.mjs`, the driver) and
   saves its whole `s`, plus the replies of the actions a view calls on mount;
3. the case format: a recorded state, a patch, steps, and a slot for the tc-api replies;
4. the action recorder: every `actions.*` call with its arguments, saved per case;
5. the cases of §7.4 (68 cases in 18 groups, §6 below), captured as tC4 draws them: PNG, DOM and
   action trace, with the same capture rules as the baseline;
6. the gate's side: `parity/app/cases.json` lists every case, `screen_record.rs` gives each a row
   in `report.json` that names the unit capturing each layer, and checks the case files.

What A7 is **not**:

- It ports no screen and captures no Rust side. Every case row is `unported`, naming the unit of
  its §7.4 group (B11, B8, B3, C8, B4b, A5, A8, E1b, F1, C6, G1, B5a, B6, B2, B9b).
- It records no tc-api reply. `MemoryBackend` is B1b's, and the view types of a screen are built by
  that screen's unit (§10 introduction), so A7 defines the reply slot and each porting unit fills it
  (decision D4, design text in §12 of this plan).
- It writes no translator data. The recorder writes only into the mock's throw-away
  `parity/tc4-baseline/.state/<scenario>` (rebuilt for every state); the gallery writes nothing at
  run time. Never write into the tC4 checkout, into `fixtures/`, or outside the worktree and your
  scratchpad.
- It does not touch tc-store, tc-journal, the storage branch or its worktree.

The no-loss rule still shapes the work: a case whose page logs an error, shows the view-error
callout, sends a request, mounts nothing or fails a step is a failed capture that is never
committed, so a broken render can never become "tC4's reference".

## 3. Decisions (record each in the A7 row note, step 7)

- **D1. Recorded states.** A case starts from the whole `s` of real tC4, read from its React tree
  after the driver took it, against the baseline's mock, to a baseline screen or a few steps
  further. The recorder also calls the read-only actions a view calls on mount and whose reply it
  draws (`readPrintStories`), and saves the replies. A case's patch is the `set` patch tC4's reducer
  would apply, written only for what the mock cannot reach (a release upgrade, a failed share step,
  a check list with no items), and built from the recorded values wherever it can be. *Why:* §7.4's
  "a tC4 `s` fragment" over nothing would be a hand-written fixture for every case, which risk 17
  warns against; the mock reaches 23 of the states the cases need.
- **D2. Calibration.** Every recorded state is rendered with no patch and compared with real tC4's
  own capture at the moment it was recorded: PNG byte for byte, DOM after the gate's id
  renumbering. A state that does not calibrate is not used. *Why:* it proves the stub (the `useApp`
  value, the derived `book` and `sourceModel`, the CSS, the focus rule) adds nothing, so a case
  differs from tC4 only by its patch and steps.
- **D3. tC4's own toolchain.** The gallery builds with the clone's own Vite, React plugin, node
  polyfills and React (a `node_modules` link to the clone's), in release mode with base
  `/clients/uw-tc4/` and tC4's `__APP_VERSION__`/`__APP_COMMIT__` defines, like `npm run build`.
  *Why:* `import.meta.env.DEV` false gives the production `DCS_SERVER` and no Inspector, as in the
  baseline; the same base gives the same asset URLs; the same packages need no second lockfile.
- **D4. Replies.** A7 defines the slot (`parity/view-gallery/replies/<case>.json`) and its format;
  each case's porting unit records the replies there, from `MemoryBackend` where the state exists
  and by hand where it cannot. *Why:* `MemoryBackend` is B1b's and each screen's view types are its
  unit's (§10 introduction), so no reply can exist at A7.
- **D5. Case rows.** A case belongs to a §7.4 group; the group's DOM unit and pixels unit are the
  case row's `missing` units. A group whose DOM unit comes first is DOM-first, as in §7.6: its cases
  carry a `scope` (the dialog) that the DOM layer compares until the pixels unit captures the case
  whole. A case's pixels compare with the gallery capture's machine (`cases.json` `machine`), not
  the baseline's. The gate checks every case file by sha256 and refuses stray files under
  `parity/view-gallery/{screens,dom,actions}`. A case has no meaning layer.
- **D6. Selectors.** The stub answers two actions with tC4's own code because a view calls them
  while drawing: `sourceGateways()` and `installedCountFor(g)` (`state.jsx:4195-4200`; Get source
  texts crashes without them). `stagedNote` answers `undefined` (no comment is staged in a fresh
  render). Every other action records its call and returns `undefined` unless the state or the case
  gives a reply.
- **D7. Focus.** Before mounting, the capture clicks a full-window `tabindex="-1"` layer at the
  pointer's resting point and the page removes it, as the DS gallery clicks its frame
  (`parity/ds-gallery/protocol.mjs` `captureCase`). *Why:* measured: without it, focus a view moves
  on mount draws a keyboard ring that tC4, after the click that opened the screen, does not.
- **D8. M18.** M18 is "Remove all the text of section …?" (`SectionEditor.jsx:244-255`, tC4 #600),
  the only dialog Translate has. B4a's row names M18, but only the section editor draws it and B4b
  builds the #600 question, so the M18 group names B4b, and B4a's row gets a note.
- **D9. Rust captures of cases.** `capture-rust.mjs` drops every `kind: case` entry when it rewrites
  `captures.json` (it maps `SCREEN_LIST`); A7 makes it keep them and capture a case through a Rust
  route (`--case`). A case whose state route uses only the driver and that has no patch gets that
  route plus its steps by default. `measure-masks.mjs` crashes on a mask rectangle named after a case
  (`SCREEN_LIST.find(...).scenario`); A7 makes it skip case names, and the gallery capture measures
  case rectangles.

**`lib.mjs`** (no imports; runs in Node and, through `page.evaluate` or the bundle, in the page):

```js
/** Tags for values JSON cannot carry. An object with exactly one key from TAGS is a tag. */
export const TAGS = ['$u8', '$part'];

/** Walks `value`; returns { value, refused } where refused lists "<path>: <why>" for anything
 * that is not plain JSON: undefined (as a property or in an array), functions, symbols, bigints,
 * non-finite numbers, Map, Set, Date, class instances, cycles, strings starting with "blob:",
 * and plain objects whose only key is a tag name. Uint8Array becomes { $u8: <base64> }.
 * Self-contained (no closure over module scope), so page.evaluate can ship it. */
export function encodeValue(value) {}

/** The inverse in the page: { $u8 } -> Uint8Array (atob). Other values unchanged. */
export function reviveValue(value) {}

/** tC4's reducer `set`: { ...s, ...patch }. `patch` is a plain object. */
export const applyPatch = (s, patch) => ({ ...s, ...patch });

/** The `actions` object of the stub: a Proxy whose `get` returns ONE cached function per name
 * (tC4's actions object is made once, `useMemo(..., [])`, and views put actions in effect
 * dependencies), undefined for symbols and for 'then'. Each call runs record({ name, args })
 * then answers: selectors[name](s, args) when there is one; else returns[name]:
 * { value } -> value, { resolves } -> Promise.resolve, { rejects: message } ->
 * Promise.reject(new Error(message)), { pending: true } -> a promise that never settles;
 * else undefined. */
export function makeActions({ s, returns = {}, selectors = {}, record }) {}

/** Arguments as the trace stores them: React synthetic events -> { $event: type }, DOM nodes ->
 * { $node: nodeName }, functions -> { $fn: true }, undefined -> { $undefined: true },
 * Uint8Array -> { $u8len: n }, cycles -> { $cycle: true }, deeper than 6 -> { $deep: true }. */
export function traceArgs(args) {}

/** The gate's DOM id rule (APP-DESIGN 7.3 layer 2): tc-(f|g|dlg|cfm|rg)N renumbered per prefix by
 * first appearance, across the lines in order. */
export function renumberIds(lines) {}

/** What calibration compares of a domSnapshot: [html, outside, renumberIds(root), styles]. */
export const domDigestInput = (dom) => JSON.stringify([dom.html, dom.outside, renumberIds(dom.root), dom.styles]);
```

`SELECTORS` take `(s, args)`; `makeActions` passes the mounted `s`.

**`virtual:tc4-state-exports`** comes from a small Vite plugin in `build.mjs`: it reads
`<TC4>/src/state.jsx`, takes the exact source text of `export const SCRIPT_FONTS = [ … ];` (regex
`/^export const SCRIPT_FONTS = \[[\s\S]*?^\];$/m`) and of `export function isOldTestament(…) { … }`
(`/^export function isOldTestament\([\s\S]*?^\}$/m`), prefixes
`import { BOOK_NAMES } from '@tc4/src/data/bookNames';`, and serves that as the module (the usual
`resolveId` to `'\0virtual:tc4-state-exports'` and `load`). The build
fails when either is not found exactly once. So the stub carries no copy of tC4 code except the
6-line `model` memo and the two selectors, which calibration covers.

**The state-file plugin** (`stateStub`), `enforce: 'pre'`: in `resolveId(source, importer,
options)`, for any `source` ending in `state.jsx` or `/state`, resolve it with
`this.resolve(source, importer, { ...options, skipSelf: true })`; when the result is
`<TC4>/src/state.jsx`, return the stub's path. Its `load(id)` throws if `<TC4>/src/state.jsx` is
ever loaded, so no import path can bypass the stub (verified: the build passes and never loads it).

## 7. Invariants and edge cases

- **Nothing is a request.** The gallery's pages may load only their own static files; every other
  request is aborted and fails the case. tC4's `guardFetch` is not installed and is not needed.
- **The stub never runs tC4's provider effects** (boot reads, schedulers, the ops log): a fresh
  render of a state must not change it.
- **One function per action name**, and one `actions` object per mount, as tC4's `useMemo(..., [])`
  gives (`state.jsx:7329`); otherwise effects keyed on an action run again every render.
- **StrictMode in a production build**: effects run once, as in tC4's release build; the trace is
  deterministic.
- **Module counters** (`tc-f`, `tc-dlg`, …) restart with every page; each case gets a fresh page.
  The gate renumbers them anyway (A6b D4).
- **Patches are shallow**, as tC4's reducer `set` is: a nested slice (`upgrade`, `sh`, `im`, `fb`,
  `gatewayPreview`) is written whole, spread from the recorded slice. `upgrade` keeps every key of
  `UPGRADE_IDLE` (`state.jsx:98`).
- **Never put a live object in a patch**: tC4's real upgrade preview holds `store` (a
  `JournalingStore`, `state.jsx:4582`); the view does not read it, so the case has none.
- **Dates and times**: the context is `en-US`, `UTC` (`CONTEXT_OPTIONS`), so `toLocaleDateString`
  in the conflict review is stable. `OpenProgress` is the only view that reads `Date.now()`;
  `startedAt: 0` makes it show at once whatever the clock.
- **Images**: OBS pictures would be mock URLs; the sample has no picture pack, so S12 shows text
  only and makes no request. The recorder refuses a `blob:` URL anywhere in a state.
- **A case named like a baseline screen** would share `parity/app/screens/<name>.png` with it on
  the Rust side: refused (node test and `DuplicateRow`).
- **Units that land before A7 merges**: if A5, A8, B2 or any group unit is in `units.json` when A7
  merges, the gate fails with `LayerOverdue` for that group's cases. None of them has landed at
  `4b88ff2`; the merger must check, and the unit that landed then captures its cases with
  `capture-rust.mjs --case` (or the merge waits).
- **Recording isolation**: one fresh mock environment per state; never run the recorder beside
  `capture.mjs` or `measure-masks.mjs` (shared `.state`).
- **No translator data** is written outside the throw-away mock state; the tC4 clone is only read
  (Vite's cache is in `parity/view-gallery/.cache`).

## 10. Traps found

   `npm ci` in the read-only checkout (`env-tc4.mjs` `buildClient` would, if `TC4_ROOT` pointed
   there).
2. `TC4_ROOT` must always be set: every default path in the harness is `/home/user/…`.
3. tC4's `node_modules` has Playwright **1.61.1**. With the `node_modules` link in
   `parity/view-gallery`, a bare `import 'playwright'` there gets the wrong one (wrong Chromium
   build, other pixels). Use `loadPlaywright()` and assert 1.56.1.
4. `node_modules/` in `.gitignore` does not match a symlink named `node_modules`; write
   `node_modules` without the slash in `parity/view-gallery/.gitignore`.
5. Top-level `await` in `src/main.jsx` fails the Vite build.
6. Without the click on a focusable layer before mount, focused rows draw keyboard rings (D7).
7. `src/views/Align.jsx` holds a NUL byte (`wordKey`, the `\x00` separator), so plain `grep` calls it
   binary and prints nothing; use `grep -a`.
8. `about.ts` needs `__APP_VERSION__` and `__APP_COMMIT__` defined and imports `LICENSE?raw` and
   `COPYING?raw` from the tC4 root; the build handles them, a dev server would need `server.fs.allow`.
9. Get source texts calls `actions.sourceGateways()` while drawing, and a modal is outside tC4's
   `ViewBoundary`: without the selector the whole page goes blank (D6).
10. `capture-rust.mjs` drops case entries and `measure-masks.mjs` crashes on a case rectangle (D9).
11. The gate's old `Case` had one `until` for both layers, paths relative to `parity/`, no hashes,
    and compared case pixels with the baseline's machine; `Paths::parity()` existed only for it.
12. `an_identical_capture_is_same_on_every_layer` asserts `unported == 60`; it must count cases.
13. A recording is not reproducible byte for byte (timestamps); the committed states are the
    reference and the byte test is on the gallery capture.
14. The mock's `.state` and port are shared with the baseline capture: one tool at a time.
15. `generated ids` differ between the gallery and real tC4 after a longer navigation
    (`source-texts`: `tc-dlg2` there, `tc-dlg1` here); calibration compares DOM after renumbering,
    as the gate does.
16. The conflict review's dates are the recording run's; the Rust side (B11) must seed the
    versions with the `ts` values in the committed state (`s.verseConflicts`), or its dates differ.
17. The `home-open-error` text contains tC4's repo path (`_local_/_local_/sample_burrito`); the

18. tC4 seeds a conformance sample's journal on its first open, so the outside file of
    `home-open-error` must be written after one open, or the seed takes it in.
19. The production React build strips most dev warnings, so "no console error" catches thrown
    errors and failed loads, not missing keys.
