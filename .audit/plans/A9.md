## 1. What A9 is, and what it is not

**Is.** tc-resources gets a seeding that says up front how much it will do and can be watched
and stopped. tc-app opens the machine's resource store at start, plans seeding from receipts
alone, runs the plan as the `Seed` job, mirrors the job into `Startup` events and `hello.startup`,
and cancels and waits for the job when the app quits (the shell's Close is a quit). `tc4 serve`
gets `--bundle <dir>`. tc-ui gets `app/prepare.html`, tC4's preparation window with its words as
rebuild keys in English (nine languages pending). A Playwright script proves the window and
Close. A count test proves PERF's targets, and a measurement records how long a first launch
takes here.

**Already done, do not redo.** The join of A2 and A3: A3 merged second and joined them in
`crates/tc4/src/join.rs`; `crates/tc4/tests/join.rs::tc4_serve_answers_hello_with_real_state`
proves it (§10 order paragraph, "(A3: … Done …)"). Nothing to do but keep it green.

**Not A9.** Seeding from the shipped archives instead of an expanded bundled store (DELTA §3.6
item 3, "packaging"); the shell's prep window, its single-instance lock and its close handler
(G1); a UI boot that sends a page to `/prepare.html` (A5, see D10); any new endpoint (A9 adds
none); changing tc-resources' rules for refused or damaged installs; touching the `storage`
branch or `.claude/worktrees/storage`; touching `crates/tc-resources/src/dcs.rs` (the storage
team changed `install_all` there).

## 2. Decisions (record each in the design, §8 of this plan)

- **D1. Plan at start, from receipts only.** `App::start` opens `<app_data>/resources` (STORAGE
  §3.7) with `ResourceStore::open` (which clears `.partial/`), then, when `--bundle` names a
  bundled store, calls `ResourceStore::seed_plan`, inline, before it returns: it reads receipts
  and check records, never a content file. So `hello.startup` is exact from the very first
  request: `Ready` when there is nothing to copy or check (a repeat launch: no job, no frame, no
  report), `Preparing { done: 0, total }` with `total` in content files when there is, and
  `Failed { reason }` when the plan cannot be made. Without `--bundle` nothing is seeded and the
  state is `Ready` (development, tests, and the parity captures, §7.2, Q-11).
- **D2. The tc-resources hooks.** `seed_plan(&self, bundled) -> Result<SeedPlan, StoreError>`
  and `seed(&self, plan, &dyn SeedWatch) -> Result<Seeding, StoreError>`, where `SeedWatch` hears
  `done(files)` after each content file is checked or written and is asked `cancelled()` before
  each install and before each file; `Seeding` is `Finished(SeedReport)` or `Cancelled(SeedReport)`.
  `seed_from` stays, as plan then seed with a watch that never stops, so its tests and callers are
  unchanged. A thread-local `content_files_written()` joins `content_files_opened()`, so PERF's
  "writes each installed file once" is a count, not a guess.
- **D3. The count is files.** "Preparing resources: n of total" counts content files, as A1's
  golden `hello.json` already shows (`1200 of 3739`) and §4.6's Seed row says. Declared difference
  from tC4, which counts its 16 resources (`desktop-bootstrap.cjs:236`): one resource is up to
  1,021 files written with an fsync each (`en_tw`), so on the reference laptop a count of
  resources would stand still for many seconds, and PERF rule 4 asks for a count that grows.
  The words are tC4's.
- **D4. Startup follows the job.** The `Startup` frames carry the Seed job's own reports (none
  before 300 ms, then at most one per 100 ms, §4.6), through a new `JobRegistry::watch(id)`. The
  state only moves forward: `Preparing` counts never fall, and `Ready` or `Failed` is final for
  the run, so the reporter's last `Running` frame, which comes after the job's own end, can never
  show preparing again. The ring keeps only the newest `Startup(Preparing)` frame, as it keeps
  only the newest `Running` frame of a job (§5.4).
- **D5. Close is a quit, and a quit cancels.** On Close the shell asks `tc4` to quit (§6.5, "The
  close guard"; G1). `App::quit` cancels the Seed job and waits until it has stopped, before it
  flushes prefs, all inside the server's 5 s close (§5.1), so `tc4` lets go of `app.lock` only
  when no seed writer runs (DELTA §3.15.10: "keep the single-instance lock until no writer can
  write"). The seed stops before its next file. Every copy finished before the stop stays whole
  and checked; the copy being made is not in the store, its files stay in `resources/.partial/`
  until the next start's `ResourceStore::open` removes them (as tC4's next launch removes its
  staging, `desktop-bootstrap.cjs:228`); the next launch copies only what is missing and reads no
  copy made before. `jobs/cancel` of the Seed job does the same without quitting; the state then
  says `Failed` until the next launch.
- **D6. Failures stop the start, as in tC4.** A copy whose receipt cannot be read or names
  another resource (found by the plan), a copy that fails its check, a bundled install that fails
  its own check (`SeedReport::refused`), or a bundle folder that cannot be read: `Startup::Failed
  { reason }`, a `seed` report with the reason, and the window shows tC4's failure words ("translationCore4
  could not start", "The bundled resources could not be prepared. Please quit and try again.") with
  the reason under them. tC4 shows those words in a native error box and exits
  (`desktop-main.cjs:175-181`); here the server is the one that seeds, so its window shows them
  in the person's language, and the person closes it. Declared difference; the failure state is
  new design and goes to the owner with its screenshot (Q-9). tc-resources keeps its rule that a
  refused bundled install does not stop `seed_from` (the other installs are still copied); the app
  turns a non-empty `refused` into `Failed` after the copies end (DELTA §3.6 item 3:
  "A damaged bundled install must stop the start, as in tC4").
- **D7. One self-contained page.** `/prepare.html` is `crates/tc-ui/app/prepare.html` (beside
  A4a's `app/index.html`; never under `assets/`, which holds only tC4's files). It is tC4's
  `desktop-preparing.html` (same markup, CSS, title and words) plus: a JSON block with the
  `prepare.*` text of all ten languages (English; nine pending, Q-10), generated from
  `assets/i18n-rebuild/` and checked by `crates/tc-ui/tests/prepare_page.rs`; one inline script
  allowed by a `sha256` source in its own CSP meta (the server sends no CSP for this route); the
  script reads `app/hello` and the event stream, shows the saved app language with English per
  key as tC4's `t()` does, sets `<html lang dir>`, and goes to `/#t=<token>` at `Ready`. It shows
  counts only, never resource names, as tC4's page (`desktop-prepare.cjs:43-45`).
- **D8. Flags.** `tc4 serve --bundle <dir>` names the bundled store the installer ships (read
  only). `--test-seed-pace <ms>` exists only with the `test-hooks` feature: the seed waits `<ms>`
  before each file, so the process tests and Playwright can watch and close a seed on any disk.
- **D9. The bundled store.** The installer still ships an expanded store (`seed_from`'s input);
  shipping archives stays with packaging (DELTA §3.6 item 3). `crates/tc-app/examples/bundle_store/`
  builds that store from `bundle/en` with tc-resources' own installers (`install_dcs_zip`,
  `install_lexicon_zip` against `fetched.lock`): the core of the packaging step, used by the tests,
  the Playwright script and the measurement.
- **D10. Who opens the window (a contract; not built here).** The shell (G1) opens
  `/prepare.html#t=<token>` when `hello.startup` is `Preparing` and still is 300 ms later, and
  `/#t=<token>` otherwise, so a repeat launch shows no window (PERF rule 4; tC4 shows its window
  on every packaged launch, until its main window is ready). A UI page that boots while
  `hello.startup` is not `Ready` goes to `/prepare.html` with its fragment (A5's `App`, which owns
  the root). The Seed job's failure is `JobState::Failed(ApiError::Internal { report })`, the
  report being the `seed` report: no refusal family describes a damaged resource copy, and
  "Ask for help" attaches that report.

```rust
/// Who watches a seeding (APP-DESIGN §4.6): hears how many content files are done, and is
/// asked whether to stop.
pub trait SeedWatch {
    /// After each content file is checked or written: the files done so far. It only grows,
    /// and reaches [`SeedPlan::files`] when the seeding finishes.
    fn done(&self, files: u64);
    /// Whether to stop. Asked before each install is copied or checked and before each of its
    /// files (never between the last file of a copy and its receipt: a copy whose files are
    /// all written is finished).
    fn cancelled(&self) -> bool;
}

/// What seeding must do, found from receipts and check records alone.
#[derive(Debug, Default)]
pub struct SeedPlan {
    steps: Vec<SeedStep>,
    files: u64,
    /// `already_installed` and the unreadable bundled folders (`refused`) are known now.
    report: SeedReport,
}

#[derive(Debug)]
enum SeedStep {
    /// The store lacks this bundled install: read it from the bundle, check it, copy it.
    Copy { install: Installed, name: String },
    /// The store's copy was not checked against its present receipt: check it again.
    Check { copy: Installed, name: String },
}

impl SeedPlan {
    /// The content files seeding will open: each file of every copy to make and of every copy
    /// to check again.
    pub fn files(&self) -> u64;
    /// Nothing to copy or check. The report may still list refused bundled folders.
    pub fn is_empty(&self) -> bool;
    pub fn report(&self) -> &SeedReport;
}

/// How a seeding ended.
#[derive(Debug)]
pub enum Seeding {
    Finished(SeedReport),
    /// The watch asked to stop. Every copy in `added` is whole and checked. The copy being made
    /// is not in the store; its files are under `.partial/`, which the next
    /// [`ResourceStore::open`] removes. Seeding again copies what is missing.
    Cancelled(SeedReport),
}

impl ResourceStore {
    /// What [`ResourceStore::seed`] would do, without opening a content file: a repeat start
    /// reads receipts and check records only (tC4 #740).
    pub fn seed_plan(&self, bundled: &ResourceStore) -> Result<SeedPlan, StoreError>;
    /// Does `plan`. Errors as `seed_from` errs.
    pub fn seed(&self, plan: SeedPlan, watch: &dyn SeedWatch) -> Result<Seeding, StoreError>;
    /// Unchanged signature and doc; now `seed_plan` then `seed` with a watch that never stops.
    pub fn seed_from(&self, bundled: &ResourceStore) -> Result<SeedReport, StoreError>;
}
```

`seed_plan`: `bundled.installed()?`; each unreadable folder →
`report.refused.push(("an unreadable bundled install".to_owned(), e))`; for each install in
order, `name = install.origin().describe()`; `self.find(install.origin())?` →
`Some(copy) if copy.is_checked()` → `report.already_installed.push(name)`; `Some(copy)` →
`files += copy.receipt.files.len()`, `Check`; `None` → `files += install.receipt.files.len()`,
`Copy`.

`seed`: `let mut done = 0u64;` for each step, first `if watch.cancelled() { return
Ok(Seeding::Cancelled(report)) }`, then:

- `Check`: a private `Installed::check_listed_watched(&self, watch, done: &mut u64) ->
  Result<bool, StoreError>` (the loop of `check_listed`, with `if watch.cancelled() { return
  Ok(false) }` before each file and `*done += 1; watch.done(*done)` after it); `false` →
  `Cancelled`; then `copy.record_check()?`, push to `checked_again` and `already_installed`
  (today's order of fields).
- `Copy`: `count = install.receipt.files.len()`, `base = done`. `read_all_checked()` error →
  `refused.push((name, e))`, `done = base + count; watch.done(done)` (the count still reaches the
  total), continue. Else `install_until(staged, &mut |step| …)` with: on `FileWritten(n)` call
  `watch.done(base + n)`, and when `n < count && watch.cancelled()` set a local `stopped = true`
  and return `true`; every other step returns `false`. Then `done = base + count`. Result:
  `Ok(_)` → `added`; `Err(Interrupted) if stopped` → `return Ok(Cancelled(report))`;
  `Err(InstallError::Store(e))` → `return Err(e)`; other errors → `refused` with
  `StoreError::BadReceipt { path: install.dir.clone(), problem: other.to_string() }` (as today).

`seed_from` keeps its doc comment; add one sentence: "[`ResourceStore::seed_plan`] and
[`ResourceStore::seed`] are the same seeding in two steps, with progress and a stop."

Invariants: no existing install is ever written (only `install_until` writes, and it returns an
existing copy untouched); a copy is visible whole or not at all; `done` only grows and ends at
`files()` on `Finished`; with an empty plan nothing is opened or written.

Change in order, and why it is safe: a copy whose receipt cannot be read or names another
resource now stops seeding at the plan, before any copy, where it stopped after the copies
before it. Both stop the start and change nothing in that copy; the `c29_*` tests that assert
`opens == 0` for those cases still hold.

`lib.rs`: `pub use store::{…, SeedPlan, SeedWatch, Seeding, content_files_written, …}`; in the
"Store" bullet add: "[`ResourceStore::seed_plan`] says from receipts alone what a first run must
copy, and [`ResourceStore::seed`] does it with a [`SeedWatch`] that hears each file and can stop
it."

```rust
//! The first-launch state `hello` answers and `Startup` events carry (APP-DESIGN §3.6, unit A9).

/// How preparation ended.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum StartupEnd { Ready, Failed(String) }

/// The next state, or `None` when the update changes nothing. Pure: `Preparing` counts never
/// fall, and `Ready` or `Failed` is final, so a late progress report never shows preparing
/// again after it ended.
pub(crate) fn advance(now: &StartupState, update: Update) -> Option<StartupState>;

pub(crate) enum Update { Progress { done: u64, total: u64 }, End(StartupEnd) }

/// The state, under one lock with its publication, so the last `Startup` frame always equals
/// what `hello` answers.
pub(crate) struct Startup { state: Mutex<StartupState>, bus: EventBus }
impl Startup {
    pub(crate) fn new(state: StartupState, bus: EventBus) -> Self; // publishes nothing
    pub(crate) fn get(&self) -> StartupState;
    pub(crate) fn update(&self, update: Update) -> bool;  // applies `advance`; publishes `Event::Startup` when it changed
}
```

total }`; a lower `done` → `None`; `End(e)` → `Ready` or `Failed { reason }`. (A3's app starts

```js
      const { done, total } = startup.value;
      if (shown?.type === 'preparing' && done < shown.done) return;
      shown = { type: 'preparing', done, total };
    } else if (startup.type === 'ready') {
      shown = { type: 'ready' }; ended = true;
    } else if (startup.type === 'failed') {
      shown = { type: 'failed', reason: startup.value.reason }; ended = true;
    } else return;
    render();
    if (shown.type === 'ready') location.replace(`/#t=${token}`);
  };

  if (token === null) {
    apply({ type: 'failed', value: { reason: 'This window was opened without its key.' } });
    return;
  }
  const headers = { 'X-Tc-Token': token, 'X-Tc-Api': '1' };

  const hello = async () => {
    const response = await fetch('/api/v1/app/hello', {
      method: 'POST', cache: 'no-store', body: '{}',
      headers: { ...headers, 'Content-Type': 'application/json' },
    });
    if (response.status !== 200) throw new Error(`HTTP ${response.status}`);
    const reply = await response.json();
    if (reply.type !== 'ok') throw new Error(JSON.stringify(reply.value));
    showLanguage(reply.value.prefs.appLocale);
    apply(reply.value.startup);
  };

  // The event stream, read with fetch (AD10): `id:` and `data:` lines, a blank line per frame.
  let after = 0;
  const listen = async () => {
    while (!ended) {
      try {
        const response = await fetch(`/api/v1/events?after=${after}`, { headers, cache: 'no-store' });
        if (response.status !== 200 || !response.body) throw new Error(`HTTP ${response.status}`);
        const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
        let buffer = '';
        while (!ended) {
          const { value, done } = await reader.read();
          if (done) break;
          buffer += value;
          let end;
          while ((end = buffer.indexOf('\n\n')) >= 0) {
            const block = buffer.slice(0, end);
            buffer = buffer.slice(end + 2);
            for (const line of block.split('\n')) {
              if (!line.startsWith('data: ')) continue;
              const frame = JSON.parse(line.slice(6));
              after = frame.seq;
              if (frame.event.type === 'startup') apply(frame.event.value);
              else if (frame.event.type === 'resync') hello().catch(() => {});
            }
          }
        }
        reader.cancel().catch(() => {});
      } catch { /* the server may be closing; try again */ }
      if (!ended) await new Promise((resolve) => setTimeout(resolve, 500));
    }
  };

  listen();
  hello().catch(() => {}); // the stream carries the state if hello fails
})();
```

## 5. Invariants (each is a test above; keep all of them)

1. Seeding writes only under `<app_data>/resources/` and never touches a project, a draft, the
   prefs or a report file; it opens no network connection (the bundle is local).
2. No install is ever rewritten: an existing copy is used as it is, or stops the start when it
   cannot be trusted (D6). A copy is in the store whole and checked, or not at all.
3. A stop (Close, `jobs/cancel`, a crash, a kill) at any point leaves only whole copies; the next
   start removes `.partial/` and copies only what is missing, without reading a copy made before.
4. `hello.startup` is exact from the first request; `Ready` means every bundled install is here,
   checked, and none was refused; `Preparing` counts only grow and `total` never changes in a
   run; `Ready` and `Failed` are final for the run; no `Startup(Preparing)` frame ever follows
   them.
5. A repeat launch opens and writes no resource content file, starts no job, sends no `Startup`
   frame and adds no report.
6. A quit during a seed returns only after the seed stopped (or the 5 s close cut it), so `tc4`
   holds `app.lock` while a seed writer runs.
7. The window keeps tC4's markup, CSS, title and English words; it shows counts, never names;
   its text follows the saved language with English per key; nothing but its hashed script runs.
