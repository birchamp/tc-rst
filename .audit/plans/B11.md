## Steps (each one commit, built and tested)

1. **tc-api.** `conflicts/list { at, tab }` (query): the tab counts and the tab's entries,
   each with its place, kind, group and versions (person or cause, mine, date, clock
   warning, value) and its review tokens; the Text tab is tC4's `verseConflicts` in one read.
   `conflicts/history { at, record }` (query). `conflicts/resolve { at, request, conflict,
   review, keep }` (command) → `Ack`. Goldens.
2. **tc-app `conflicts.rs`.** The list from `conflicts_of(kind)` per tab (a tab costs its
   conflicts), counts from `conflict_counts`, groups by batch set, labels from
   `person_labels`, the clock warning (a version dated more than 24 h after this computer's
   clock), detached records, the store's notices; History from `FoldState::history`;
   resolve through `StoreCommand::resolve` (scripted outcomes on the memory backend, the
   store otherwise; the reply cache gives a second send its first reply). Markers on Check
   rail rows and Align verses. Tests through `App::request`, the count row.
3. **tc-ui.** Port of `ConflictReview.jsx` (Text tab), shown in Translate as tC4 does; the tab
   strip only when another tab has entries; read-only lists for the other tabs; History;
   entries from Home's chip, the sync toast (closes once open), Translate's button and
   markers, Align and Check markers; Keep with one request id per choice, off in flight.
   Host tests: the `actorLabel` and `conflictReview` ports.
4. **Parity and journeys.** S4's three gallery cases through a Rust route; journey
   `conflict-review.test.mjs` with J18's UI steps on the store with a scripted sync.
5. **Docs.** B11's notes in the row (D-n), TC4-ISSUES rows, declared differences.
