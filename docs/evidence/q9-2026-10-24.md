# The H5 packet: review screens with no tC4 design (C7b step 2, Q-9)

tC4 4.0 reviews only verse text. These screens are new in the rebuild. None of their buttons
do anything yet. Each button is wired only after the owner signs the screens off (C7b steps 3
to 6). The pictures and the DOM of each screen are in `q9-2026-10-24/` (`<name>.png`,
`<name>.json`). `parity/app/q9-packet.mjs` made them on 2026-10-24.

The proposed screens are drawn by the test build's probe page from fixed data
(`crates/tc-ui/src/app/q9.rs`). Their words come from STORAGE §8.3 and §8.5. The words are in
English. They become translatable when the screens are wired. Names such as Ana, Juan, Maria and
Pedro stand for teammates. The review names a teammate by their Door43 username.

## Screens

- `alignments`: Titus 1:1 has two alignments, Ana's and mine. Each card says whether it was made for the current text. *Use this alignment* keeps that alignment. *Open in the aligner starting from this one* opens the aligner with it, and saving there settles the conflict. *Dismiss alignments made for text that was not kept* (over every alignment conflict) puts away each alignment made for text nobody kept. It stays in History.
- `checks`: one Translation Notes check where Ana and I selected different words. *Keep mine* and *Keep Ana's* keep one decision. *Choose per line* asks for one value for each part that differs, and keeps every part that agreed.
- `checks-moved`: Ana's upgrade moved a check to a new note while Pedro changed the old one. *Apply Pedro's change to the moved check* puts Pedro's changes on the moved check. *Keep Pedro's check where it was* keeps his decision on the old note. It then shows as needing a new check, and the moved copy stays.
- `checks-comment`: two versions of one comment. *Keep this one* keeps that text. *Keep both* joins the two texts, each with its author's name.
- `settings-pins`: Juan uses Translation Notes v93, and I use v92. Each card shows the counts first ("With v92: 1,204 checks valid, 37 to check again"). *Use v92* or *Use v93* moves the pin and carries the checks over in one step. It downloads the version first when it is missing. Nothing moves until the person chooses.
- `settings-setting`: two values of one project setting (script font). *Keep this one* keeps that value. *Edit* opens the setting with both values beside it. Project details, verse numbering, the order of a book's chapters and a computer's profile use the same card.
- `settings-books`: Juan restored Jonah with its text, and Maria brought Jonah back empty. *Restore the text* or *Start empty* decides. Every version of Jonah's verses stays in History either way.
- `settings-book-removed`: Maria removed Jonah while Juan changed four of its verses. *Restore Jonah* brings the book back with Juan's changes. *Keep it removed* removes it, and Juan's changes stay in History. *Show Juan's changes* shows them, read only.
- `settings-last-book`: Juan removed Titus, the project's last book. *Keep Titus* keeps it. *Add another book first, then remove Titus* opens the add-a-book step.
- `settings-carried`: Juan and I each replaced version 1 of `jon_01.wav`. *Keep this one* on each version keeps that file and removes only the other version of this conflict. *Keep both* keeps mine and saves Juan's as `jon_01-Juan.wav`, a name the project does not hold yet (H19, H22 part 2). There is no *Keep the other*.
- `settings-path-case`: `jon_02.wav` and `JON_02.wav` cannot both live in one folder on Windows or macOS. *Rename* on a file asks for a new name the project does not hold yet. Both files stay. *Remove* removes that file.
- `detached`: records with no place left in the project. *Show* opens where the record was. *Open in the aligner at Titus 3:15* opens an alignment there. *Dismiss* puts the record out of this list. It is kept.
- `notices`: one sentence each. *Apply what was recovered* applies the part of a teammate's set of changes that arrived. *Dismiss* takes a notice off the list. A kept copy's notice is D1's, not this screen's.
- `received`: the sheet after a sync or a file of work. "Received 212 changes from Juan and Ana. 3 verses, 1 alignment and 2 checks were changed by more than one person." It lists the notices. *Review now* opens the review. *Later* closes the sheet. Nothing is modal.
- `draft-offer`: at an open, "Unsaved text from your last session was found for Titus 1:4." *Keep it* saves that text. *Discard* drops it. The words and the choice exist (C1b). Until now no screen drew them.
- `read-only`: the banner over a project that may be open on another computer. *Copy the project* makes a copy to work on here. *That computer is closed* opens the project again with this computer as the one that saves. The words and the choices exist (C1b). Until now no screen drew them.
- `boot-error`: the app's own boot error, when the page and the app's server are different builds. It names both builds. *Retry* reloads the page.
- `bulk-keep`: the real review with two verses in conflict. *Keep all of Teammate 1's* (and *of Teammate 2's*) keeps that person's version in every conflict of the tab that one choice can settle, and says how many were left.
- `history`: the real History of Titus 1:1, with every version, its author, date and cause. *Restore this version*, on each version but the one shown, keeps that version over every version of the verse.
- `first-launch-failure`: the first-launch window when the bundled resources cannot be prepared. It shows tC4's words and the reason. It has no button: the person quits and tries again.
