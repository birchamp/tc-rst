## 1. Summary

**The reference stays at d310bf3.** tC4 has no v4.0.0 tag yet. Its release branch holds
rc.2 and every change below except the three newest Align fixes (#782, #787 and #788). Q32
asks which version the rebuild follows if v4.0.0 ships without them.

**What changed for translators in tC4.**

- Check: a Notes title and the ULT highlight name only the quote's own phrase (#773), also
  for Hebrew quotes with a maqaf (#765). Notes group by figure of speech, and every group
  folds (#769). On a wide window the source texts sit side by side (#762).
- Align: words inside nested alignments show, such as "the heavens" in Genesis 1:1 (#782).
  Cards keep their English label after a save (#768). A verse opens with the words of its
  current text in the word bank, and with "The draft changed" when the text changed (#787).
  A card click places only the words the bank shows as selected (#788).
- Import and Add a book: a project with no pins gets the bundled English source texts at its
  first open (#766). A file too large to save is refused in its own row, and no empty book is
  left (#767). tC4's journal pieces can now be up to 8 MiB (D104).
- Help and About: the help pages describe rc.2 (#763). The version is 4.0.0-rc.2 (#759).

**The rebuild already matches three of these:** the maqaf split (#765), the word bank built
from the current text (#787), and placing only the shown selection (#788). The last two match
the owner's rulings Q15 and Q16 of 2026-10-16, which tC4 has now adopted.

**Four of these changes show defects in rebuild code that exists today.**

- #773: four of tC4's five Genesis test cases give a Notes title with words from elsewhere
  in the verse.
- #782: the verse text drops words inside nested alignments. In a Psalms verse that keeps
  its markup, "Yahweh" is missing from Translate, Check and the Align word bank.
- #795 (still open in tC4): a word joins the next word after a footnote ("brotherwill").
  An imported alignment then loses two links when the verse opens.
- #787: Align never shows "The draft changed" when a verse opens, even when a teammate's
  change altered the text under the alignment.

The issue triages found 13 more defects, most of them in Align. `TC4-ISSUES.md` §1 lists all
17, each with its failing scenario and its regression test.

**Seven questions for the owner** are in §5 (Q30 to Q36). The ones that block work: Q30 (a
link that moves to another copy of a repeated word), Q32 (follow the v4.0.0 tag or tC4 main
for three Align fixes), and Q35 (what the new-project dialog offers for a language code a
Scripture Burrito cannot hold).

**What to do first.** On main now: the four defects above, then the other defects in
`TC4-ISSUES.md` §1 that sit in code that exists (tc-usfm, tc-helps, tc-align, tc-check,
tc-resources, the tc-ui Select, `Store::create`, tc-obs and tc-door43-fake). Before format
1.0 is frozen (unit V): the shown-text change (#782, #795) and the System cause for pins
written at open (#766). The rest belongs to I, C6, B5a, B5b, B6, B7, A5, A6a, and to the
vendoring of the catalogs when the reference moves.

### Corrections to the sweep and to DELTA-10-16

The verifiers checked every item. These corrections are used in the rest of this document.

- **#787, saving at open.** The commit sweep called two things a bug: no notice at open, and
  a carry-over that loses nothing being saved when the person leaves the verse. Only the
  first is a bug. The second is the rebuild's design: APP-DESIGN AD19 says "a lossless reflow
  is saved on leaving the verse", and the owner's Q-6 answer ("adjust it right away")
  supports it. Keep `a_carry_over_that_drops_nothing_is_saved_as_tc4_saves_it`. Record it as
  a declared difference, because tC4 writes nothing at open.
- **#789.** A link that moves to another copy of a word is a defect the rebuild fixes in any
  case: build the position diff. Only one part is for the owner: whether such an edit also
  marks the verse for review (tC4's ruling D106) or not (the owner's Q-6). See Q30.
- **#773.** The USFM triage called it a reference change. The check verifier showed that the
  rebuild is worse than both tC4 versions for these notes, because it added #765's maqaf
  split early without #773's fallback. So it is a defect today.
- **#782 reaches tC4 imports too.** STORAGE §13.1 converts tC4 4.0 verse events with
  `split_verse` only. Every aligned book that a tC4 4.0 user added from USFM therefore arrives
  with its markup inline, and about 41% of Genesis verses lose words there (633 of 1,533).
- **#793.** In the verifier's run, a memory trained on NFC records gave 12% fewer right
  suggestions (45 against 51 of 70), not 22%. The regression test asserts equal counts, not a
  percentage.
- **#766, timing.** Do not wait for the reference to move. At d310bf3 a USFM import already
  opens with "No resources pinned", which works against the feature (AGENTS.md "Matching
  tC4"). Build it in I, F1, E1b and C1a now, as a declared difference.
- **#767.** The owner accepted R3's fallback (AddBook, then one SaveSection per chapter) in
  APP-DESIGN Q-17. That fallback can leave a book of empty stubs that blocks every retry. A
  one-batch command replaces it; that is a change to Q-17, so tell the owner.
- **DELTA-10-16 Q12 and STORAGE §9.5.** Both say an HTTP 403 push reply means "no write
  access". Door43 does not answer 403. It answers 200, with "User permission denied for
  writing." and a declined ref (`docs/evidence/door43-live-2026-10-17.md` step 6).
  `tc-door43-fake` on main still answers 403. The fix is on the unmerged branch
  `origin/windows-push-refusal` (02300d9). Merged later on 2026-10-19: STORAGE §9.5 and
  DELTA-10-16 Q12 now give the measured reply, and the fake answers as Door43 does.
- **DELTA-10-16 Q11.** The rebuild retries a refused push six times within 30 s, not three
  times as tC4 does. Name unit X's test for six.

**Q30. A link that moves to another copy of a repeated word (#789).**
A verse often repeats a short word, such as "of", "de" or "the". Today, when a translator
adds or deletes an earlier copy of that word, an alignment link stays on "the second 'of'"
by number. That can now be a different word, and nothing warns anyone. The exported file
then carries the wrong link. tC4 4.0 does the same. The rebuild will fix this by following
each linked word by its position in the verse. The question is what else happens.

- (a) Follow each linked word by its position. If it is not clear where a word went, put
  that link back in the word bank and list it. Do not mark the verse for review. This keeps
  your earlier answer Q-6: "adjust it right away and do not flag it".
- (b) The same, and also mark the verse for review whenever an earlier copy of a linked
  word was added or deleted. This is your tC4 ruling D106.
- (c) Keep today's rule. A link can move to another word with no warning.

*Recommendation:* (a). With the position rule, the link stays on the right word, so there
is nothing left to review, and any unclear case goes back to the bank where the translator
sees it. Choose (b) if you want the rebuild to match tC4 once tC4 builds D106.

Answer: (a), owner, 2026-10-19. Follow each linked word by its position; an unclear link goes back to the bank and is listed; the verse is not marked for review (Q-6 stands).

**Q31. The tC4 version named in the help pages (#763).**

counts files), "the window shows only for a moment" (the rebuild shows no preparing page on

- (b) Keep the pages, but replace the banner's version line with the rebuild's own version,

- (c) Ask the tc-website team for wording that fits both apps.

*Recommendation:* (b) now, and (c) the next time the help pages change. Add a help test
that the banner names the same version as About.

Answer: (b), decided by the orchestrating session under AGENTS.md ("Matching tC4") and told to the owner, 2026-10-19: replace or hide the banner's version line, list the three install sentences as known differences, and test that Help and About name one version.
