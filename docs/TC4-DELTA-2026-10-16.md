## 1. Summary

**tC4 4.0 now syncs teams through Door43.** Decision D102 (2026-10-15) moved team sync round 1
(epic #24) and the Arabic interface (epic #658) into v4.0.0. There will be no rc.2 or rc.3.
On a shared Bible project the Home card now reads "Sync with Door43". One press gets the
teammates' changes, sends this computer's changes, and shows a toast with three counts, the
teammates' Door43 usernames, and a link to the verse-conflict review. A teammate on another
computer starts with a fourth "Add a project" card, "Open a project from Door43". tC4 marks
J17 (open from Door43), J18 (keep one version) and the new J26 (three translators sync one
project) as built. So PLAN's baseline, "the same outcome as tC4 4.0", now includes team
sync, open from Door43 and an Arabic interface.

**The rebuild keeps its own sync design and copies tC4's visible contract.** tC4 syncs
through a scratch clone, an apply marker, an ops log and recovery at start (D101). STORAGE
§9 has none of these, and that stays. What the rebuild must copy is what the translator
sees: the card button and its states, the internet question kinds `sync` and `open`, the
sign-in name notice, the result toast with its keys and test ids, the Add a project card and
the Open from Door43 dialog. Several tC4 messages say "Nothing changed" after a failed sync.
That is true in tC4, which applies nothing before a successful push. It is not always true
in the rebuild, which integrates received work before it pushes (§9.1 S6). Those cases need
their own keys.

**tC4 4.0 team data will exist from the first release.** Import (unit I) must read what the
tC4 sync leaves behind: v3 `actor.name.set` events, the reserved folders
`ingredients/tc4-sync/` and `ingredients/tc4-open/`, scratch copies under
`_local_/_archive_/`, an apply that stopped part way, a torn `metadata.json`, platform
stamps in `metadata.json`, and a local `.git` that diverges from Door43 `main`. Moving a
Door43 team from tC4 (STORAGE §13.3) becomes a main path, and Open from Door43 must handle
a tC4 team repository.

**Four screens changed in ways that touch code already on main.** In Align, the word bank
and each card's target words are now always in verse order, repeated words show their
occurrence number, and several bank words can be selected and placed in one edit. tc-align
on main keeps bootstrap order and drop order, so it must change now. In Check, a drag across
"Your translation" selects whole words, and Previous and Next moved into the marking row as
labelled pills. In Translate, an open editing card blocks every exit that would drop its
text. Home says "— in progress" until progress is known. Help no longer blinks white. Align
and Check now handle book text that arrives after the tool opened.

**Catalogs, startup and docs.** Each of the 10 catalogs grew from 942 to 1,029 keys, and
Arabic has 73 corrected strings. The rebuild must vendor the d310bf3 catalogs. tC4 now ships
its bundled resources as 16 archives, verifies each installed copy once, shows a preparation
window on first launch, and gates the release on a usable Home in under 60 s on a signed
Windows build with Defender on. The rebuild's `seed_from` still takes an expanded store, and
PERFORMANCE has no start budget. The parity baseline (42 screens at d494a9d) is stale for
Check, Align, Translate and Home.

**What to do first.** On main now: tc-align ordering, one-edit multi-place and the
selection rule; the `::selection` rule in tc-ui's base.css; BookTile `disabled`; the
props that tc-ui fixes at build and the new screens change at run time (Switcher option
`disabled`, AppHeader exits, Button `style`, `title` and `aria-busy`, Modal close); the
missing-pin count in tc-resources; the PLAN and PERFORMANCE edits; a recapture of the parity
baseline at d310bf3. The rest belongs to S1, S2, X, I, screen work and packaging. Section 5
lists 29 questions for the owner. The ones that block design are Q1 (check conflicts are
shown in the rebuild, tC4 hides them), Q2 (OBS sync), Q3 (private repositories), Q4 (salvage
versus refusal of a damaged file) and Q8 (what a refused sync may have changed).

These were checked against tC4 at d310bf3 and are used in the rest of this document.

- The #722 fix is two pull requests. #732 has one commit, 19ef58e: Align waits for the book
  text. #733 has c3f023f (the trainer reads the open book from the store), e58f00d (Align
  resumes at the remembered verse), 31f6937 (Check reads the draft again) and 0e0d7ca (a
  test of the trainer's wiring). #732 changes nothing in the UGNT upgrade; its branch name
  refers to line 489 of `e2e/j12-upgrade-resources.spec.ts`, where the symptom showed.
- Each catalog gained 87 keys, not 80: 30 `syncResult.*`, 25 `openDoor43.*`, 21 `refusal.*`,
  2 `home.*`, 2 `net.ask.*`, 2 `addProject.*`, 2 `check.*`, and `inspector.settingsUnreadable`,
  `signIn.nameNotice`, `shareDialog.teamAccess`. No key was removed, and no English value
  changed. Arabic changed 69 existing keys; with 4 keys added and corrected in the same
  window, that is the 73 strings of #739.
- The #725 lesson for the rebuild needs no `unsafe` code. `std::fs::rename` of a directory
  never replaces a non-empty directory: on Unix the target must be an empty directory, and on
  Windows the target must not be a directory. The rule is: on any failure, delete only what
  this operation created, never the destination.
- tC4's "no write access" journey asserts that the local `HEAD` did not move
  (`e2e/sync-button.spec.ts:247-270`). In the rebuild the merge commit (S7) comes before the
  push (S8), so `HEAD` moves unless the sync checks write access first. See Q8.
- tC4's `missingPinCount` counts language-set, original-language and source-pane pins. It
  does not count lexicon pins. The rebuild's `ProjectPins::all_pins` includes lexicons, so a
  port must leave them out.

### Sync and team work

**Q1. Check-result conflicts (tC4 G7 against STORAGE L8).** tC4's J26 says a check-result

conflicts kept the newest version" stays true. The conflict is also reviewable. The J26 port

**Q2. OBS sync.** tC4 4.0 syncs Bible projects only: an OBS card keeps "Upload changes", the

**Q8. What a refused sync may have changed.** The rebuild integrates received work (S6) and

**Q12. 403 reply.** tC4 has not measured Door43's real 403 reply (#710). *Answered by

refuse a push without write access with a 403. It answers HTTP 200, and its pre-receive hook

a token without `write:repository` or a repository that takes no push; STORAGE §9.5 says what
it maps to.
