# Ruling H11: "Stay signed in" keeps the token in the computer's password store

- Asked: 2026-10-25, by the roadmap session: fetch the `keyring` crate for "Stay signed in", or
  let the shell keep the token?
- Answer, in the owner's words: "agree" (to the recommendation: fetch `keyring`).
- The rule: a translator's Door43 token, when they choose "Stay signed in", is kept in the
  operating system's credential store (Windows Credential Manager, macOS Keychain, the Secret
  Service on Linux) through the `keyring` crate, behind tc-app's `Keychain` port. It is never
  written into a project or a plain file. Tests use a fake keychain and never touch the real
  store.

## Also ruled the same day: the conflicts button with only a kept outside copy

  Review"?
