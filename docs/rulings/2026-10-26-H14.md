# Ruling H14: a project has one name

- Asked: 2026-10-26, from E1b step 6: opening a Door43 project under a new name, change only
  the card, or the project's own name too? ([#837](https://github.com/unfoldingWord/translationcore4/issues/837))
- Answer, in the owner's words: "I agree with your naming recommendation."
- The rule: a project has one name, the one in the project (`identification.name`). It matches
  Door43 after a sync and changes only in Project details, which syncs to the team. Open from
  Door43 asks for no name. When two Home cards share a name, each shows a short second line
  saying where it lives, for example "On Door43: Juan/es_tit_text" or "Only on this computer".
  The folder on disk still gets a unique name, chosen without asking.
- Declared difference from tC4, which asks for a new name at the open: one name for the whole
  team, and nothing to drift.

## Also ruled the same day: no second copy of a Door43 project on one computer

- Asked: two copies of one Door43 repository on one computer would share a name and a second
  line. Should a second copy exist at all? (Recommendation: no; Open from Door43 offers to open
  the copy you already have.)
- Answer, in the owner's words: "1 agree".
- The rule: a computer holds one copy of a Door43 project. When the person already has that
  project, Open from Door43 says so, makes no copy, and offers a button that opens it.
- Declared difference from tC4, which opens a second copy under a new name: one copy per
  computer keeps the team's work in one place.
